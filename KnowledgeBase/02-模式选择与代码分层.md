# 模块 02：模式选择与代码分层

> Catalog ID: `ARCH-02`  
> 状态：`verified`  
> 最后核验：`2026-08-05`  
> 适用模式：GameHot / ET Client / Editor

## 模块定位

客户端支持 GameHot 与 ET 两种业务组织方式，并可独立启用 `UNITY_HOTFIX`。模式决定编译哪些 asmdef、启用哪套 Luban 配置与资源规则、维护哪些 HybridCLR 程序集，以及 `ProcedurePreset` 最终启动哪个入口。

## 依赖关系

### GameHot

`Game.Hot.Code` 引用 `Game.Hot.Loader`、`Game`、UGF 和业务包；Loader 不引用 Code。Code asmdef 约束为 `UNITY_GAMEHOT` 且满足 `!UNITY_HOTFIX || UNITY_COMPILE || UNITY_EDITOR`。

`Game.Hot.Loader/Define.cs` 只把编译期宏投影为运行布尔值：`IsEditor` 来自 `UNITY_EDITOR`，`EnableHotfix` 来自 `UNITY_HOTFIX`，`EnableIL2CPP` 来自 `ENABLE_IL2CPP`。它不选择 GameHot/ET 模式，模式选择仍由 Define Symbol 菜单和 `ProcedurePreset` 完成。

### ET

```text
ET.Core / ET.ThirdParty / Game.ET.Loader
  -> Game.ET.Code.Model
     -> Game.ET.Code.Hotfix
     -> Game.ET.Code.ModelView
        -> Game.ET.Code.HotfixView
```

准确引用以各 `.asmdef` 为准：Hotfix 引用 Model；ModelView 引用 Model 和 Loader；HotfixView 同时引用 Model、Hotfix、ModelView 和 Loader。当前 Model 还直接引用 `ReactiveBinding`。Model/Hotfix 设置 `noEngineReferences=true`，ModelView/HotfixView 可引用 Unity 表现层。

`Game.ET.Loader/Define.cs` 除了 `IsEditor`、`EnableHotfix`、`EnableIL2CPP`，还暴露 `UseUnityEditorModelDll`、`EnableEditorView` 与 `CodeMode`。`EnableEditorView` 只在 `UNITY_ET_VIEW && UNITY_EDITOR` 时为 true；`CodeMode` 由 `UNITY_ET_CODEMODE_CLIENT`、`UNITY_ET_CODEMODE_SERVER` 或 `UNITY_ET_CODEMODE_CLIENTSERVER` 三个宏映射，三者都不存在时会抛出要求通过 `ET/Define Symbol/CodeMode` 菜单设置的异常。

## 入口与调用链

```text
Game/Define Symbol 菜单
  -> 增删 UNITY_ET / UNITY_GAMEHOT / UNITY_HOTFIX
  -> 清理临时业务 DLL 目录
  -> 激活 ET 或 GameHot Luban 配置
  -> 激活对应 ResourceRule
  -> 更新 link.xml 条件区块
  -> 更新 HybridCLR hotUpdateAssemblies
  -> RefreshSettings + SaveAssets

ProcedurePreset
  -> UNITY_ET: ProcedureET -> CodeRunner.StartRun("ET.Init")
  -> UNITY_GAMEHOT: ProcedureGameHot -> CodeRunner.StartRun("Game.Hot.Init")
  -> neither: ProcedureGame
```

ET 与 GameHot 的 Add 菜单会调用另一模式的 Remove 方法，因此工具层保证互斥。`Refresh` 只根据当前已编译宏同步关联配置。

## 核心类型与 API

| 类型/API | 职责 | 生命周期/约束 |
| --- | --- | --- |
| `DefineSymbolTool.Refresh()` | 根据当前宏修复所有关联配置 | Unity Editor 菜单调用 |
| `Add_UNITY_ET` / `Add_UNITY_GAMEHOT` | 启用一种模式并关闭另一种 | 会触发重新编译 |
| `Add_UNITY_HOTFIX` | 启用 HybridCLR 业务 DLL 模式 | 清理旧构建目录 |
| `Set_Luban_GenConfig` | 修改 `Design/Excel/*/luban.conf` 的 active | 依赖 Unity 工程相对工作目录 |
| `ResourceRuleTool.ActivateRule_*` | 选择对应资源收集规则 | 与业务 DLL/资源路径联动 |
| `HybridCLRTool.RefreshSettings()` | 刷新热更/AOT 程序集配置 | 切换模式后执行 |

## 数据与生命周期

- 模式状态由 Scripting Define Symbols 持有；Luban active、ResourceRule、`link.xml` 和 HybridCLR Settings 是派生状态。
- 切换菜单先清理旧业务 DLL 目录，随后修改派生配置并保存 AssetDatabase。
- 非热更模式下，Loader 从当前 AppDomain 找业务程序集。
- 热更且启用 CodeBytes 模式时，GameHot 加载 `Game.Hot.Code.dll.bytes`；ET 加载四业务程序集的 DLL/PDB bytes，再注册 `CodeTypes`。
- Editor 可关闭 CodeBytes 模式继续使用 Unity 已编译程序集；Player 中 `EnableCodeBytesMode` 固定为 true。

新增热更程序集时，还必须同步 asmdef 约束、构建复制清单、HybridCLR Settings、资源规则、运行时加载顺序和 `link.xml`。

## 约束与常见错误

- 不要只在 Player Settings 手工改宏，否则 Luban、资源规则、裁剪和 HybridCLR 配置会分叉。
- `UNITY_ET` 与 `UNITY_GAMEHOT` 必须互斥；`UNITY_HOTFIX` 可以叠加任一业务模式。
- `UNITY_COMPILE` 是业务 DLL 单独编译时用于满足 asmdef 条件的辅助符号，不是日常模式开关。
- ET Model/Hotfix 禁止 UnityEngine 依赖；视图代码必须进入 ModelView/HotfixView。
- Loader 被业务 Code 引用，不能反向引用业务 Code，否则破坏稳定加载边界。
- 热更 DLL 名称、资源路径和加载器字符串必须完全一致。
- ET 运行入口依赖 `Define.CodeMode`，只设置 `UNITY_ET` 而没有设置 `UNITY_ET_CODEMODE_*` 会在读取 CodeMode 时失败；Editor View 也必须同时满足 `UNITY_ET_VIEW` 与 `UNITY_EDITOR`。

## 验证方法

1. 分别执行 Add UNITY_GAMEHOT 与 Add UNITY_ET，确认另一模式符号被移除。
2. 每次切换后执行 Refresh，检查对应 `luban.conf` active、ResourceRule、`link.xml` 和 HybridCLR Settings。
3. 在非 Hotfix 模式启动两种业务入口。
4. 启用 Hotfix 后分别在 Editor CodeBytes 开/关状态启动，并检查 DLL 资源加载。
5. 构建目标 Player，确认未选模式的业务程序集和资源未被错误打入。

本次已核验菜单实现、Procedure 分派、CodeRunner、六个关键 asmdef，以及 GameHot/ET 两个 Loader `Define.cs` 的条件分支。Unity 菜单和 Player 运行验证应在模式/构建变更时重复执行。
