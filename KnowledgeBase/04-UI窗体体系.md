# 模块 04：UI 窗体与 ETUI

> Catalog ID: `UNITY-04`、`ET-05`  
> 状态：`verified`  
> 最后核验：`2026-08-05`  
> 适用模式：GameHot Client / ET Client

## 模块定位

UI 资源、分组、加载和实例池由 UGF `UIComponent` 管理。项目基础层提供 `AUIForm`、Widget、异步打开和深度同步；GameHot 直接在 MonoBehaviour UIForm 中编写业务；ETUI 则把 UGF Mono 视图绑定到 ET `UGFUIForm`/`UGFUIWidget` Entity，并把 UGF 生命周期转发给 ET System。

## 依赖关系

```text
Luban UI.xlsx
  -> DRUIForm / DTUIForm + UIFormId
  -> Game.UIExtension
  -> UGF UIComponent
  -> prefab 上的 UIFormLogic
     -> GameHot: StarForceUIForm
     -> ET: AETMonoUGFUIForm <-> UGFUIForm Entity <-> HotfixView System
```

GameHot UI 依赖 `Game.Hot.Code` 和 `AHotUIForm`。ETUI 的 Entity/Mono 定义位于 ModelView，System 位于 HotfixView；稳定的生命周期转发器位于 `Game.ET.Loader`。

## 入口与调用链

### GameHot

```text
GameEntry.UI.OpenUIForm(UIFormId.X, userData)
  -> UIExtension 从 DTUIForm 取 AssetName/UIGroup/AllowMulti/PauseCovered
  -> UGF UIComponent 加载并实例化 prefab
  -> UIFormLogic.OnInit（实例首次初始化）
  -> OnOpen（每次打开）
  -> 业务 StarForceUIForm
```

`StarForceUIForm` 在 OnInit 设置主字体并按 Text 内容查本地化字符串，在 OnOpen/OnResume 执行 CanvasGroup 淡入。主字体由 GameHot Preload 提前设置。

### ETUI

```text
scene.UIComponent.AddUIFormComponentAsync<T>(UGFUIFormId.X)
  -> 创建 UGFUIForm Entity
  -> UGFUIForm.OpenUIFormAsync
  -> GameEntry.UI.OpenUIFormAsync(..., ETMonoUGFUIFormData)
  -> AETMonoUGFUIForm.OnOpen 消费 pooled data
  -> 双向绑定 Entity.UGFMono / Mono.UGFUIForm / CachedTransform
  -> 扫描本 Form 下全部后代 AETMonoUGFUIWidget，并把通过过滤的项建成 ET 子 Widget Entity
  -> UGFSystemSingleton 调用 [UGFUIFormSystem] 对应生命周期 System
```

真实调用见 `AppStartInitFinish_CreateLoginUI`，它在 Demo Scene 事件中打开 `UIFormLoginComponent`。

`AETMonoUGFUIForm.OnOpen` 使用 `GetComponentsInChildren(true)` 取得本 Form 下全部后代 Widget，过滤条件是“该 Widget 尚未 Initialized，且 `GetComponentInParent<AETMonoUGFUIForm>(true)` 仍是当前 Form”。它不会按 Transform 直属子节点过滤，也不会排除位于某个父 `AETMonoUGFUIWidget` 下面的子 Widget；如果父 Widget 还未初始化，Form 这次扁平扫描可能先把整棵 Widget 子树登记到 Form 容器。随后 `AETMonoUGFUIWidget.OnOpen` 也会全后代扫描，但会跳过 `this`、已 Initialized、以及最近父 Widget 不是自己的项。因此 ETUI prefab 设计不能把“嵌套在父 Widget 下面”直接等同于运行时所有权已经归父 Widget，必须用实际初始化顺序验证归属。

## 核心类型与 API

| 类型/API | 职责 | 生命周期/约束 |
| --- | --- | --- |
| `AUIForm` | UGF UIFormLogic 基类 | OnInit 补 Canvas、GraphicRaycaster 并铺满 RectTransform |
| `AUIForm.OnDepthChanged` | 同步子 Canvas 与 ParticleSystemRenderer 层级 | 使用 UIGroup 与 Form 深度计算增量 |
| `AExUIForm` | 带 Widget/Event/Entity/Resource 容器的窗体 | OnClose 自动清理受管资源 |
| `AUIWidget` / `AExUIWidget` | prefab 内复用 UI 单元 | Initialized、Available、Visible 分离 |
| `UIExtension.OpenUIForm` | 按配置同步打开 | 非多实例时拒绝重复加载/已打开实例 |
| `UIExtension.OpenUIFormAsync` | 可取消异步打开 | 返回 null 代表配置缺失或重复实例 |
| `UGFUIForm<TMono>` | ET UI Entity，强类型 View | Dispose 取消打开请求并关闭 UGF Form |
| `AETMonoUGFUIForm` | UGF Mono 到 ET Entity 的桥 | OnOpen 必须收到 `ETMonoUGFUIFormData` |
| `UGFUIWidget` | ET Widget Entity | 可作为 Child 或 Component 挂载 |
| `UGFSystemSingleton` | 转发 UIForm/UIWidget 生命周期 | Awake 收集带属性的 System；运行时仅对 Entity 已声明的接口分派 |

## 数据与生命周期

UGF Form 生命周期包括 OnInit、OnOpen、OnPause/Resume、OnCover/Reveal、OnRefocus、OnUpdate、OnDepthChanged、OnClose、OnRecycle。OnInit 对池中实例通常只执行一次；OnOpen/OnClose 每次可用周期执行。

`AUIForm` 调整根 Canvas 和所有子 Canvas/粒子 renderer 的 sortingOrder。`AExUIForm` 只自动收集“最近父 Form 是当前 Form”的 `AExUIWidget`，避免把嵌套 Form 的 Widget 错归属。

ETUI 在 Mono OnOpen 时完成 Entity/View 绑定。关闭时先关闭 Widget 并分派 ET OnClose，然后解除容器；ET Entity Dispose 会关闭仍可用的 UGF Form。异步打开使用池化 `CancellationTokenSourcePlus`，Entity 销毁会取消请求。

Demo 登录窗体中的 `UIFormLoginComponentSystem.LoadTest1/LoadTest2` 是演示用动态 Widget 代码：`await LoadChildUIWidgetAsync<UIWidgetTest>` 返回后直接写 `self.View.Test*RectTransform` 并调用 `uiWidget.Open()`。同一 Demo 的 `LoginFinish_RemoveLoginUI` 会在登录完成事件中 `RemoveComponent<UIFormLoginComponent>()`，因此等待期间 Form 可被移除或释放；这段代码应记录为关闭/释放竞态样例，不作为生产安全模板。生产路径要在 await 后重新确认 `self`、`self.View`、Owner 可用性和当前打开周期，再移动 Transform 或打开 Widget。

## 通用组件接入

GameHot 与 ETUI Form 可以复用 `Unity/Assets/Res/UI/UIPrefab/ComponentLibrary` 下的 Button、Toggle、ProgressBar、ItemSlot、Badge 和 Loading。它们是 `AExUIWidget`，由最近的 Form/父 Widget 初始化和关闭，但宿主仍必须在每次 `OnOpen` 显式调用 `OpenUIWidget` 并重新写入本次数据与回调。

组件基础结构由 `Game/UI/ComponentLibrary` 与 `Game/Editor/UIComponentLibrary/UIComponentLibraryBuilder.cs` 共同维护，通过 Unity 菜单 `Game/UI/Rebuild Common Component Library` 重建；业务 Form 对组件的引用继续使用 CodeBind。组件目录、API、所有权和 AI 接入门禁见 `UNITY-05`。

## AI UI 开发工作流

本流程用于新增或修改 UIForm。只调整组件绑定、Widget 或资源所有权时，继续执行 `UNITY-05` 的“AI 组件绑定与所有权工作流”。

### 0. 建立任务契约

AI 在修改前先输出并核对一份变更清单：

| 项目 | 必须明确的内容 |
| --- | --- |
| 目标模式 | GameHot Client 或 ET Client；从当前宏、启动链和实际配置判断，不能因两个目录都存在而同时修改 |
| 任务类型 | 新建 Form、修改 Form、静态 Widget、动态 Widget，或仅调整表现/配置 |
| 调用闭环 | 谁打开、传入什么数据、谁关闭；ETUI 还要明确 Entity 挂为 Child 还是 Component |
| 配置语义 | Id、CSName、AssetName、UIGroup、AllowMultiInstance、PauseCoveredUIForm |
| 生命周期 | 哪些工作只做一次，哪些每次打开重置，异步任务在何时取消 |
| 资源边界 | prefab、图片/字体、配置、本地化、生成代码及业务代码分别由谁维护 |

优先通过源码和配置补齐清单；仍无法判定目标模式、调用方或关闭责任时，先向需求方确认，不开始修改 prefab 和表格。

### 1. 建立证据链

1. 从 `catalog.json` 定位 `UNITY-04`；涉及绑定/资源时追加 `UNITY-05`，涉及导表时追加 `DATA-01`，ETUI 再读 `ET-02`、`ET-03`。
2. 核对当前模式、实际参与导出的 `UI.xlsx`、对应生成 ID 和目标 prefab。不要编辑非当前模式的 Excel，也不要把 GameHot `UIFormId` 与 ET `UGFUIFormId` 混用。
3. 找一个同模式、同类型且仍有真实调用方的最小样例：GameHot 可沿 `ProcedureMenu -> MenuForm` 阅读；ETUI 可沿 `AppStartInitFinish_CreateLoginUI -> UIFormLoginComponent -> HotfixView System` 阅读。
4. 搜索目标 CSName、配置 Id、AssetName、打开 API 和关闭 API，确认不存在重复配置、废弃同名类或第二条生命周期链。
5. 列出将手工修改的输入与预期生成物。`.Bind.cs`、`UIFormId.cs`、`UGFUIFormId.cs` 和 `dtuiform.json` 只能由工具生成。

涉及 Unity 场景、prefab 或 Inspector 查询/修改时，AI 必须先遵守仓库 `AGENTS.md` 的 Unity Agent Bridge 规则：阅读已安装包的 `AGENT.md`，会话首次调用运行时 `list_commands`，只使用返回的 command/schema，并遵守 single-flight 与响应 ack；不得直接手改 prefab YAML，也不得自行创建 Bridge 目录。

### 2. 按依赖顺序实现

共同步骤：

1. 在当前模式的 UIForm 资源目录创建或调整 prefab，确定根 UIFormLogic、Canvas、Widget 层级及 CodeBind 标记。
2. 在当前模式的 `UI.xlsx` 增改记录，保证 Id 和 CSName 唯一，AssetName 与资源规则一致，并显式确认分组和覆盖策略。
3. 从正确工作目录运行 Luban，检查 `DTUIForm`、运行时 JSON 和当前模式 ID 类的差异；生成结果异常时回到 Excel 或生成配置修复。
4. 运行 CodeBind，审查 `.Bind.cs` 差异；事件、默认值和业务行为只写在非生成 partial 文件。

GameHot 分支：

1. UI 逻辑继承 `StarForceUIForm` 或项目中更具体的共享基类。
2. `OnInit` 只缓存一次性引用；`OnOpen` 校验 userData 并重置每次打开的状态；`OnClose` 结束本次可用周期。
3. 从明确的 Procedure 或业务调用方使用生成的 `UIFormId` 打开，并覆盖成功、重复打开返回 null 和关闭路径。

ETUI 分支：

1. prefab Mono 继承 `AETMonoUGFUIForm`；ModelView Entity 继承 `UGFUIForm<TMono>`，只声明确实需要的 `IAwake`、`IUGFUIFormOn*` 接口。
2. 在 HotfixView 为每个已声明接口提供带 `[UGFUIFormSystem]` 的实现，保持数据模型、视图引用与行为分层。
3. 唯一实例通常由 `AddUIFormComponentAsync` 挂载；允许同类型多实例时使用 `AddUIFormChildAsync`，并保证 Excel 的 AllowMultiInstance 与调用方式一致。
4. 关闭时移除或 Dispose 对应 ET Entity，由桥接层关闭 UGF Form；不要绕过桥接层直接打开或关闭 ET prefab。

### 3. 生命周期与所有权审查

- 每个 Event、Entity、Asset、Widget 和异步请求只能有一个明确的 Form/Widget Owner。
- 不在 `OnInit` 保存每次打开的 userData 或易变业务状态；不在生成文件中写业务逻辑。
- Form 关闭后，迟到的异步结果不能写回已关闭或已复用的实例。
- ETUI 的 Entity、Mono、静态/动态 Widget 必须沿同一父子关系创建和销毁。
- 新增本地化文本、图集或字体时，把对应数据导出和预加载纳入同一任务，不用临时硬编码替代。

### 4. 验证门禁

1. **生成检查**：重新运行 Luban 和 CodeBind 后工作区稳定，生成 ID、配置路径、绑定类型与 prefab 一致。
2. **编译检查**：编译当前 Unity 模式；ETUI 同时检查 ModelView/HotfixView 程序集边界和生命周期签名。
3. **运行检查**：至少连续打开/关闭两次，并覆盖重复打开、多实例、UIGroup、PauseCovered、Refocus 和 userData 异常路径。
4. **竞态检查**：在 Form 或动态 Widget 加载期间关闭 Owner，确认请求取消、无迟到回写、无孤立 Entity/资源。
5. **表现检查**：检查目标分辨率下的布局、遮挡、Raycast、嵌套 Canvas、粒子排序和本地化长文本。
6. **知识库检查**：运行 `powershell -ExecutionPolicy Bypass -File KnowledgeBase/Test-KnowledgeBase.ps1 -RequireStaticComplete`。未实际执行的 Unity 验收必须标记为未运行，不能写成通过。

### 5. AI 交付格式

完成后报告：目标模式及判定依据、调用与关闭链、手工输入与生成物清单、执行过的生成/编译/运行验证、未执行项和剩余风险。若行为或目录边界发生变化，同步更新本页、`UNITY-05` 或相应 Catalog 条目，再提交变更。

## 开发扩展步骤

### 新建 GameHot UIForm

1. 在 `Unity/Assets/Res/UI/UIForm/Hot` 创建 prefab，根逻辑继承 `StarForceUIForm` 或合适的共享基类。
2. 优先从 `Res/UI/UIPrefab/ComponentLibrary` 组合通用 Widget，并通过 CodeBind 生成宿主引用。
3. 在 GameHot `UI.xlsx` 增加唯一 Id、CSName、AssetName、UIGroupName、AllowMultiInstance、PauseCoveredUIForm。
4. 运行 Luban 导出，使用生成的 `UIFormId`；不要手工增加常量。
5. 在 `Game/Hot/Code/UI` 编写 partial UI 类并使用 CodeBind 生成绑定字段。
6. 使用 `GameEntry.UI.OpenUIForm(UIFormId.X, userData)` 或 Async 版本打开。

### 新建 ETUI Form

1. 创建 prefab，Mono 类继承 `AETMonoUGFUIForm`。
2. 优先从 `Res/UI/UIPrefab/ComponentLibrary` 组合通用 Widget，并让 ET Mono/View 按现有绑定边界引用。
3. 在 ET `UI.xlsx` 配置并导出 `UGFUIFormId`。
4. 在 ModelView 创建 `UGFUIForm<TMono>` Entity，声明 `IAwake` 和需要的 `IUGFUIFormOn*` 接口。
5. 在 HotfixView 创建 `[EntitySystemOf]` partial System；生命周期方法标记 `[UGFUIFormSystem]`。
6. 从 Scene 的 `UIComponent` 调用 `AddUIFormChildAsync` 或 `AddUIFormComponentAsync`。需要同类型多实例时使用 Child；唯一 Form 可使用 Component。

### 新建 Widget

GameHot 使用 `AExUIWidget` 并由 Form/父 Widget 容器管理。ET 使用 `AETMonoUGFUIWidget + UGFUIWidget<TMono>`；静态 Widget 在 Form/父 Widget OnOpen 的全后代扫描中自动建 Entity，动态 Widget 可通过 UIEntity 加载 API 创建。嵌套 ET Widget 的所有权以实际 `Initialized` 和最近父 Widget/Form 过滤结果为准，不能只看 prefab 层级。

## 约束与常见错误

- UI 表中的 AssetName 必须与资源规则生成的 `AssetUtility.GetUIFormAsset` 路径一致。
- `AllowMultiInstance=false` 时，正在加载或已经打开都会返回 null；调用方不能假设必有实例。
- `StarForceUIForm.OnInit` 依赖主字体已由 Preload 设置；绕过正常启动链会得到 invalid font 日志。
- `AETMonoUGFUIForm.OnOpen` 强制把 userData 转成 `ETMonoUGFUIFormData`，不能直接用普通 UGF Open API 打开 ET prefab。
- `AETMonoUGFUIForm` 对 Widget 是全后代扁平扫描并只排除嵌套 Form，不排除尚未初始化的父 Widget 子树；复杂嵌套 Widget 必须在 Unity 中验证 Owner、初始化顺序和关闭顺序。
- ET Entity 声明了生命周期接口但没有对应 `[UGFUIFormSystem]` 时，转发器找不到行为；反之未声明接口则不会分派。
- 关闭 ETUI 应 Dispose/移除对应 Entity，让 Entity 与 UGF Form 生命周期保持一致。
- 不要把 Demo Login 的 `LoadTest1/LoadTest2` 当安全模板；它们等待动态 Widget 后直接访问 `self.View`，而登录完成事件可能已经移除 Form。
- `OnDepthChanged` 会修改所有子 Canvas/Particle 的当前 sortingOrder，prefab 内应使用相对层级且避免其他脚本重复累加。
- UI prefab 和生成 ID 都是模式相关资源；切换 ET/GameHot 后必须重新导表并刷新资源规则。

## 验证方法

1. 导表后确认 DTUIForm 和对应模式 UIFormId 生成成功，Unity 无编译错误。
2. 打开/关闭同一 Form 两次，确认 OnInit 一次、OnOpen/OnClose 两次，并验证实例池复用。
3. 验证 `AllowMultiInstance`、UIGroup、PauseCovered 和 Refocus 行为。
4. 打开带粒子和嵌套 Canvas 的 Form，检查不同 UIGroup/深度下排序正确。
5. ET 模式验证 Entity Dispose 能取消加载或关闭 Form，所有声明的生命周期 System 被调用。
6. ET 模式打开包含“父 Widget -> 子 Widget”的 prefab，核对 `Initialized`、Owner、父/子 OnOpen 和关闭顺序，确认没有被 Form 扁平扫描提前错误接管。
7. 动态 Widget 验证加载、父子归属、Depth 更新、关闭和回收；额外覆盖 Form 关闭发生在 await 期间的迟到回写。
