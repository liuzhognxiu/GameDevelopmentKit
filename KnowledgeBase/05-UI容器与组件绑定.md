# 模块 05：UI 容器与组件绑定

> Catalog ID: `UNITY-05`  
> 状态：`verified`  
> 最后核验：`2026-08-04`  
> 适用模式：GameHot Client / ET Client / Shared UI

## 模块定位

项目用四个 `IReference` 容器把 UI 生命周期内的 Widget、事件、Entity 和资源归属到 Form 或 Widget。CodeBind 负责 prefab 到 partial 类字段的生成；StateController 与 ReactiveBinding 负责状态切换和数据响应。目标是让 UI 关闭时能统一释放，而不是由每个窗体散落管理。

## 依赖关系

`AExUIForm` 与 `AExUIWidget` 按需从 GF `ReferencePool` 获取容器。容器调用 `GameEntry.Event`、`GameEntry.Entity`、`GameEntry.Resource` 和共享 `UIWidgetContainer`。CodeBind 是 UPM 编辑器生成器，项目 Customizer 额外依赖 StateController。ET Reactive 使用 ReactiveBinding 接口和 ET `CodeTypes`。

## 入口与调用链

```text
AExUIForm.OnInit
  -> 收集直属 AExUIWidget
  -> UIWidgetContainer.AddUIWidget
     -> SetInitialized(true) + SetUIFormOwner + OnInit

业务调用 Subscribe / ShowEntity / LoadAsset
  -> 首次调用时从 ReferencePool 创建对应容器
  -> 容器记录本 Form/Widget 拥有的句柄或对象

AExUIForm.OnClose
  -> 关闭可用 Widget
  -> HideAllEntity
  -> UnsubscribeAll
  -> UnloadAllAssets
  -> shutdown 时移除 Widget 并释放容器
```

普通关闭保留容器对象供池中 Form 下次打开复用，但清空受管内容；shutdown 或 Mono OnDestroy 会释放容器到 ReferencePool。

## 核心类型与 API

| 类型/API | 管理内容 | 关键行为 |
| --- | --- | --- |
| `UIWidgetContainer` | AUIWidget 列表 | 防重复、校验 Open/Close 状态、转发生命周期与 Depth |
| `EventContainer` | EventId 到 Handler 多字典 | 订阅时登记；关闭时统一退订 |
| `EntityContainer` | UGF Entity serialId 集合 | 关闭时隐藏实体并取消异步 Show |
| `ResourceContainer` | 已加载 Unity Object 与取消源 | 关闭时卸载资源并取消异步 Load |
| `AExUIForm` | 四容器的 Form API | 只收集直属 Widget，避免跨 Form 归属 |
| `AExUIWidget` | 四容器与嵌套 Widget API | 父 Widget 优先于 Form 作为打开/关闭入口 |
| `ADynamicUIWidgetLoader` | 动态 prefab | Start 自动加载，实例铺满 Loader RectTransform |
| `GameCodeBindCustomizer` | 生成字段/属性/状态常量 | 序列化字段前缀 `m_`，公开属性保留成员名 |

## 数据与生命周期

`AUIWidget` 有三个独立状态：Initialized 表示已加入容器并执行 OnInit；Available 表示已 OnOpen 且未 OnClose；Visible 只有 Initialized 后可设置。关闭会先隐藏，再把 Available 置 false。

`ResourceContainer` 使用 `m_Version` 防止 callback 异步加载在容器复用后把旧资源交给新 Owner；UniTask 路径使用 CancellationTokenSource。`EntityContainer` 同样用 CancellationTokenSource 管理异步 Show，并用 serialId 集合限制 Hide 只能作用于归属实体。

`EventContainer` 记录全部订阅；shutdown 时不再调用可能已经关闭的 GameEntry Event，只清本地记录。所有容器的 `Clear()` 只重置内部状态，正确释放顺序由 AExUIForm/AExUIWidget 保证。

ET Reactive 在初始化时扫描 `[ETReactiveObserver]`，为 OwnerType 建池并递增 DllVersion；回收时只把当前 DLL 版本、类型仍匹配的 Observer 放回池，避免热重载后复用旧类型实例。

## 通用 UI 组件库

组件库位于 `Unity/Assets/Res/UI/UIPrefab/ComponentLibrary`，GameHot 与 ETUI 都可以在各自 Form prefab 中复用。组件行为位于 `Game/UI/ComponentLibrary`，统一继承 `AExUIWidget`，因此仍遵守 Initialized、Available、Visible 和最近 Owner 规则。

| prefab / 组件 | 主要能力 | 每次打开应设置 |
| --- | --- | --- |
| `CommonBadgeWidget` | 数量角标、零值隐藏、超过 99 显示 `99+` | `SetCount` |
| `CommonButtonWidget` | 文本、图标、禁用态、角标、点击回调 | `SetLabel`、`SetIcon`、`SetBadgeCount`、`SetClickHandler` |
| `CommonToggleWidget` | 文本、值、禁用态、值变化回调 | `SetLabel`、`SetValue`、`SetValueChangedHandler` |
| `CommonProgressBarWidget` | 归一化进度、当前值/最大值、数值文本开关 | `SetNormalizedValue` 或 `SetValue` |
| `CommonItemSlotWidget` | 图标、数量、品质框、选中、锁定、角标、点击 | 按业务状态调用对应 Set API |
| `CommonLoadingWidget` | 旋转加载指示和可选文本 | `SetLabel` |

`AExUIForm.OnInit` 只收集和初始化静态 Widget，不会自动把它们置为 Available。宿主必须在自己的 `OnOpen` 中显式调用 `OpenUIWidget(widget)`；父 `AExUIWidget` 内的嵌套 Badge 由父组件打开。正常关闭交给 Owner 容器，组件会清空本次交互回调。

```csharp
protected override void OnOpen(object userData)
{
    base.OnOpen(userData);
    OpenUIWidget(m_ConfirmButton);
    m_ConfirmButton.SetLabel("Confirm");
    m_ConfirmButton.SetBadgeCount(0);
    m_ConfirmButton.SetClickHandler(Confirm);
}
```

共享 prefab 是确定性构建产物：修改基础结构、默认尺寸、颜色或公共 Sprite 时，编辑 `UIComponentLibraryBuilder.cs`，再通过 Unity 菜单 `Game/UI/Rebuild Common Component Library` 重建。不要直接编辑这些 prefab YAML。构建器会保留既有 GUID，并为六个 prefab 添加 `All`、`Pack` 标签；连续重建应保持资源数量和 GUID 不变。

组件库内部引用采用 `[SerializeField]`，由构建器用 `SerializedObject` 赋值。业务 Form/Widget 对组件实例的引用仍按项目规范使用 CodeBind；不要为共享组件内部再生成一套 `.Bind.cs`，也不要把构建器维护的字段复制到业务 partial 中。

### AI 组件库接入流程

1. 从现有六类组件中选择最小满足项；纯视觉差异优先做 prefab variant 或宿主状态配置，新增行为才扩展组件类。
2. 在目标 Form prefab 中放入组件，通过 CodeBind 生成宿主引用；确认最近 Owner 是目标 Form 或父 Widget。
3. 在 `OnOpen` 显式 `OpenUIWidget`，随后完整写入本次状态与回调；不要依赖上一次打开残留的数据。
4. 修改共享基础组件时只改运行时代码和构建器，通过 Agent Bridge 调用 Unity 菜单重建，禁止手写 prefab YAML。
5. 连续重建两次，核对六个 prefab 数量、GUID、`Game.Common*Widget` 脚本和 `All`/`Pack` 标签；随后执行 Unity 编译与目标 Form 两次打开/关闭回归。

## AI 组件绑定与所有权工作流

本流程在 `UNITY-04` 已明确目标 UIForm、模式和调用闭环后执行，目标是让 prefab 引用、Widget、事件、Entity、资源及异步请求都能随最近 Owner 正确释放。

### 1. 先做归属决策

| 需求 | 优先使用 | Owner/边界 |
| --- | --- | --- |
| prefab 中固定存在的复用区域 | 静态 `AExUIWidget` | 最近父 Widget，否则最近父 Form |
| 运行时加载的复用区域 | `ADynamicUIWidgetLoader` 或 Owner 的动态 Widget API | 发起加载的 Form/Widget，必须同时定义卸载路径 |
| UGF 全局事件 | Owner 的 `Subscribe`/`Unsubscribe` | `EventContainer` |
| 临时 UGF Entity | Owner 的 `ShowEntityAsync`/`HideEntity` | `EntityContainer` |
| 临时 Unity Asset | Owner 的 `LoadAssetAsync`/`UnloadAsset` | `ResourceContainer` |
| prefab 内有限视觉状态 | StateController | 由 CodeBind 生成状态属性和常量 |
| ET 数据变化驱动视图 | ReactiveBinding | ET Host 与当前 DllVersion 的 Observer |

AI 必须先画出 `Form -> Widget -> Event/Entity/Asset/Async` 的所有权树。找不到唯一 Owner、动态加载器没有卸载责任、或一个对象被两个容器同时管理时，先修正设计再写代码。

### 2. 绑定与代码生成

1. 检查 prefab 根类型、最近父 Form/Widget、现有 CodeBind 标记和同名 `.Bind.cs`，避免建立第二个 BindingRoot。
2. 涉及 Unity 对象时，先按仓库 `AGENTS.md` 完成 Agent Bridge 会话初始化，并从运行时 `list_commands` 获取可用命令；不硬编码命令，不直接编辑 prefab YAML。
3. 在 prefab 中添加或调整标记后运行 CodeBind，逐项审查生成字段类型、命名、StateGroup 和状态常量。
4. `.Bind.cs` 只作为可重复生成的输出；事件注册、初始状态、空值保护和业务逻辑写入非生成 partial 文件。
5. 再次生成并确认没有手工逻辑丢失或无关大面积 diff，才继续业务实现。

### 3. 实现生命周期

1. `OnInit` 仅做实例生命周期内一次的引用准备；`OnOpen` 注册本次交互、填充数据并打开静态 Widget；`OnClose` 结束本次状态。
2. Event、Entity、Asset 和 Widget 操作优先经过 `AExUIForm`/`AExUIWidget` 代理 API，不另建平行的全局订阅或裸 `GameEntry` 句柄。
3. 只有业务需要提前释放单项资源时才显式调用 Unsubscribe/Hide/Unload；正常关闭交给容器统一清理。
4. 每个异步完成点都重新检查 Owner 是否仍可用、请求是否属于当前打开周期。关闭后重新打开的实例不能接收上一次请求的结果。
5. ET Reactive Observer 不跨热重载 DLL 版本持久化；View 销毁或 Entity Dispose 后不得继续回写绑定组件。

### 4. AI 审查门禁

- **生成稳定性**：CodeBind 连续生成结果稳定，`.Bind.cs` 无手工代码，业务 partial 编译无冲突。
- **归属正确性**：嵌套 Form/Widget 只被最近父容器收集；静态与动态 Widget 没有重复 Add/Open。
- **释放完整性**：连续打开/关闭后 Event、Entity、Asset、Widget 数量不增长，shutdown 路径也不访问已关闭模块。
- **竞态安全性**：资源/Entity/Widget 加载中关闭并重新打开，迟到结果不会进入新 Owner。
- **状态正确性**：Initialized、Available、Visible 的调用顺序合法；StateController 状态名可生成且无重名。
- **已知缺口**：依赖 Entity 显示失败回调时，必须先验证或修复 `OnShowEntityFail` 不调用 `OnFailureCallback` 的当前行为，不能把预期回调当成已实现。
- **运行验证**：在 Unity 中检查按钮事件、布局、动态层级、热重载后的 Reactive 更新；未执行时在交付报告中明确标记。
- **组件库稳定性**：共享 prefab 由构建器重建，连续生成后 GUID 稳定且没有 Missing Script；宿主每次 OnOpen 显式打开并刷新组件状态。

AI 交付时附上所有权树、生成文件列表、容器 API 使用点、异步取消策略和验证结果。任何只能靠“Form 通常不会在加载中关闭”成立的实现，都不能视为完成。

## 开发扩展步骤

### 在 Form/Widget 中管理资源

1. 业务基类继承 `AExUIForm` 或 `AExUIWidget`。
2. 使用基类 `Subscribe`、`ShowEntityAsync`、`LoadAssetAsync`、Widget API，不单独保存全局订阅。
3. 只对提前结束的单项调用显式 Unsubscribe/Hide/Unload；普通关闭由容器兜底。
4. 异步完成后仍要检查业务对象状态，尤其是关闭与重新打开之间的竞态。

### CodeBind

1. UI partial 类标记 `[MonoBehaviourBinding]`，Widget 根由 `AUIWidget` 的 `[BindingRoot]` 提供。
2. 在 prefab 中按 CodeBind 规则标记目标并执行生成。
3. 业务代码只引用生成的公开属性；`.Bind.cs` 是生成物，禁止手改。
4. StateController 目标会额外生成 `StateGroup` 属性、StateName 和 StateIndex 常量。

### ReactiveBinding

ET Host 实现 `IETReactiveHost`，Observer 使用对应特性与生成流程。热重载后由新的 `ETReactiveSystem.DllVersion` 隔离旧 Observer；不要把 Observer 跨 DLL 版本持久保存。

## 约束与常见错误

- Widget 必须先 Add/Init 才能 Open；可用 Widget 不能 Remove，未打开 Widget 不能 Close。
- `DynamicOpenUIWidget` 会额外刷新 Depth；Form OnOpen 中的静态 Widget 通常用 `OpenUIWidget`。
- `ADynamicUIWidgetLoader` 当前只在销毁前加载完成检查 `this == null`，加载成功资源由后续 Widget/Entity 生命周期负责；新增 Loader 时必须明确卸载所有权。
- `ResourceContainer` callback 路径会校验资源类型，类型不匹配立即卸载并抛异常。
- `EntityContainer` 当前 `OnShowEntityFail` 只释放内部事件参数，**没有调用已保存的 `OnFailureCallback`**；依赖失败回调前需先修正实现或使用可观察的 Async API。
- `EventContainer.Unsubscribe` 和 Entity Hide 的非 Try API 会在“不属于本容器”时抛异常；不确定状态使用 Try 版本。
- CodeBind 生成文件会被重新覆盖；业务逻辑、默认值和事件注册写在非生成 partial 文件。
- StateController 状态名会直接生成 C# 标识符，表述应满足合法标识符规则且避免重名。
- 不要把通用组件 prefab 的默认激活状态等同于 Available；未经过 Owner 的 `OpenUIWidget`，Loading 不更新，按钮/Toggle 的本次回调也不应视为已建立。
- 共享组件结构由 `UIComponentLibraryBuilder` 维护；直接在 Inspector 修改生成 prefab 会在下次重建时丢失。

## 验证方法

1. 打开/关闭 Form 多次，统计 Event 订阅、Entity、资源和 Widget 数量不增长。
2. 在资源/Entity 尚未加载完成时关闭 Form，确认请求取消且迟到结果不归属新实例。
3. 验证嵌套 Form 和嵌套 Widget 只归属最近父容器。
4. 重复 Open/Close/Remove 非法顺序，确认错误能在开发期暴露。
5. 重新生成 CodeBind，确认 `.Bind.cs` 可重复生成且业务 partial 无冲突。
6. ET 热重载后触发 Reactive 更新，确认旧 DllVersion Observer 不回池复用。
7. 连续执行两次 `Game/UI/Rebuild Common Component Library`，确认六个 prefab 的 GUID、脚本和标签稳定，并在目标 Form 中验证组件两次打开/关闭。

本次已核验四个容器、AExUIForm/AExUIWidget、动态 Widget、CodeBind 生成示例、ET Reactive 版本逻辑和六个通用组件 prefab。组件库已通过 Unity 编译与两次幂等重建；目标业务 Form 的交互回归、资源加载与热重载回归仍需在具体功能开发时执行。
