# 模块 05：UI 容器与组件绑定

> Catalog ID: `UNITY-05`  
> 状态：`verified`  
> 最后核验：`2026-08-03`  
> 适用模式：GameHot Client / ET Client / Shared UI

## 模块定位

项目用四个 `IReference` 容器把 UI 生命周期内的 Widget、事件、Entity 和资源归属到 Form 或 Widget。CodeBind 负责 prefab 到 partial 类字段的生成；StateController 与 ReactiveBinding 负责状态切换和数据响应。目标是让 UI 关闭时能统一释放，而不是由每个窗体散落管理。

## 依赖关系

`AExUIForm` 与 `AExUIWidget` 按需从 GF `ReferencePool` 获取容器。容器调用 `GameEntry.Event`、`GameEntry.Entity`、`GameEntry.Resource` 和共享 `UIWidgetContainer`。CodeBind 是 UPM 编辑器生成器，项目 Customizer 额外依赖 StateController。ET Reactive 使用 ReactiveBinding 接口和 ET `CodeTypes`。

## 入口与调用链

```text
AExUIForm.OnInit
  -> 收集直属 AExUIWidget
  -> UIWidgetContainer.AddUIWidget
     -> SetInitialized(true) + SetUIFormOwner + OnInit

业务调用 Subscribe / ShowEntity / LoadAsset
  -> 首次调用时从 ReferencePool 创建对应容器
  -> 容器记录本 Form/Widget 拥有的句柄或对象

AExUIForm.OnClose
  -> 关闭可用 Widget
  -> HideAllEntity
  -> UnsubscribeAll
  -> UnloadAllAssets
  -> shutdown 时移除 Widget 并释放容器
```

普通关闭保留容器对象供池中 Form 下次打开复用，但清空受管内容；shutdown 或 Mono OnDestroy 会释放容器到 ReferencePool。

## 核心类型与 API

| 类型/API | 管理内容 | 关键行为 |
| --- | --- | --- |
| `UIWidgetContainer` | AUIWidget 列表 | 防重复、校验 Open/Close 状态、转发生命周期与 Depth |
| `EventContainer` | EventId 到 Handler 多字典 | 订阅时登记；关闭时统一退订 |
| `EntityContainer` | UGF Entity serialId 集合 | 关闭时隐藏实体并取消异步 Show |
| `ResourceContainer` | 已加载 Unity Object 与取消源 | 关闭时卸载资源并取消异步 Load |
| `AExUIForm` | 四容器的 Form API | 只收集直属 Widget，避免跨 Form 归属 |
| `AExUIWidget` | 四容器与嵌套 Widget API | 父 Widget 优先于 Form 作为打开/关闭入口 |
| `ADynamicUIWidgetLoader` | 动态 prefab | Start 自动加载，实例铺满 Loader RectTransform |
| `GameCodeBindCustomizer` | 生成字段/属性/状态常量 | 序列化字段前缀 `m_`，公开属性保留成员名 |

## 数据与生命周期

`AUIWidget` 有三个独立状态：Initialized 表示已加入容器并执行 OnInit；Available 表示已 OnOpen 且未 OnClose；Visible 只有 Initialized 后可设置。关闭会先隐藏，再把 Available 置 false。

`ResourceContainer` 使用 `m_Version` 防止 callback 异步加载在容器复用后把旧资源交给新 Owner；UniTask 路径使用 CancellationTokenSource。`EntityContainer` 同样用 CancellationTokenSource 管理异步 Show，并用 serialId 集合限制 Hide 只能作用于归属实体。

`EventContainer` 记录全部订阅；shutdown 时不再调用可能已经关闭的 GameEntry Event，只清本地记录。所有容器的 `Clear()` 只重置内部状态，正确释放顺序由 AExUIForm/AExUIWidget 保证。

ET Reactive 在初始化时扫描 `[ETReactiveObserver]`，为 OwnerType 建池并递增 DllVersion；回收时只把当前 DLL 版本、类型仍匹配的 Observer 放回池，避免热重载后复用旧类型实例。

## 开发扩展步骤

### 在 Form/Widget 中管理资源

1. 业务基类继承 `AExUIForm` 或 `AExUIWidget`。
2. 使用基类 `Subscribe`、`ShowEntityAsync`、`LoadAssetAsync`、Widget API，不单独保存全局订阅。
3. 只对提前结束的单项调用显式 Unsubscribe/Hide/Unload；普通关闭由容器兜底。
4. 异步完成后仍要检查业务对象状态，尤其是关闭与重新打开之间的竞态。

### CodeBind

1. UI partial 类标记 `[MonoBehaviourBinding]`，Widget 根由 `AUIWidget` 的 `[BindingRoot]` 提供。
2. 在 prefab 中按 CodeBind 规则标记目标并执行生成。
3. 业务代码只引用生成的公开属性；`.Bind.cs` 是生成物，禁止手改。
4. StateController 目标会额外生成 `StateGroup` 属性、StateName 和 StateIndex 常量。

### ReactiveBinding

ET Host 实现 `IETReactiveHost`，Observer 使用对应特性与生成流程。热重载后由新的 `ETReactiveSystem.DllVersion` 隔离旧 Observer；不要把 Observer 跨 DLL 版本持久保存。

## 约束与常见错误

- Widget 必须先 Add/Init 才能 Open；可用 Widget 不能 Remove，未打开 Widget 不能 Close。
- `DynamicOpenUIWidget` 会额外刷新 Depth；Form OnOpen 中的静态 Widget 通常用 `OpenUIWidget`。
- `ADynamicUIWidgetLoader` 当前只在销毁前加载完成检查 `this == null`，加载成功资源由后续 Widget/Entity 生命周期负责；新增 Loader 时必须明确卸载所有权。
- `ResourceContainer` callback 路径会校验资源类型，类型不匹配立即卸载并抛异常。
- `EntityContainer` 当前 `OnShowEntityFail` 只释放内部事件参数，**没有调用已保存的 `OnFailureCallback`**；依赖失败回调前需先修正实现或使用可观察的 Async API。
- `EventContainer.Unsubscribe` 和 Entity Hide 的非 Try API 会在“不属于本容器”时抛异常；不确定状态使用 Try 版本。
- CodeBind 生成文件会被重新覆盖；业务逻辑、默认值和事件注册写在非生成 partial 文件。
- StateController 状态名会直接生成 C# 标识符，表述应满足合法标识符规则且避免重名。

## 验证方法

1. 打开/关闭 Form 多次，统计 Event 订阅、Entity、资源和 Widget 数量不增长。
2. 在资源/Entity 尚未加载完成时关闭 Form，确认请求取消且迟到结果不归属新实例。
3. 验证嵌套 Form 和嵌套 Widget 只归属最近父容器。
4. 重复 Open/Close/Remove 非法顺序，确认错误能在开发期暴露。
5. 重新生成 CodeBind，确认 `.Bind.cs` 可重复生成且业务 partial 无冲突。
6. ET 热重载后触发 Reactive 更新，确认旧 DllVersion Observer 不回池复用。
