# 模块 08：场景与相机

> Catalog ID: `UNITY-08`  
> 状态：`verified`  
> 最后核验：`2026-08-04`  
> 适用模式：GameHot / ET Client / Unity Runtime

## 模块定位

本模块用 Luban `DRScene` 把场景 ID 映射为 Unity 场景资源路径，并用 UGF Scene 完成加载/卸载。相机部分在持久化的默认场景相机与业务场景相机之间自动切换，并把 UI Camera 接入 URP Camera Stack。

GameHot 的完整换场流程由 `ProcedureChangeScene` 负责；ET Client 可直接调用 UGF 路径接口，不依赖 GameHot Procedure。

## 依赖关系

- 场景扩展依赖 `GameEntry.Tables.DTScene`、UGF `SceneComponent`、UniTask Awaitable 扩展和 `Constant.AssetPriority.SceneAsset`。
- 相机依赖 UGF Event、GF ReferencePool、Unity URP `UniversalAdditionalCameraData`。
- `CameraComponent`、UI Camera 和默认 Scene Camera 配置在 `Unity/Assets/Res/GameEntry.prefab`。
- GameHot `ProcedureChangeScene` 同时依赖 Entity、Sound、Event、Base 和 Procedure；ET 的场景切换调用点位于 `Game/ET/Loader/Helper/UGFHelper.cs` 及 HotfixView 场景流程。

## 入口与调用链

按 ID 加载的封装链路：

```text
GameEntry.Scene.LoadSceneAsync(sceneId)
  -> DTScene.GetOrDefault(sceneId)
  -> AssetUtility.GetSceneAsset(DRScene.AssetName)
  -> SceneComponent.LoadSceneAsync(path, SceneAsset priority)
```

GameHot Demo 的实际换场链路更完整：

1. `ProcedureChangeScene.OnEnter` 订阅 UGF 场景事件。
2. 停止全部声音、隐藏全部实体、卸载全部已加载场景并恢复正常游戏速度。
3. 从 FSM 的 `NextSceneId` 读取 `DRScene`，用资源路径调用 UGF `LoadScene`。
4. 成功事件中播放 `BackgroundMusicId`，再切到 `ProcedureMenu` 或 `ProcedureMain`。

相机接管链路：场景 Camera 上的 `SceneCamera.Awake` 立即发 Enable 事件；`CameraComponent` 将默认相机禁用，校验新相机是 URP Base Camera，并把 UI Camera 加入 Stack。`SceneCamera.OnDestroy` 发 Disable 事件，当前相机被销毁时恢复默认相机。

## 核心类型与 API

| 类型/API | 职责 | 生命周期/线程约束 |
| --- | --- | --- |
| `SceneIsLoading(sceneId)` | 将 ID 转路径后查询加载中状态 | 表项不存在时返回 false |
| `SceneIsLoaded(sceneId)` | 查询是否已加载 | 表项不存在时返回 false |
| `LoadScene(sceneId, userData)` | 触发 UGF 事件式加载 | 表项不存在时抛 `GameFrameworkException` |
| `LoadSceneAsync(sceneId)` | 返回 UniTask 的加载封装 | 当前 ID 版不接受 userData |
| `UnloadScene*` | 按 ID 卸载 | 同步版可传 userData，异步版不可传 |
| `CameraComponent` | 暴露 `UICamera`、`CurrentSceneCamera`，内部切换相机 | `SetCurrentSceneCamera` 是私有方法 |
| `SceneCamera` | 场景相机标记和生命周期事件源 | `internal`；在 `Awake`/`OnDestroy` 发同步事件 |
| `SceneCamera*EventArgs` | 携带 Camera 的池化事件参数 | 通过 GF `ReferencePool` 创建和清理 |

## 数据与生命周期

- `DRScene` 当前字段为 `Id`、`AssetName`、`BackgroundMusicId`，并解析 `BackgroundMusicId_Ref`。
- 资源路径固定为 `Assets/Res/Scene/{AssetName}.unity`。
- `CameraComponent.Awake` 先使用默认场景相机；`Start` 等待帧末后订阅场景相机事件。
- Menu、Main、Map1、Map2 场景当前都挂有 `SceneCamera`。
- 业务场景 Camera 必须是 URP Base Camera。接管时仅在缺失时追加 UI Camera，避免重复 Stack 项。
- `SceneCamera` 的事件名是 Enable/Disable，但实现时机实际是 `Awake`/`OnDestroy`，临时 `enabled=false` 不会触发交还。

## 开发扩展步骤

1. 按当前模式编辑场景表：GameHot 使用 `Design/Excel/GameHot/Datas/Game/Scene.xlsx`，ET 使用 `Design/Excel/ET/Datas/Game/Scene.xlsx`；不要只修改 inactive 的另一套工作簿。
2. 在 `Unity/Assets/Res/Scene` 创建同名 `.unity` 场景并运行 Luban 导出。GameHot 使用 `Game.Hot.SceneId`，ET 使用 `ET.Client.UGFSceneId`，不要手改生成代码。
3. 若场景有专属 Camera，挂载 `SceneCamera`，设为 URP Base Camera；不要手工把同一 UI Camera 重复加入 Stack。
4. GameHot 中设置 FSM `NextSceneId` 并切入 `ProcedureChangeScene`；简单叠加场景可调用 `GameEntry.Scene.LoadSceneAsync(sceneId)`。
5. ET Client 使用 ET 的 UGF Helper 或直接传 `AssetUtility.GetSceneAsset(name)` 给 UGF，不要引用 GameHot Procedure。

## 约束与常见错误

- `SceneExtension.CanLoadScene` 当前实现为 `!SceneIsLoading && SceneIsLoaded`，等价于“已经加载且未加载中”，不符合方法名。不要用它判断一个未加载场景能否加载；这是当前源码缺陷。
- `CameraComponent.SetCurrentSceneCamera` 并非公开 API，业务应通过挂载/销毁 `SceneCamera` 触发切换。
- 非 Base 类型的 URP Camera 会抛 `GameFrameworkException("Scene camera must be base camera.")`。
- `SceneCamera` 在 `Awake` 发事件，而 `CameraComponent` 到首帧末才订阅；正常流程依赖 GameEntry 先常驻、业务场景后加载。若把两者放进同一初始场景，事件可能早于订阅。
- GameHot `ProcedureChangeScene` 使用底层字符串路径 API，而不是本文的 ID 扩展；修改路径规则时两处都要核对。
- `ProcedureChangeScene` 加载失败只记录错误，不会设置完成标志或进入恢复流程。

## 验证方法

1. 导表后检查 `dtscene.json`、`DRScene.cs` 与当前模式生成的 GameHot `SceneId.cs` 或 ET `UGFSceneId.cs` 一致。
2. 在 Unity 从 Menu 切到 Main，确认旧实体/声音/场景被清理，成功后进入对应 Procedure 并播放配置音乐。
3. 观察 Hierarchy：业务场景加载后默认 Camera 禁用，当前 Camera Stack 含 UI Camera；卸载后默认 Camera 恢复。
4. 将测试 Camera 改为 Overlay，确认明确抛出 Base Camera 约束错误。
5. 运行知识库校验脚本；Unity 行为验证需要 Unity 6000.3.21f1 和项目依赖可用。
