# 模块 10：本地化（多语言）

> Catalog ID: `UNITY-10`  
> 状态：`verified`  
> 最后核验：`2026-08-04`  
> 适用模式：GameHot / ET Client / Unity Runtime / Editor / Tooling

## 模块定位

本地化模块以 `Design/Excel/Localization.xlsx` 为唯一业务语言源，生成各语言运行时字典、可用语言清单、资源路径代码和 ET/GameHot 强类型 Key。启动更新阶段使用随包发布的 Builtin 字典，预加载阶段再读取完整 Luban 字典。

当前 Demo 的语言切换是“保存后重启生效”，不是无缝热切换。

## 依赖关系

- 运行时依赖 UGF `LocalizationComponent`、GF `ILocalizationManager`、UniTask Awaitable、Luban `ByteBuf` 和项目 `BuiltinComponent`。
- 导出器依赖 `Share.Tool`、ExcelDataReader、Luban 配置开关和 `GameFramework.Localization.Language` 枚举。
- `ProcedureLaunch` 选择语言并加载 Builtin；`ProcedurePreload` 在配置表之后加载完整语言资源。
- GameEntry prefab 将 Localization Helper 配为 `Game.LubanLocalizationHelper`，因此 `XmlLocalizationHelper` 仅是可替换实现。
- GameHot `StarForceUIForm`、更新流程、Dialog/Menu/Setting UI 是当前调用者；UXTool 还消费导出的编辑器语言数据。

## 入口与调用链

启动链路：

1. `ProcedureLaunch.InitLanguageSettings` 优先使用编辑器资源模式的 Inspector 语言，否则读取 `Setting.Language` 或系统语言。
2. 当前只允许 English、ChineseSimplified、ChineseTraditional、Korean；其他值回退 English 并保存。
3. `ProcedureLaunch` 设置 `GameEntry.Localization.Language`，随后加载 Builtin 字典供资源更新前 UI 使用。
4. `ProcedurePreload` 先加载 Tables，再调用 `LoadLanguageAsync(currentLanguage)`。
5. `LoadLanguageAsync` 清空全部 RawString，再次加入对应 Builtin 字典，然后读取 `Assets/Res/Localization/{Language}/Localization.bytes`。
6. prefab 配置的 `LubanLocalizationHelper` 用 `ByteBuf` 逐对读取 key/value 并调用 `AddRawString`。

导出链路：`Design/Excel/gen all bin.bat` 从 `Bin` 启动 `Tool.exe --AppType=ExcelExporter`；Luban 导出后固定执行 Localization 后处理，生成语言资源和代码。JSON 脚本附加 `--Customs=Json`。

## 核心类型与 API

| 类型/API | 职责 | 生命周期/线程约束 |
| --- | --- | --- |
| `LoadLanguageAsync(Language)` | 重建 RawString 并异步读取完整字典 | 不会替调用者设置 `Localization.Language` |
| `LubanLocalizationHelper.ParseData(string)` | 解析 JSON 对象 | 重复/无效 Key 时警告并返回 false |
| `LubanLocalizationHelper.ParseData(byte[])` | 解析连续的 Luban 字符串对 | 当前二进制资源使用此路径 |
| `XmlLocalizationHelper` | 从 Dictionaries 中选择当前语言节点 | 仅在替换 prefab Helper 后生效 |
| `BuiltinComponent.InitDefaultDictionary` | 注入当前语言的随包基础文案 | 找不到语言或重复 Key 时警告 |
| `BuiltinLocalizationDictionary` | Odin 序列化的 Language -> Dictionary 资产 | 由 GameEntry prefab 引用 |
| `LocalizationKey` | 强类型字符串常量 | 生成物；GameHot 与 ET 分别生成 |

## 数据与生命周期

- Excel 中只有左上角以 `##` 开头的 Sheet 参与导出；表头必须包含 `key`，其他有效列名必须与 `Language` 枚举名称完全一致。
- 同一语言的 Key 在整个工作簿范围内必须唯一；导出器以有序字典生成稳定结果。
- 二进制模式生成 `Localization.bytes` 并删除旧 JSON；JSON 模式反向处理，同时重写 `AssetUtility.Localization.cs` 的扩展名。
- Builtin 资产当前包含语言名称、`CheckVersion.Tips`、`UpdateResource.Tips` 等资源更新前必须可用的少量 Key；完整业务 Key 来自 Excel。
- `StarForceUIForm.OnInit` 把所有非空旧版 `Text.text` 当作 Key，只在首次初始化时替换。当前重启式切换避免了已打开窗体不刷新的问题。
- SettingForm 保存所选语言后停止音乐并调用 `ShutdownType.Restart`；下次启动重新选择并加载字典。

## 开发扩展步骤

1. 在 `Design/Excel/Localization.xlsx` 的有效 Sheet 增加唯一 Key，并为所有已支持语言填值。
2. 在仓库已编译 `Kit.sln` 的前提下，`Push-Location Design/Excel` 后运行 `gen all bin.bat` 再 `Pop-Location`，或从 Unity 菜单执行 `Game/Tool/ExcelExporter`。这些 bat 未用 `%~dp0` 固定自身目录。
3. 检查四个语言资源、`LocalizationReadyLanguage.cs`、`AssetUtility.Localization.cs` 以及启用模块对应的 `LocalizationKey.cs`。
4. 业务代码优先引用生成常量：

```csharp
string title = GameEntry.Localization.GetString(
    LocalizationKey.Key_AskQuitGame_Title);
```

5. 新增支持语言时，还要扩展 `ProcedureLaunch` 的白名单、Builtin 字典资产、GameEntry prefab 引用以及 UI 选择项。

## 约束与常见错误

- `LoadLanguageAsync(language)` 不会设置 `GameEntry.Localization.Language`。非启动流程调用时必须先设置组件语言，否则当前状态、解析器和 UI 可能不一致。
- 当前 GameEntry prefab 使用 Luban Helper；旧文档中“运行时读取 XML”不适用于当前配置。
- `--Customs=Check` 会跳过 Localization 导出，只做 Luban 校验，不能用来刷新语言资源或 Key。
- 生成资源和 `LocalizationKey` 禁止手改；切换 bin/json 后资源扩展名及路径代码必须成套提交。
- `BuiltinComponent.CollectAllLocalizationDictionary` 的“缺失 Key”循环当前遍历每个字典自身的 Key 再检查全局并集，无法发现某语言缺少其他语言已有的 Key；不能把它当作完整性证明。
- `StarForceUIForm` 会把任何非空 `Text.text` 当 Key。需要保留运行时字面文本时，应在代码中于初始化后设置，或使用项目的 UX 本地化配置。
- 当前默认切换会重启应用；若实现即时切换，还必须等待字典加载、刷新现有 UI，并同步 UXTool 的语言状态。

## 验证方法

1. 在 `Design/Excel` 工作目录运行 `check all.bat` 检查 Luban；再在同一目录运行 bin 或 json 导出以实际刷新 Localization。
2. 对比 `LocalizationReadyLanguage.Languages` 与 `Unity/Assets/Res/Localization` 目录，并确认每种语言都有同扩展名文件。
3. 启动 Unity，确认资源更新前 Builtin 文案可读，进入 `ProcedurePreload` 后业务 Key 可读。
4. 在 SettingForm 选择另一语言并提交，确认重启后 `Setting.Language`、GF 当前语言和 UI 文案一致。
5. 人为制造重复 Key 或无效语言列，确认导出器失败而不是静默覆盖。
