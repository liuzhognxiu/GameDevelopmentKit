# 模块 11：事件、日志与调试

> Catalog ID: `UNITY-11`  
> 状态：`verified`  
> 最后核验：`2026-08-04`  
> 适用模式：GameHot / ET Client / Unity Runtime / Editor

## 模块定位

该模块补充 UGF 全局事件总线的安全退订、带分类标签的 GF 日志入口，以及运行时 Debugger 的项目工具页。GF Event 与 ET EventSystem 是两套独立机制；本文只覆盖 Unity/UGF 一侧。

## 源码边界

| 类型 | 仓库相对路径 | 说明 |
| --- | --- | --- |
| 事件扩展 | `Unity/Assets/Scripts/Game/Event/EventExtension.cs` | `TryUnsubscribe` |
| 自动管理 | `Unity/Assets/Scripts/Game/Container/EventContainer.cs` | UI/Entity 生命周期订阅容器 |
| 分类日志 | `Unity/Assets/Scripts/Game/Log` | `GLog` 与 `LogWithTag` |
| 日志菜单 | `Unity/Assets/Scripts/Game/Editor/Log/GLogTool.cs` | EditorPrefs 开关与菜单 |
| 调试窗口 | `Unity/Assets/Scripts/Game/Debugger/ToolDebuggerWindow.cs` | RuntimeInspector 按钮 |
| 注册点 | `Unity/Assets/Scripts/Game/Procedure/ProcedureLaunch.cs` | Debugger 活跃时注册 Tool 页 |

## 依赖关系

- 事件依赖 UGF `EventComponent`、GF `GameEventArgs` 和 `ReferencePool`。
- `EventContainer` 被 `AExUIForm`、`AExUIWidget`、`AExEntity` 使用，在宿主关闭时批量退订。
- 日志依赖 `GameFrameworkLog`、`Utility.Text` 和 C# `ConditionalAttribute`；编辑器开关依赖 UnityEditor。
- 调试页依赖 UGF `IDebuggerWindow`、UIComponent 和 `RuntimeInspector` UIGroup。
- ET 动态事件、Fiber 事件和 UGF Event 不共享事件 ID、订阅容器或生命周期。

## 入口与调用链

安全退订链路是 `EventContainer.TryUnsubscribe` -> `GameEntry.Event.TryUnsubscribe` -> 先 `Check(id, handler)`，存在时才调用 UGF `Unsubscribe`。

分类日志链路是 `GLog.UI.Info(...)` -> 检查 `IsEnabled` -> 在标签前加 Rich Text -> `GameFrameworkLog.Info` -> BaseComponent 当前日志 Helper。编辑器加载时 `GLogTool` 从 EditorPrefs 恢复每个分类开关。

调试链路：`ProcedureLaunch` 仅在 `GameEntry.Debugger.ActiveWindow` 为真时注册 `ToolDebuggerWindow`；点击 `Show RuntimeInspector` 直接以资源路径打开到 `RuntimeInspector` UIGroup。

## 核心类型与 API

| 类型/API | 职责 | 生命周期/线程约束 |
| --- | --- | --- |
| `TryUnsubscribe(id, handler)` | 避免重复退订 | handler 必须与订阅时委托实例一致 |
| `GameEventArgs` 子类 | UGF 事件载荷 | 通常从 ReferencePool 获取并在 `Clear` 清空引用 |
| `GLog` | Entity/Game/Procedure/Resource/Scene/Sound/UI 七类入口 | 每类默认 `IsEnabled=false` |
| `LogWithTag` | Debug/Info/Warning/Error/Fatal 及 0-16 参数重载 | 同时受 `IsEnabled` 和日志编译符号控制 |
| `GLogTool` | 菜单启停分类日志 | 仅 Editor；状态保存在 EditorPrefs |
| `ToolDebuggerWindow` | UGF IMGUI 调试页 | 当前只有打开 RuntimeInspector 的按钮 |

## 数据与生命周期

- 事件参数的 `EventId` 通常使用 `typeof(EventArgsType).GetHashCode()`，创建方通过 `ReferencePool.Acquire` 填值，`Clear` 必须还原字段。
- `EventContainer` 记录宿主订阅；正常关闭和 shutdown 的退订策略由容器处理，优先在扩展 UI/Entity 基类中使用它。
- `GLog` 实例为静态单例。编辑器启动读取 `Game.Log.*`；Player 中没有 `GLogTool`，若业务未设置 `IsEnabled`，分类日志保持关闭。
- 每个日志级别的方法都带 Conditional；调用点可能在编译期被移除，具体取决于 `ENABLE_LOG`、单级别或 `*_AND_ABOVE_LOG` 符号。
- GameEntry prefab 当前使用 `UnityGameFramework.Runtime.DefaultLogHelper`；`HyperlinkLogHelper` 并未配置为运行时 Helper。

## 开发扩展步骤

1. 新事件继承 `GameEventArgs`，定义稳定静态 EventId、只读公开数据、`Create` 和完整 `Clear`。
2. UI/Entity 内通过宿主的 `Subscribe` 方法订阅，让 `EventContainer` 自动管理；全局服务才直接用 `GameEntry.Event.Subscribe`。
3. 发布时选择 `Fire` 或 `FireNow`，并确认同步重入是否安全。
4. 新日志分类在 `GLog` 增加实例，并同步扩展 `GLogTool` 的加载、全开关、菜单和 EditorPrefs 键。
5. 新调试能力实现 `IDebuggerWindow`，在 `ProcedureLaunch` 或已有 Tool 页注册/绘制。

## 约束与常见错误

- `TryUnsubscribe` 只防重复退订，不会解决匿名 lambda 无法用另一个实例退订的问题。
- 不要把 ET 的 `EventSystem.Publish*` 事件参数传给 UGF Event，反之亦然。
- 只打开 `GLog.*.IsEnabled` 仍不保证日志存在；若对应 Conditional 符号未定义，调用已被编译器移除。
- `GLogTool.SetAllLog` 当前重复写 `Game.Log.Entity`，漏写 `Game.Log.Sound` 的 EditorPrefs。当前会话内 Sound 开关会改变，但重载编辑器后“Enable All”设置的 Sound 状态可能不保留。
- `ToolDebuggerWindow` 用硬编码资源路径和组名打开 RuntimeInspector；重命名资源或 UIGroup 时必须同步修改。
- 当前项目没有通过 `HyperlinkLogHelper` 输出；不要宣称所有日志自动支持源码超链接。

## 验证方法

1. 在 Editor 用 `Game/Log Tool` 切换单分类和 Enable All，重载脚本后检查 EditorPrefs 恢复，重点观察 Sound。
2. 确认启用日志编译符号时分类日志出现，关闭 `IsEnabled` 或移除符号后不出现。
3. 用扩展 UIForm 订阅事件，关闭窗体后再次发布，确认处理器不再执行。
4. 启用 UGF Debugger，确认 Tool 页可以打开 RuntimeInspector 且组名存在。
5. 执行知识库静态校验脚本。
