# 模块 13：内置窗体与通用 UI

> Catalog ID: `UNITY-13`  
> 状态：`verified`  
> 最后核验：`2026-08-04`  
> 适用模式：GameHot / ET Client / Unity Runtime

## 模块定位

本模块包含资源更新前可用的 Builtin 数据与轻量窗体、UGF UIForm/UIWidget 的项目基础类、动态 Widget 加载器，以及 Debugger 打开的 RuntimeInspector。Builtin 对象通过已序列化模板直接 Instantiate，不走普通 UIForm 表；通用 UI 基类则供 GameHot 与 ET 桥接共同复用。

## 依赖关系

- Builtin 依赖 GameEntry Base、Screen、Debugger、Localization 和 UGF Resource 更新流程。
- `AUIForm` 继承 UGF `UIFormLogic`；`AUIWidget` 是带 CodeBind `BindingRoot` 的 MonoBehaviour。
- `AExUIForm/AExUIWidget` 依赖模块 05 的四类 Container，并把生命周期转发给子 Widget。
- 动态加载器依赖 UGF Resource Awaitable 和 UniTask；同一抽象加载器分别有 Game 与 ET 接入实现。
- RuntimeInspector 依赖 CodeBind 生成 partial、StateController 和名为 `RuntimeInspector` 的 UIGroup。

## 入口与调用链

更新资源链路：Procedure 根据网络/版本状态构造 `BuiltinDialogParams` -> `BuiltinComponent.OpenDialogForm` Instantiate 模板并 Open；资源更新开始后直接 Instantiate `UpdateResourceFormTemplate`，事件累计进度并调用 `SetProgress`，离开 Procedure 时 Destroy。

普通扩展 UIForm 链路：UGF 创建 AExUIForm -> `OnInit` 收集直属 `AExUIWidget` 并加入 `UIWidgetContainer` -> 打开/暂停/恢复/深度更新向子 Widget 传播 -> 关闭时退订事件、隐藏实体、卸载资源并关闭 Widget。

动态 Widget：Loader 的 Start 异步加载 prefab -> Instantiate 为子物体 -> 校验 AUIWidget -> Game 实现把 AExUIWidget 加入最近的父 Widget 或父 Form，并根据组件 enabled 状态动态打开。

## 核心类型与 API

| 类型/API | 职责 | 生命周期/线程约束 |
| --- | --- | --- |
| `BuiltinComponent` | 选择 Debug/Release BuildInfo、初始化 Builtin 字典、实例化模板 | 挂在 GameEntry prefab |
| `BuiltinDialogParams` | 标题、消息、三个按钮、暂停与回调数据 | 普通 class，不走 ReferencePool |
| `BuiltinDialogForm` | 配置按钮并可暂停/恢复游戏 | 当前按钮回调不自动 Close |
| `BuiltinUpdateResourceForm` | 设置 Slider 和说明文本 | Procedure 自己 Instantiate/Destroy |
| `AUIForm` | 全屏 RectTransform、Canvas/粒子深度、关闭和 UI 音效 | UGF UIForm 生命周期 |
| `AUIWidget` | Widget 可用、可见和完整生命周期 | 必须先 SetInitialized 才能切 Visible |
| `AExUIForm/AExUIWidget` | 自动 Container 和嵌套 Widget 管理 | shutdown 时额外移除 Widget/清容器 |
| `ADynamicUIWidgetLoader` | Start 时异步加载并实例化 Widget | 类位于 `ET` 命名空间，尽管文件在 Game/UI |
| `RuntimeInspectorForm` | 绑定关闭按钮并切换横屏布局 | Debugger 直接按资源路径打开 |

## 数据与生命周期

- `BaseBuiltinForm.Awake` 根据 Screen SafeArea 与标准纵横比设置 CanvasScaler；Close 会禁用并 Destroy GameObject。
- `BuildInfo` 按 `GameEntry.Debugger.ActiveWindow` 选择 Debug 或 Release 资产。当前 Release 资产没有配置字段，Debug 仅配置本地版本检查 URL。
- GameEntry prefab 已引用四种语言字典和 UpdateResourceForm，但 `m_DialogFormTemplate` 当前为 null。
- `BuiltinDialogParams.Mode` 在 Form 中没有被读取；实际按钮显示只取决于对应文本是否为空。
- AUIForm 深度公式使用 UIGroup `1000 * depth` 和窗体内 `100 * depthInGroup`，同时调整所有子 Canvas 和 ParticleSystemRenderer。
- 动态 Loader 成功后未保存并释放已加载 prefab 资源句柄，也没有销毁时卸载逻辑；当前存在资源所有权缺口。

## 开发扩展步骤

1. 资源更新前 UI 放在 Builtin，创建随包 prefab 并在 GameEntry prefab 序列化引用；不要依赖尚未完成的资源初始化。
2. 普通业务窗体继承 `AExUIForm`（GameHot 再继承 `AHotUIForm`），子控件继承 `AExUIWidget`，优先使用宿主 Container API。
3. 动态 Widget prefab 根节点必须有 AUIWidget 派生组件，Loader 配置资源路径并选择 Game 或 ET 对应实现。
4. RuntimeInspector 类工具需要先配置 UIGroup，再在 Debugger Window 中以路径打开。
5. 修改 Builtin 对话框前先补齐模板引用、关闭语义与 PauseGame 恢复，再用于强制更新/流量确认。

## 约束与常见错误

- 当前 `m_DialogFormTemplate` 为 null，`OpenDialogForm` 在版本/流量分支会 Instantiate null；必须配置后才可用。
- `BuiltinDialogForm` 三个按钮只调用回调，不调用 Close；`PauseGame=true` 时也不会自动 Resume。回调必须显式处理关闭，或统一修正 Form 行为。
- `BuiltinBuildInfo.IOSAppUrl` getter 返回自身而不是 `m_IOSAppUrl`，读取会无限递归；iOS 强更路径当前不可用。
- 空的 `BuiltinExtension.OpenBuiltinDialog` 是 no-op，不要调用它代替 `OpenDialogForm`。
- Release BuildInfo 当前为空；非 Debugger 模式的版本检查 URL 可能为空。
- 动态 Loader 文件声明 `namespace ET`，Game 实现需要 `using ET`；不要仅根据目录推断命名空间。
- 动态 Loader 当前没有成对 `UnloadAsset`，频繁创建销毁前应先补资源所有权。

## 验证方法

1. 在 GameEntry prefab 检查 BuildInfo、四语言字典、UpdateResourceForm、DialogForm 和 UIGroup 引用，禁止忽略 null。
2. 模拟强制更新与移动网络更新，验证按钮、关闭、暂停恢复和模板实例生命周期。
3. 打开/关闭 AExUIForm，确认子 Widget 生命周期、事件退订、实体隐藏和资源卸载。
4. 加载动态 Widget 后销毁宿主，用 UGF Resource/Profiler 检查 prefab 是否仍被持有。
5. 启用 Debugger 打开 RuntimeInspector，检查横屏 StateController 和 Close 绑定。
