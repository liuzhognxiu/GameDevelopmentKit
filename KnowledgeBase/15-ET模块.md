# 模块 15：ET Core、Unity Loader 与四业务程序集

> Catalog ID: `ET-01`、`ET-02`、`ET-03`  
> 状态：`verified`  
> 最后核验：`2026-08-04`  
> 适用模式：ET Client / ET Server / Shared / Unity Runtime

## 模块定位

ET Core 提供 World/Singleton、Entity System、Fiber、事件、网络和序列化基础；Unity Loader 把日志、时间、配置与 UGF 资源适配给 ET，并负责静态或字节程序集装载；业务再按 Model、Hotfix、ModelView、HotfixView 四程序集隔离数据定义、逻辑与 Unity 视图。

本文不重复 ETUI/ETEntity 桥接细节，也不把 GameHot Procedure 与 ET Fiber 混为一套生命周期。

## 依赖关系

- `Game.ET.Loader` 只在 `UNITY_ET` 下编译，引用 ET Core、Game、UGF、UniTask 和 UI 扩展库。
- Model 与 Hotfix 设置 `noEngineReferences=true`；ModelView 与 HotfixView 可引用 UnityEngine、UGF、CodeBind、UXTool 等。
- 四程序集都要求 `UNITY_ET`，并使用 `!UNITY_HOTFIX || UNITY_COMPILE || UNITY_EDITOR` 约束决定是否参与当前 Unity 编译。
- Hotfix 依赖 Model；ModelView 依赖 Model/Loader/Game；HotfixView 依赖前三者与 Loader。
- 独立 DotNet 服务端复用 ET Core/业务代码思想，但入口和项目文件属于 SERVER 模块。

## 入口与调用链

1. `ProcedurePreset` 在 `UNITY_ET` 下切换到 `ProcedureET`。
2. `ProcedureET.OnEnter` 调 `GameEntry.CodeRunner.StartRun("ET.Init")`，CodeRunner 创建 Unity Mono 入口。
3. `ET.Init.StartAsync` 解析空参数、强制 `StartConfig=Localhost`，向 World 注册 Options、UnityLogger、UnityTimeNow、FiberManager、ConfigComponent 和 CodeLoaderComponent。
4. CodeLoader 选择已加载程序集或 `Assets/Res/ET/Code/*.dll.bytes`，注册包含 Core、Loader、四业务程序集的 CodeTypes。
5. CodeLoader 反射 Model 中的 `ET.Entry.Start`。
6. Entry 注册 IdGenerater、OpcodeType、ObjectPool、MessageQueue、NetServices、Navmesh、LogMsg，创建代码 Singleton，加载配置并创建 Main Fiber。
7. `FiberInit_Main` 依次发布 EntryEvent1/2/3；共享模块、服务端或客户端视图按 SceneType 完成组件初始化。
8. CodeLoader 返回后，Init 才添加 Runner；Runner 每帧更新 TimeInfo/FiberManager，并在销毁时发布 OnShutdown、Dispose World。

## 核心类型与 API

| 类型/API | 职责 | 生命周期/线程约束 |
| --- | --- | --- |
| `World` | 按类型保存 ASingleton 并按栈逆序释放关键 Singleton | 进程级静态实例；Dispose 后可重新创建 |
| `Entity` / `EntitySystemSingleton` | 数据实体与特性扫描的生命周期 System | 不直接覆写 Mono 生命周期 |
| `EventSystem` | 按 struct 类型+SceneType Publish，按 type Invoke | Publish 可无订阅；Invoke 缺处理器会抛错 |
| `FiberManager` | Main/Thread/ThreadPool Scheduler 与 Fiber 创建移除 | Editor 中三种 Scheduler 都映射主线程 |
| `ET.Init` | Unity Mono 壳和 Runner 所有者 | ProcedureET 进入/离开时由 CodeRunner 管理 |
| `CodeLoader.StartAsync` | 初次选择程序集并调用 ET.Entry | Model/ModelView 保存为稳定程序集引用 |
| `CodeLoader.ReloadAsync` | 重载 Hotfix/HotfixView 并重建 CodeTypes | 仅 EnableHotfix 可调用 |
| `ConfigReader` | 按 CodeMode 从 ET Client 或 ClientServer Luban 资源读取 | 读取后立即 Unload TextAsset |
| `Define.CodeMode` | Client/Server/ClientServer | 未设置对应宏时访问直接抛异常 |

## 数据与生命周期

- Unity Init 使用空命令行，Options 的 StartConfig 固定为 `Localhost`；不是从 Player 启动参数读取。
- 开启 `UNITY_HOTFIX` 且 CodeRunner 为 CodeBytesMode 时，Editor 默认仍复用 Unity 的 Model/ModelView，Hotfix/HotfixView 从 bytes 加载；Player 可四个都从 bytes 装载。
- 非 bytes 路径从当前 AppDomain 按程序集名查四程序集；缺失值没有统一前置校验，后续反射可能失败。
- Main Fiber 固定 ID `ConstFiberId.Main`、zone 0、初始 SceneType.Main；客户端 EntryEvent3 根据 GlobalComponent.AppType 改写 Root SceneType。
- Editor 的 UnityTimeNow 跟随 `GameEntry.Base.GameSpeed`；Player 实现直接返回 UTC ticks，不缩放时间。
- ProcedureET 离开会 StopRun，最终 Runner OnDestroy Dispose 整个 ET World。

## 开发扩展步骤

1. 纯数据、组件、消息契约放 Model；不含 Unity API 的 System 放 Hotfix。
2. Mono/UGF 视图组件定义放 ModelView，对应业务 System 放 HotfixView。
3. 新进程/客户端初始化使用带 SceneType 的 ET Event 或 FiberInit，不要在 Unity Init 中堆业务组件。
4. 新 Singleton 若需热重建加 `[Code]` 并确认 CreateCode 生命周期；稳定基础 Singleton 在 Entry 显式注册。
5. 新配置按 CodeMode 放入 ET Client/ClientServer Luban 输出，并经 ConfigComponent 读取。

## 约束与常见错误

- Model/Hotfix 禁止引用 UnityEngine；需要 Transform、UGF UI/Entity 的代码必须进入 View 程序集或 Loader 桥接层。
- Editor 的 Thread/ThreadPool Scheduler 实际仍在主线程，不能用 Editor 行为证明 Player 多线程安全。
- `FiberManager.Get` 是 internal，禁止直接持有其他 Fiber；跨 Fiber 用消息通信。
- Runner 在 CodeLoader 完成后才创建；装载/Entry 异常会导致 ET 没有帧更新，但 UGF 主循环仍可能正常。
- CodeMode 宏缺失时 ConfigReader 访问 `Define.CodeMode` 会抛出菜单提示异常。
- Reload 只替换 Hotfix/HotfixView；修改 Model 契约通常需要完整重启或重新构建，不应期待热重载生效。
- `UNITY_ET_VIEW` 只在 Editor 提供实体调试视图，不是运行时业务 GameObject 所有权方案。

## 验证方法

1. 在 Unity 检查 `UNITY_ET` 与唯一 CodeMode 宏，进入 Play 后确认 ProcedureET、ET.Entry 和 Main Fiber 日志顺序。
2. 分别验证普通程序集模式、Editor bytes 模式和 Player bytes 模式的六程序集集合完整。
3. 创建 Main/ThreadPool Fiber，在 Editor 与 Player 对比线程行为，并用 Actor 消息跨 Fiber。
4. 修改 Hotfix System 后执行 reload，确认逻辑更新；修改 Model 后确认不会被错误热替换。
5. 退出 ProcedureET，确认 OnShutdown 被调用且 World/Fiber/Singleton 全部释放。
