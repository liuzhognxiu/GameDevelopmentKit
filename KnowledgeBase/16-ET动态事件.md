# 模块 16：ET 动态事件

> Catalog ID: `ET-06`  
> 状态：`verified`  
> 最后核验：`2026-08-04`  
> 适用模式：ET Client / ET Server / Main Fiber

## 模块定位

DynamicEvent 是按参数类型、SceneType 和实体精确类型，对 Main Scene 内已注册 ET Entity 做进程内广播的扩展。它支持 fire-and-forget 与等待全部处理器，不跨 Fiber、进程或网络，也不替代 Actor 消息/RPC。

## 依赖关系

- 依赖 ET Entity/EntityRef、CodeTypes、SceneType、TimeInfo、ListComponent 和 UniTask。
- `EntryEvent1_InitDynamicEvent` 只响应 `SceneType.Main`，注册表属于 Main Scene/Fiber。
- 处理器由带 `[Code]` 的 Singleton 在当前 CodeTypes 中扫描 `[DynamicEvent]` 类型。
- 参数必须是 struct；接收者必须挂 `DynamicEventReceiverComponent`。
- UGF Event、ET 普通 EventSystem 和 DynamicEvent 是不同分发机制。

## 入口与调用链

初始化：Main Fiber 发布 EntryEvent1 -> Main 处理器添加 DynamicEventComponent -> 类型系统扫描并实例化所有处理器。

注册：实体添加 Receiver -> Awake 从 `Root()` 取得 DynamicEventComponent -> 以 `entity.GetType()` 加入列表；Destroy 只加入待移除列表，下一次 Update 删除。

发布：按参数运行时 Type 找处理器 -> `HasSameFlag` 过滤 SceneType -> 按处理器 EntityType 精确查实体列表 -> 对有效 EntityRef 调 `Handle`。同步版对每个任务 `.Forget()`；Async 版收集后 `UniTask.WhenAll`。

## 核心类型与 API

| 类型/API | 职责 | 生命周期/线程约束 |
| --- | --- | --- |
| `ADynamicEvent<A,B>` | A 为实体，B 为 struct 参数 | `Run(A,B)` 返回 UniTask；Handle 捕获异常 |
| `[DynamicEvent(SceneType)]` | 声明处理器作用域 | 默认 All；允许同类多次标注 |
| `DynamicEventReceiverComponent` | 自动注册/反注册 Parent | Root 必须有 DynamicEventComponent |
| `Publish(arg)` | 使用组件所属 SceneType，不等待 | 处理器任务 fire-and-forget |
| `Publish(sceneType,arg)` | 显式指定过滤 SceneType | 仍使用同一个 Main 注册表 |
| `PublishAsync*` | 并发等待全部匹配处理器 | 不保证顺序或业务成功 |

## 数据与生命周期

- 注册表是 `Dictionary<Type,List<EntityRef<Entity>>>`，键为实体精确运行时类型。
- 反注册延迟到下一帧 Update；失效 EntityRef 不会被执行。
- 每 60 秒全量移除失效引用，发布时也顺便清理当前匹配列表。
- `ADynamicEvent.Handle` 捕获并记录每个处理器异常，因此 `PublishAsync` 不向调用者传播业务失败。
- 热重载重建 CodeTypes/类型系统后可发现新处理器；Scene 上已注册实体列表不随 Hotfix 程序集重载自动丢失。

## 开发扩展步骤

1. 定义唯一的 readonly struct 参数。
2. 实现 `ADynamicEvent<TEntity,TArg>`，添加 `[DynamicEvent(SceneType.X)]`，在 `Run` 中返回 UniTask。
3. 给 Main Fiber 中的目标实体添加 `DynamicEventReceiverComponent`。
4. 从 `scene.Root().GetComponent<DynamicEventComponent>()` 调 Publish 或 PublishAsync。
5. 有顺序、结果、跨 Fiber 或网络要求时，改用显式服务/Actor 请求，不要叠加 DynamicEvent。

```csharp
[DynamicEvent(SceneType.Client)]
public sealed class RefreshLevel : ADynamicEvent<Player, PlayerLevelChanged>
{
    protected override UniTask Run(Player self, PlayerLevelChanged arg)
    {
        self.Level = arg.Level;
        return UniTask.CompletedTask;
    }
}
```

## 约束与常见错误

- 旧示例的 void `Handle` 覆写不存在；当前必须覆写 `protected UniTask Run(A self, B arg)`。
- 基类处理器不会自动接收派生实体，注册与查询都是精确 Type。
- Receiver 的 `Root()` 没有 DynamicEventComponent 时 Awake 会空引用；其他 Fiber 默认未初始化本模块。
- Async 处理器并发执行且异常被内部吞并记录，不能提供事务、顺序或成功结果。
- 适合低频状态通知；每帧向大量实体广播会线性扫描并产生 UniTask 调度成本。
- 显式传 SceneType 只改变过滤条件，不会跨到该 SceneType 所在的其他 Fiber。

## 验证方法

1. 在 Main Fiber 创建两个同类型实体并挂 Receiver，发布后确认都收到。
2. 覆盖匹配/不匹配 SceneType、派生实体、移除 Receiver 和实体销毁。
3. 让一个处理器抛异常，确认其他处理器继续且 PublishAsync 正常结束但日志有错。
4. 热重载处理器后确认新 CodeTypes 注册生效且原实体仍在注册表。
5. 用性能采样验证目标规模和发布频率，而不是假设广播零开销。
