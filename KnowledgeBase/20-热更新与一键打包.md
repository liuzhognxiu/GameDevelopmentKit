# 模块 20：HybridCLR 热更新与一键打包

> Catalog ID: `BUILD-01`  
> 状态：`verified`  
> 最后核验：`2026-08-04`  
> 适用模式：GameHot / ET Client / Editor

## 模块定位

BUILD-01 覆盖 Unity 客户端从模式选择到可运行 Player 的构建面：同步 `UNITY_HOTFIX` 与业务模块配置、编译热更新程序集、生成 HybridCLR IL2CPP 产物、复制 AOT 补充元数据、构建 UGF 资源，最后调用 Unity `BuildPipeline` 生成 Player。

这不是单个原子“一键”命令。`HybridCLR/Do All` 负责热更新与 AOT 准备，`Game/Build Tool Editor` 负责资源和 Player；`Build Pkg` 不会调用 `HybridCLR/Do All`。DotNet ET 服务端也不在此链路内，它由 `Kit.sln` / `DotNet.sln` 构建。

## 依赖关系

```text
UNITY_ET / UNITY_GAMEHOT + UNITY_HOTFIX + ET CodeMode
  -> DefineSymbolTool.Refresh
     -> HybridCLR enable/disable
     -> Assets/link.xml 条件区块
     -> hotUpdateAssemblyDefinitions / patchAOTAssemblies
     -> ET 或 GameHot ResourceRule + Luban 配置

当前 Build Target
  -> 模块 BuildAssemblyTool
     -> PlayerBuildInterface.CompilePlayerScripts
     -> *.dll.bytes / *.pdb.bytes
     -> Temp/HybridCLRBin 原始 DLL/PDB
  -> HybridCLR/Generate/All
     -> HybridCLRData/AssembliesPostIl2CppStrip/<BuildTarget>
  -> CopyAotDlls
     -> Assets/Res/HybridCLR/*.dll.bytes
     -> HybridCLRConfig.asset

GameEntry.prefab ResourceMode + ResourceBuilder.xml + ResourceRule
  -> UGF BuildEventHandle
  -> Temp/Bundle + Assets/StreamingAssets
  -> BuildPipeline.BuildPlayer
  -> Temp/Pkg/<Platform>
```

热更新程序集集合固定为：

| 模式 | 热更新程序集 | 资源目录 | 编辑器运行中重载 |
| --- | --- | --- | --- |
| ET | `Game.ET.Code.Model`、`ModelView`、`Hotfix`、`HotfixView` | `Assets/Res/ET/Code` | `ETReload` 只重新加载 `Hotfix` 与 `HotfixView`；Model 两个程序集沿用启动时实例 |
| GameHot | `Game.Hot.Code` | `Assets/Res/Hot/Code` | 只有 `HotCompile` 编译按钮，没有等价的运行中重载入口 |

`UNITY_HOTFIX` 选择 DLL 资源加载方式；`UNITY_ET` / `UNITY_GAMEHOT` 选择业务模块。AOT 补充元数据不是业务热更 DLL，它来自目标平台 IL2CPP 裁剪后的 AOT 程序集，用于支持热更新代码引用的泛型等元数据。

## 入口与调用链

推荐的完整构建顺序如下，必须先选最终目标平台：

1. 用 `Game/Define Symbol` 选择 ET 或 GameHot、ET CodeMode 和 `UNITY_HOTFIX`，等待 Unity 重编译。
2. 导出受影响的 Luban、Proto 等生成物；执行 `Game/Define Symbol/Refresh` 校准资源规则、`link.xml` 和 HybridCLR 设置。
3. 切换到最终 Build Target，再执行 `HybridCLR/Do All`。
4. 检查业务 `.dll.bytes/.pdb.bytes`、AOT `.dll.bytes` 和 `HybridCLRConfig.asset` 都属于当前平台和当前宏组合。
5. 打开 `Game/Build Tool Editor`，选择同一平台，执行 Build Resource 或 Build Pkg。
6. 以 Unity ResourceBuilder `BuildLog.txt`、产物内容和 Player 启动结果判定成功，不能只看窗口最后一条 `Success` 日志。

`HybridCLR/Do All` 的真实同步链为：

```text
HybridCLREditor.HybridCLRDoAll
  -> ExecuteMenuItem("Game/Define Symbol/Refresh")
  -> [UNITY_HOTFIX && UNITY_GAMEHOT] GameHot/Compile Dll
  -> [UNITY_HOTFIX && UNITY_ET] ET/Compile Dll
  -> HybridCLR/Generate/All
  -> HybridCLR/CopyAotDlls
     -> 清理 Assets/Res/HybridCLR/*.dll.bytes(.meta)
     -> 从 strippedAOTDllOutputRootDir/<activeBuildTarget> 逐项复制
     -> 创建/更新 HybridCLRConfig.asset 的 TextAsset 引用
```

业务 DLL 编译使用当前 Active Build Target，并额外传入 `UNITY_COMPILE` 与当前模块宏。产物先写到 `Unity/Temp/Bin/Debug/<BuildTarget>`，再复制到模块资源目录和 `Unity/Temp/HybridCLRBin`。后者被注册到 `externalHotUpdateAssembliyDirs`，供 HybridCLR 生成阶段识别外部热更新程序集。

`Build Pkg (Contains Rebuild Resource)` 的真实链为：

```text
BuildToolEditor
  -> SwitchActiveBuildTarget(selected Platform)
  -> BuildHelper.BuildPkg
     -> 清空 Temp/Pkg/<Platform>
     -> BuildResource
        -> RefreshResourceCollectionWithOptimize
        -> ResourceBuildHelper.StartBuild
           -> 从 GameEntry.prefab 解析 ResourceMode
           -> 加载 ResourceBuilder.xml，要求 OutputDirectory=../Temp/Bundle
           -> Package: 输出 Package
              Updatable*: 输出 Full + Packed
           -> BuildEventHandle.OnPreprocessAllPlatforms
              -> 清理 StreamingAssets 中 *.dat/*.meta，刷新 AssetCollection
           -> OnPreprocessPlatform
              -> 热更模式下再次编译并复制该平台业务 DLL
           -> 构建 AssetBundle/版本清单
           -> Updatable 模式生成 Temp/Version/<Platform>Version.txt
           -> OnPostprocessPlatform
              -> Packed 优先，否则 Package，复制到 Assets/StreamingAssets
     -> BuildPipeline.BuildPlayer，仅传入 Assets/Launcher.unity
     -> Temp/Pkg/<Platform>/<productName>[.exe|.apk]
```

因此 Build Resource 会在热更模式刷新业务 DLL，但不会执行 `HybridCLR/Generate/All` 或 `CopyAotDlls`；跨平台、AOT 列表变化、首次构建或稳定层变化时仍需先执行 Do All。`BuildSceneSetting.AllScenes()` 不在 Build Pkg 链路中，业务场景由 UGF 资源系统加载。

运行时链路为：

```text
ProcedureCompleteResources
  -> ProcedurePreload
     -> Tables / Localization / UXTool
     -> [UNITY_HOTFIX && ENABLE_IL2CPP] HybridCLRHelper.LoadAsync
        -> 加载 HybridCLRConfig.asset
        -> 每个 AOT TextAsset 调用 LoadMetadataForAOTAssembly(..., Consistent)
     -> ProcedurePreset
        -> ProcedureET -> CodeRunner.StartRun("ET.Init")
           -> ET.CodeLoader -> 资源加载/Assembly.Load -> ET.Entry.Start
        -> ProcedureGameHot -> CodeRunner.StartRun("Game.Hot.Init")
           -> 资源加载/Assembly.Load Game.Hot.Code -> 实例化 HotEntry.prefab
```

非 Editor Player 的 `CodeRunner.EnableCodeBytesMode` 固定为 `true`。Editor 则取 Launcher 场景中的 `m_EnableEditorCodeBytesMode`；当前为 `0`，默认直接使用 Unity 已加载程序集。ET Editor DLL 模式又固定保留 Unity 的 Model/ModelView，只禁用并动态装载 Hotfix/HotfixView。

## 核心类型与 API

| 类型/API | 职责 | 约束 |
| --- | --- | --- |
| `HybridCLREditor.HybridCLRDoAll()` | 串联 Refresh、模块 DLL 编译、Generate/All 和 AOT 复制 | 使用当前 Active Build Target；不是 Build Pkg 的子步骤 |
| `HybridCLREditor.CopyAotDll()` | 复制 `patchAOTAssemblies` 并更新配置资产 | 缺失源 DLL 时直接 `continue`，不会使菜单失败 |
| `HybridCLRTool.RefreshSettings()` | 同步外部热更目录并从当前 `link.xml` assembly 节点重建 AOT 列表 | `link.xml` 条件注释必须保持完整 |
| `BuildAssemblyHelper.CompileDlls()` | 调用 `PlayerBuildInterface.CompilePlayerScripts` | 平台、DevelopmentBuild 和宏组合都会影响输出 |
| `BuildAssemblyHelper.CopyHotUpdateDlls()` | 复制 DLL/PDB 到资源目录和 HybridCLR 外部目录 | 会先清空目标 Code 目录及整个 `Temp/HybridCLRBin` |
| `ET.Editor.BuildAssemblyTool` | 管理四个 ET DLL 和编辑器 DLL 冲突 | ET Editor 默认只动态装载 Hotfix/HotfixView |
| `Game.Hot.Editor.BuildAssemblyTool` | 管理 `Game.Hot.Code` | 无运行时 reload API |
| `BuildToolEditor` | 平台选择和五个按钮入口 | 仅在非 Play Mode 可用；支持 Windows、Windows64、Android、iOS、macOS、Linux、WebGL |
| `BuildHelper.BuildResource()` | 优化刷新 ResourceCollection 后启动 UGF 构建 | 返回 `void`，资源失败未向上返回状态 |
| `BuildHelper.BuildPkg()` | 清包目录、构建资源、构建 Launcher Player | Player 失败会抛异常；资源日志失败不一定中止 |
| `ResourceBuildHelper.StartBuild()` | 按 ResourceMode 配置 Package 或 Full+Packed 输出 | 强制 `../Temp/Bundle`；控制器校验失败可能只记日志 |
| `BuildEventHandle` | 清理/复制 StreamingAssets、调用带顺序的 UGF 构建回调 | 热更 DLL 编译由模块 `PreprocessCompileDll` 在此触发 |
| `UGFBuildEvent.GenerateLocalUpdatableVersion()` | 写 `Temp/Version/<Platform>Version.txt` | 仅可更新版本清单输出时触发，默认 URI 为 `http://127.0.0.1:8088` |
| `HybridCLRHelper.LoadAsync()` | 在业务模块启动前加载 AOT 补充元数据 | 仅 `UNITY_HOTFIX && ENABLE_IL2CPP` 调用；当前未检查 RuntimeApi 返回码 |

Build Tool 的按钮边界：

| 按钮 | 实际动作 |
| --- | --- |
| Build Pkg | 清理目标 Pkg，重建资源，再构建完整 Player |
| Build Resource | 重建资源；热更模式会在预处理时重编业务 DLL，不构建 Player/AOT |
| Build And Refresh Windows64 Pkg Resource | 要求已有 Windows64 Player；重建资源后替换其 `StreamingAssets`，不重编 Player |
| Open Pkg Folder | 只打开 `Temp/Pkg/<Platform>`，目录不存在则报错 |
| Build Kit.sln | 在仓库根执行 `dotnet build`；与 Unity Player 构建无自动依赖关系 |

## 数据与生命周期

1. `DefineSymbolTool.Refresh()` 把当前宏状态写入 HybridCLR settings、`Assets/link.xml`、资源规则激活状态和 Luban `luban.conf`；这些是后续构建的输入状态。
2. `HybridCLRSettings.asset` 中 `patchAOTAssemblies` 由当前有效 `link.xml` 的所有 `<assembly fullname="...">` 节点重建；它不是手工维护清单。
3. 模块编译产物按 Build Target 落到 `Temp/Bin/Debug/<BuildTarget>`。复制阶段将资源目录和 `Temp/HybridCLRBin` 清空后重建，因此产物代表最后一次编译的平台与模块。
4. `CopyAotDll` 先清理旧 AOT `.dll.bytes`，再从 `HybridCLRData/AssembliesPostIl2CppStrip/<BuildTarget>` 复制存在的文件，并把实际复制成功的 TextAsset 写入 `HybridCLRConfig.asset`。
5. UGF 构建从 `GameEntry.prefab` 读取 ResourceMode。当前 prefab 值为 `1`，即 `Package`；Package 复制 Package 输出到 StreamingAssets，可更新模式复制 Packed 输出并另外生成 Full/版本信息。
6. `Build Pkg` 每次清空 `Temp/Pkg/<Platform>`，不会保留旧安装包。资源输出位于 `Temp/Bundle`，本地版本文件位于 `Temp/Version`。
7. Player 启动完成资源阶段后，才在 `ProcedurePreload` 装载 AOT 元数据；随后 `ProcedurePreset` 启动 ET 或 GameHot。Mono/Editor 不执行 AOT 元数据装载。
8. Editor DLL 模式进入 Play 前把 `Library/ScriptAssemblies` 中动态加载的同名 DLL/PDB 改名为 `.DISABLED`，退出 Play 时恢复；异常退出可能留下中间状态。
9. ET 的 `ReloadAsync()` 只替换 Hotfix/HotfixView 并重建 `CodeTypes` 的 `[Code]` 单例，既有 Entity/Fiber 和 Model 类型不会迁移。GameHot 没有这条生命周期。

## 开发扩展步骤

新增或调整热更新程序集时：

1. 先决定代码属于稳定 Loader/AOT 层还是热更新 Code 层；跨越程序集边界的类型签名必须在目标平台 IL2CPP 下可用。
2. 在对应模块 `BuildAssemblyTool.DllNames` 中维护编译复制清单；ET 若支持运行时重载，还需判断是否加入 `HotfixDllNames`。
3. 通过 `DefineSymbolTool` 调用 `HybridCLRTool.AddHotfixAssemblyDefinition/RemoveHotfixAssemblyDefinition` 同步 asmdef，不要只编辑 `HybridCLRSettings.asset`。
4. 更新 ET/GameHot ResourceRule，确保 `.dll.bytes/.pdb.bytes` 和 `HybridCLRConfig.asset` 的依赖进入 ResourceCollection。
5. 若新增 AOT 依赖，修改 `Assets/link.xml` 对应条件区块，保持 `<!--SYMBOL_START-->` / `<!--SYMBOL_END-->` 标记，然后 Refresh。
6. 切到每个发布目标平台执行 Do All，核对 DLL 数量、配置引用和 ResourceCollection，再执行 Build Resource/Build Pkg。
7. 同时验证 Editor 普通程序集模式、Editor CodeBytes 模式和目标 IL2CPP Player；三者加载路径不同，任一成功都不能替代另两者。

本地可更新资源验证步骤：

1. 将 `GameEntry.prefab` ResourceMode 设为 `Updatable` 或 `UpdatableWhilePlaying`。
2. Build Pkg 生成基础 Player，再修改资源或热更新代码。
3. 业务 DLL 变化可执行 Build Resource；AOT/平台/稳定层变化必须先 Do All。
4. 点击 `Game/Tool/StartFileServer`，它从 `Bin` 运行 `FileServer.dll`，按 `Temp/Bundle/Full`、`Temp/Version` 等目录提供 8088 端口。
5. 运行旧 Player，核对版本文件、下载日志和新业务行为。该文件服务器监听所有网卡且无鉴权，只适合可信开发网络。

## 约束与常见错误

- **平台产物不能混用**：业务脚本编译和 stripped AOT DLL 都绑定 Build Target。先切平台，后 Do All；窗口自动切平台不等于 AOT 已重建。
- **Build Pkg 不是完整热更准备**：它会通过资源预处理重编业务 DLL，但不会 Generate/All 或 CopyAotDlls。首次构建、跨平台、AOT 依赖或稳定程序集变化仍需 Do All。
- **AOT 目标目录不会自动创建**：`CopyAotDll()` 未调用 `Directory.CreateDirectory("Assets/Res/HybridCLR")`，`FileTool.CleanDirectoryFiles()` 遇到缺失目录只会返回。当前检出只有 `HybridCLR.meta`、没有对应目录；执行 Do All 前需在 Unity 中建立该目录，否则首次 `File.Copy` 或 `AssetDatabase.CreateAsset` 可能失败。
- **AOT 缺失可能静默通过**：`CopyAotDll()` 对不存在的源文件直接跳过，最终配置只引用复制成功项。必须比较 `patchAOTAssemblies`、源目录、目标目录和配置引用数量。
- **AOT 运行结果未检查**：`HybridCLRHelper` 忽略 `LoadMetadataForAOTAssembly` 返回值；`HybridCLR load metadata` 日志只表示循环执行完，不证明每个程序集装载成功。
- **资源失败可能仍显示成功**：`ResourceBuildHelper` 对控制器校验/`BuildResources()` 失败主要写日志，`BuildHelper.BuildResource()` 返回 `void`，Build Tool 随后无条件打印 Success。应检查最早错误和 `BuildLog.txt`，并验证时间戳/文件内容。
- **平台切换结果未检查**：`BuildToolEditor.SwitchActiveBuildTarget()` 忽略 Unity API 的布尔返回值，确认对话框后总返回 `true`。平台模块缺失或切换失败时，不能相信按钮流程继续执行即代表平台正确。
- **只构建 Launcher 场景**：Build Pkg 明确只传 `Assets/Launcher.unity`。`BuildSceneSetting.AllScenes()` 没有被调用，业务 Scene 必须由 ResourceRule 收集并在运行时从 UGF 资源加载。
- **手工宏会破坏联动**：直接改 `UNITY_ET`、`UNITY_GAMEHOT`、`UNITY_HOTFIX` 可能让资源规则、Luban、`link.xml` 和 HybridCLR asmdef 不一致。两个业务宏若被手工同时启用，两次模块复制还会互相清空 `Temp/HybridCLRBin`。
- **目标目录采用清空重建**：模块 Code 目录、`Temp/HybridCLRBin`、AOT `.dll.bytes` 和目标 Pkg 都会被清理。失败后不能把残缺目录当成上一版可回退产物。
- **ResourceBuilder 输出路径是契约**：`ResourceBuilder.xml` 的 OutputDirectory 必须为 `../Temp/Bundle`；ResourceMode 不能是 `Unspecified`。
- **刷新已有 Windows64 包只换资源**：代码属于 Player 稳定程序集、Launcher 场景或 PlayerSettings 变化时，必须重新 Build Pkg。
- **编辑器 DLL 冲突**：CodeBytes 模式会移动 `Library/ScriptAssemblies` 文件。Unity 异常退出后先检查 `.DISABLED`，不要在 Play 状态切换期间手工改名。
- **ET Reload 不是完整重启**：Model/ModelView、已有对象和静态状态不会自动迁移；GameHot 只有重新编译，没有在线装载新程序集的按钮。
- **Package 与 Updatable 行为不同**：只有可更新模式输出版本清单并生成 `Temp/Version/<Platform>Version.txt`；当前 GameEntry 默认是 Package。

## 验证方法

普通静态检查在仓库根执行：

```powershell
rg -n "HybridCLRDoAll|CopyAotDll|patchAOTAssemblies|externalHotUpdate" `
  Unity/Assets/Scripts/Game/Editor/HybridCLR Unity/ProjectSettings/HybridCLRSettings.asset
rg -n "DllNames|PreprocessCompileDll|CompilePlayerScripts|CopyHotUpdateDlls" `
  Unity/Assets/Scripts/Game/Editor/Build Unity/Assets/Scripts/Game/ET/Editor/Build `
  Unity/Assets/Scripts/Game/Hot/Loader/Editor/Build
rg -n "BuildPkg|BuildResource|BuildPlayer|LauncherScenePath|StartBuild" `
  Unity/Assets/Scripts/Game/Editor/Build `
  Unity/Assets/Scripts/Library/UGF/UnityGameFramework.Extension/Editor
powershell -ExecutionPolicy Bypass -File .\KnowledgeBase\Test-KnowledgeBase.ps1
```

Unity 目标平台核验：

1. 确认 Build Target、业务宏、ET CodeMode、Development Build 和 Scripting Backend。
2. 执行 `Game/Define Symbol/Refresh`，检查 `HybridCLRSettings.asset` 的 asmdef、外部目录和 AOT 列表与 `link.xml` 一致。
3. 先确认 `Assets/Res/HybridCLR` 目录真实存在，再执行 `HybridCLR/Do All`；逐项检查 `Temp/Bin/Debug/<Target>`、模块 Code 目录、`Temp/HybridCLRBin`、stripped AOT 目录、AOT 资源目录和 `HybridCLRConfig.asset`。
4. 执行 Build Resource，打开 ResourceCollection 确认模块 Code 与 HybridCLR 资源被收集；检查 ResourceBuilder `BuildLog.txt` 无错误。
5. 执行 Build Pkg，确认 `Temp/Pkg/<Platform>`、StreamingAssets、仅 Launcher 的 Player 构建报告和启动日志。
6. 在目标 IL2CPP Player 中确认 AOT 元数据日志先于 ET/GameHot 入口，并实际触发一条依赖补充元数据的热更新代码路径。
7. 对 ET 再验证 `ETReload` 只更新 Hotfix 行为；对 GameHot 重启 Player 验证新 DLL，因为没有在线重载入口。

验证边界：本轮完成源码、配置、Book 文档及静态调用链核验，并运行普通知识库校验；未驱动 Unity 6000.3.18f1 执行 Do All、ResourceBuilder、IL2CPP Player 构建或运行时热更新。当前干净构建产物目录并不完整，平台产物完整性和运行时结果仍需在安装对应 Unity 平台模块的环境中验证。
