# 模块 22：共享工具链

> Catalog ID: `TOOLS-01`、`TOOLS-02`、`TOOLS-03`、`TOOLS-04`  
> 状态：`verified`  
> 最后核验：`2026-08-04`  
> 适用模式：Shared / Editor / Server Ops

## 模块定位

本模块覆盖四组开发与运维工具：`Share.Tool` 的 Luban、Proto 和本地化导出，编译期的 `Share.Analyzer` 与 `Share.SourceGenerator`，用于本地资源更新测试的 `Share.FileServer`，以及 `Tools/Shell`、`Tools/Luban`、`Tools/RecastNavExportor`、`Tools/Config` 中的外部程序和脚本。

这些工具不属于游戏运行时业务。它们分别修改生成代码/配置、参与 C# 编译、暴露本地文件或批量复制/删除仓库内容；运行前必须先确认工作目录、输入配置和输出边界。`Share/Aspire` 由服务端模块负责；`Tools/cwRsync` 与 `Share/Libs` 作为 `TOOLS-04` 的分发物和原生源码边界记录。

## 依赖关系

```text
Design/Excel/*/luban.conf + Excel + Localization.xlsx
  -> Bin/Tool --AppType=ExcelExporter
  -> Tools/Luban/Tools/Luban/Luban.dll + CustomTemplates
  -> Unity generated code/resources + Config/Luban

Design/Proto/*/proto.conf + *.proto
  -> Bin/Tool --AppType=Proto2CS
  -> ET/UGF C# generators
  -> Unity and DotNet generated message code

DotNet Core/Loader/Model/Hotfix build
  -> ProjectReference(OutputItemType=Analyzer)
  -> Share.Analyzer + Share.SourceGenerator
  -> diagnostics + in-memory generated sources

Unity compilation
  -> Assets/Plugins/Share.*.dll (RoslynAnalyzer)
  -> diagnostics + in-memory generated sources

Bin/FileServer.dll
  -> ASP.NET Core/Kestrel
  -> Temp/Bundle/Full, Temp/Version, Temp/Pkg/WebGL, Bundle, Version
  -> HTTP :8088
```

外部依赖如下：

- `Share.Tool` 需要 .NET 8、Luban 发行 DLL、`CommandLineParser`（由 `DotNet.Core` 间接提供）、ExcelDataReader、Newtonsoft.Json，以及可读的 Design 输入。Windows 子命令经 `cmd.exe /c`，其他平台经 `bash -c`。
- Analyzer/SourceGenerator 以 `netstandard2.0` 构建，分别依赖 Microsoft.CodeAnalysis Workspaces 4.0.1 和 CSharp 3.9.0；既要通过 .NET 编译器，也要与 Unity 当前 Roslyn 版本兼容。
- FileServer 依赖 .NET 8 ASP.NET Core shared framework；不依赖 MongoDB 或 Unity Editor。
- `RecastDemo.exe` 是 Windows GUI，仓库同目录提供 `SDL2.dll` 和字体；README 指出缺少运行库时需安装 Visual C++ 工具/运行环境。`Share/Libs/RecastDll` 的跨平台原生库构建是另一条链，需要外部 `recastnavigation` 源码、CMake 和目标平台工具链。
- `Share/Libs/Kcp/ikcp.c/.h` 是独立 C 参考源码。全仓未发现 csproj、CMake 或脚本消费它；ET 运行时使用 `Library/ET/ThirdParty/Runtime/Kcp` 中的 C# unsafe 移植，不能把二者视为同一构建产物。
- `Tools/cwRsync` 是旧版 Windows/Cygwin 二进制分发。`Config` 同时给出 Linux rsync daemon 与 client 示例；仓库源码未发现读取 `rsyncConfig.txt` 或启动 `cwrsync.cmd` 的入口。
- `Tools/Config/Egametang.ffs_*` 需要 FreeFileSync；其余设置文件分别需要对应 IDE/编辑器。`start aspire.bat` 还依赖 Aspire workload，并硬编码了 `D:\AppData\.nuget\packages`。
- cwRsync 模板需要目标 Linux 主机的 rsync daemon、正确文件权限和网络访问控制；仓库示例凭据不能用于共享或生产环境。

## 入口与调用链

所有 `Tool` 命令必须从 `Bin` 执行，因为 `Define.WorkDir` 固定为 `../Bin`，输入输出又通过 `../Design`、`../Unity`、`../Config` 展开。源码还会拒绝完整工作目录包含空格。

| 功能 | 命令/入口 | 主要输入 | 主要输出 |
| --- | --- | --- | --- |
| 构建共享工具 | 仓库根执行 `dotnet build .\Kit.sln`；bat 方式需在 `Tools/Shell` 目录运行 `build kit sln.bat` | 根解决方案、NuGet 包 | `Bin/Tool.*`、`Bin/FileServer.*` 及各项目编译输出 |
| Luban 二进制导出 | 在 `Design/Excel` 目录运行 `gen all bin.bat`；或在 `Bin` 中运行 `Tool.exe --AppType=ExcelExporter --Console=1` | active 的 `Design/Excel/*/luban.conf`、Excel、Localization | `cs-bin`/`bin` 代码和数据、本地化 `.bytes`、UGF ID 代码 |
| Luban JSON 导出 | 在 `Design/Excel` 目录运行 `gen all json.bat`；或在 `Bin` 中增加 `--Customs=Json` | 同上 | 把 `cs-bin`/`bin` 替换为 `cs-simple-json`/`json`，本地化改为 `.json` 并删除另一格式 |
| Luban 只检查 | 在 `Design/Excel` 目录运行 `check all.bat`；或在 `Bin` 使用 `--Customs=Check,ShowCmd` | 所有 active Luban 配置和表 | 去掉输出参数并给 Luban 加 `-f`；本地化直接跳过，预期不刷新生成物 |
| 仅本地化 | `Tool.exe --AppType=LocalizationExporter --Console=1`；Unity UXTool“转换文本表格”菜单 | `Design/Excel/Localization.xlsx` | 本地化资源及公共辅助代码；不会先运行 Luban |
| Proto | 在 `Design/Proto` 目录运行 `proto2cs.bat`；Unity `Game/Tool/Proto2CS`；或在 `Bin` 运行 `Tool.exe --AppType=Proto2CS --Console=1` | active 的直接子目录 `proto.conf` 与递归 `.proto` | ET 每组 `<codeName>.cs`/`<codeName>_Id.cs`；UGF 还生成 PacketHandler/Id 文件 |

`ExcelExporter` 的内部顺序是 Luban 并行导出、清理空目录、复制逗号分隔的次级输出、生成 Sound/Entity/UIForm/Scene ID，最后导出 Localization。路径变量仅支持 `%CONF_ROOT%`、`%UNITY_ASSETS%`、`%ROOT%`；当前 `Design/Excel/ET/luban.conf` 为 active，`GameHot/luban.conf` 为 inactive。ET 的 ClientServer 数据先写 `Unity/Assets/Res/ET/ClientServer/Luban`，再复制到 `Config/Luban`。

`Proto2CS.Export` 只扫描 `Design/Proto` 的直接子目录读取 `proto.conf`，再递归读取该组 `.proto` 并按序排序。当前四组均 active：ET-Client 输出到 Client 与 ClientServer，ET-ClientServer 输出到 ClientServer，ET-Admin 输出到 `DotNet/Model/Generate/Message`，GameHot 输出到 Hot 代码。末尾只清理由已声明输出目录中的孤立 `.meta` 和不含 `.cs` 的对应空目录，不会先清空全部旧 `.cs`。

`Tools/Shell` 的入口分为四类：

| 类别 | 脚本 | 行为边界 |
| --- | --- | --- |
| 构建 | `build kit sln.bat` | 切到仓库根执行无参数 `dotnet build` |
| 启动 | `start et server.bat`、`start admin.bat`、`start agent.bat`、`start aspire.bat`、`start file server.bat` | 启动 `Bin` 中服务或 Aspire；Admin/Aspire 还打开浏览器 |
| Demo/插件清理 | `clear demo.bat`、`clear demo keep ET.bat`、`clear demo keep GameHot.bat`、`delete no free unity plugins.bat` | 复制少量 Demo 代码后递归删除资源、ET/GameHot 模块、Design 输入或付费插件，操作不可自动回滚 |

## 核心类型与 API

| 类型/API | 职责 | 生命周期/线程约束 |
| --- | --- | --- |
| `ET.Server.Init.Main` | 注册 Options/日志/EventSystem，校验工作目录并分派三个工具 AppType | 单次进程；成功分支返回 0，异常返回 1 |
| `ExcelExporter.ExportAll` | 先 `ExcelExporter_Luban.DoExport`，后 `ExcelExporter_Localization.DoExport` | 单次导出；Luban 子任务用 `Parallel.ForEachAsync` 并行 |
| `ExcelExporter_Luban.GenConfig` | 读取每个一级 Excel 目录的 `active`、`customTemplate`、`cmds` | 每次运行重新发现，不读取 `Tools/Config` |

| `ETReactiveSystemGenerator` | 处理 Reactive host/source/bind，生成宿主和 System 代码 | 编译期；自身还报告 `ET1101`～`ET1114` 契约诊断 |
| `FileServer.Program`/`Config` | 在端口 8088 监听任意网卡并声明五个候选物理目录 | 进程启动时构造一次；端口和目录未暴露为命令行配置 |
| `FileServer.Startup` | 为每个存在目录注册目录浏览和 StaticFiles | 至少一个目录存在，否则启动抛 `File directory is empty` |

## 数据与生命周期

1. `Tool` 启动后把 Options、Logger、CodeTypes 和 EventSystem 放入 ET `World`，完成一个分支后进程退出；它没有增量数据库，文件系统就是输入和状态边界。
2. Luban 命令先拼接 `Luban.dll --customTemplateDir ... --conf ...`。同一配置可用逗号声明多个输出目录：Luban 只写第一个，`LubanFileHelper` 再清空并复制到其他目录。
3. Localization 以工作簿首行 `##`/`key`/`Language` 名称识别表和列，按语言与 Key 排序；它会在 `.bytes` 与 `.json` 间互斥删除。`ExcelExporter` 运行过 Luban 目录扫描后会生成 ET/GameHot `LocalizationKey.cs`，单独运行 `LocalizationExporter` 时进程内的模式标志保持默认值，不生成这两份模式专用 Key 文件。
4. Analyzer 与 SourceGenerator 随每次 Compilation 创建/执行，不持有游戏运行时状态。`.g.cs` 是编译输入，不等同于 `Unity/Assets/**/Generate` 下由 Tool 写出的持久文件。
5. .NET 项目通过 `ProjectReference OutputItemType="Analyzer" ReferenceOutputAssembly="false"` 加载 Roslyn 项目；Unity 加载仓库中已提交的两个插件 DLL，其中 `Share.SourceGenerator.dll.meta` 要求 `UNITY_ET`，Analyzer 没有该约束。两个 csproj 的 PostBuild 复制块均已注释，源项目构建不会刷新 Unity 插件。
6. FileServer 只读取启动时存在的目录列表，但静态文件内容由 PhysicalFileProvider 在请求时读取。注册的多个根共享 URL 空间，重名相对路径由中间件注册顺序决定；进程停止即结束服务，不产生缓存清单。
7. Recast GUI 的输入、参数和导出由交互会话持有。仓库内 Unity 菜单 `ET/NavMesh/ExportSceneObj` 可从已 Bake 的 Unity NavMesh 生成 OBJ，但其硬编码目录是 Unity 工程相邻的 `../RecastNavMesh/Meshes` 与 `../Config/RecastNavData/ExportedObj`，不是 `Tools/RecastNavExportor/Meshes`，二者目前需要人工衔接。
8. `Share/Libs` 不进入 `Kit.sln`：RecastDll 必须复制进外部 recastnavigation checkout 后用目标平台脚本构建；KCP C 文件当前仅随仓库存档，不参与客户端或服务端编译。

## 开发扩展步骤

新增或修改 Share.Tool 导出能力：

1. 在 Design 的 `luban.conf`/`proto.conf` 声明输入、active 状态与唯一输出目录；优先复用三个路径变量，不在 C# 中新增机器绝对路径。
2. 若新增 `AppType`，同步 `Options.AppType`、`Init.Main` 分派、Unity `EditorTool` 和需要的 bat；保持从 `Bin` 执行。
3. 生成文件必须带自动生成标记并做到内容不变时不重写；复制/清理前将目录限制在已解析的配置输出内。
4. 先执行 Luban `Check,ShowCmd`，再执行实际导出；导出前后用 Git 状态确认只变化预期生成目录。

新增 Analyzer/SourceGenerator 能力：

1. 在相应 `DiagnosticIds` 分配不冲突 ID，声明 DiagnosticDescriptor，并用最小测试源码覆盖命中与不命中场景。
2. 按 `AnalyzeAssembly`/`CustomAnalyzeAssembly` 限制程序集；生成器用稳定且唯一的 hint name 调用 `AddSource`，不得写 `Unity/Assets`。
3. 构建 `Kit.sln` 验证 DotNet 引用；再显式将新 `Share.Analyzer.dll`/`Share.SourceGenerator.dll` 更新到 `Unity/Assets/Plugins` 并保留 `RoslynAnalyzer` label，触发 Unity 重导入验证。

扩展外部工具：

1. FileServer 新增根目录或端口时优先改为显式配置并限制监听地址；为不存在目录、重名文件和实际下载增加测试。
2. Luban 模板改动放 `Tools/Luban/CustomTemplates/<name>`，由 `luban.conf.customTemplate` 选择；升级发行物时同步 DLL、deps/runtimeconfig、模板并完整回归所有 active 命令。
3. 新增 Shell 脚本时先用 `%~dp0` 固定脚本目录、引用所有路径、检查目标绝对路径并让失败传播为非零退出码；删除/同步脚本必须提供预览或备份步骤。
4. Recast 先由 Unity 或 DCC 导出 OBJ，再在 GUI 烘焙，最后把 nav 数据放入消费方明确约定的位置；不要把仓库示例 `solo_navmesh.bin` 当作任意场景输出。

## 约束与常见错误

- `Share.Tool` 的相对路径契约是“当前目录为 `Bin`”，不是“可执行文件位于 Bin 即可”；从仓库根直接运行 `Bin/Tool.exe` 会把 `../Design` 等解析到错误位置。
- `ExcelExporter_Luban.RunCommand` 不检查子进程 `ExitCode`，只根据 stderr 或 stdout 中的 `|ERROR|` 标记失败；汇总失败仅写 Warning，`DoExport` 不抛异常，`Init.Main` 仍返回 0。CI 不能只看 `Tool` 退出码，必须检查日志中的 `fail`/`|ERROR|` 和产物。
- `--Customs=Check` 会跳过 Localization，也不会执行 ID 代码生成；它只能证明 active Luban 命令通过校验，不能证明全部生成物已刷新。
- `Json`、`Check`、`ShowCmd`、`ShowInfo` 通过不区分大小写的 `string.Contains` 判断，不是结构化 flag 集合；自定义字符串意外包含关键字也会开启行为。
- Luban 的复制目标在复制前会删除已有普通文件，但保留 `.meta`、隐藏/下划线/波浪号路径；输出配置错误可能清空不相关目录。GameHot Luban 当前 inactive，但 Proto 的 GameHot 组仍 active，两者开关互不关联。
- Proto 是项目自定义行解析器，不是完整 protoc；Opcode 受已排序文件和声明顺序影响。旧 `.cs` 不会在导出前统一删除，改名/删除消息后需检查残留，跨 `proto.conf` 的 Opcode 区间也不会自动判重。
- Roslyn 源码和 Unity 插件 DLL 是两份交付物；只改 `Share/Analyzer`/`Share/SourceGenerator` 并构建，可能出现 DotNet 已生效而 Unity 仍运行旧 DLL 的分叉。
- FileServer `ListenAnyIP(8088)`、开启目录浏览、允许未知文件类型且无认证；只能用于可信开发网络。五个根目录相对 `Bin` 解析，全部不存在时启动失败。
- `Tools/Luban/Tools/build-luban.*` 会先删除整个 `Tools/Luban/Tools/Luban`，再从 `../Luban-Extension/src/Luban/Luban.csproj` 构建；当前仓库没有该源码目录，必须先准备匹配版本的外部 checkout，且失败后可能留下空发行目录。
- Recast README 只描述 GUI 流程，没有规定业务消费目录、文件格式版本或自动化命令；导出结果必须由消费方加载测试确认，不能仅凭 GUI 显示成功。
- 不要直接修改 `Share/Libs/Kcp` 并期待 ET 网络行为变化；当前 ET KCP 实现来自 `Library/ET/ThirdParty/Runtime/Kcp`。若要恢复原生 KCP 构建，必须先新增明确的项目/脚本、P/Invoke 契约和跨平台验证。
- `Tools/cwRsync/Config` 包含明文示例账号/口令，daemon 配置为 `uid=0`、`gid=0`、`read only=no`、`list=yes`。它只能作为开发模板；部署前必须轮换凭据、关闭目录枚举、使用最小权限并限制监听地址/防火墙。不要把真实 secrets 提交回仓库。
- 多数清理/同步 bat 没有先 `cd /d %~dp0`，其 `..\..`/`..\..\..` 取决于调用者当前目录；双击与从其他目录 `cmd /c` 运行可能命中不同目标。脚本也不检查错误码，并直接使用 `rd /s /q`。
- ET/GDK 同步脚本硬编码相邻目录名并采用“先删目标、后复制”；`delete no free unity plugins.bat` 会删除 Sirenix/Odin 等付费插件。执行前必须人工解析并核对 SOURCE/DESTINATION 的绝对路径，不能在有未提交修改时运行。
- `Tools/Config` 是可选偏好模板集合，不会控制上述工具。把它当作导出配置修改不会产生效果；其中 `.gitconfig` 等全局配置也不应未经审查直接覆盖本机设置。

## 验证方法

静态核验：

```powershell
rg -n "AppType|Customs|WorkDir|GEN_CLIENT|output(Code|Data)Dir" Share/Tool Design/Excel Design/Proto
rg -n 'OutputItemType="Analyzer"|ReferenceOutputAssembly|AddSource|DiagnosticAnalyzer' `
  DotNet Share/Analyzer Share/SourceGenerator
rg -n "ListenAnyIP|DirectoryPaths|UseDirectoryBrowser|UseStaticFiles" Share/FileServer
rg -n "^(set |cd |dotnet |rd|del |xcopy|copy )" Tools/Shell -g "*.bat"
```

构建与生成核验（需要 .NET 8 SDK；当前环境没有可用的 `dotnet` 命令，未执行）：

```powershell
dotnet build .\Kit.sln
Push-Location .\Bin
.\Tool.exe --AppType=ExcelExporter --Console=1 --Customs=Check,ShowCmd
.\Tool.exe --AppType=Proto2CS --Console=1
Pop-Location
git status --short -- Unity/Assets Config DotNet/Model/Generate
```

实际 Luban/Localization 导出应在干净分支分别运行 bin 与 json 模式，检查日志无 `|ERROR|`/`fail`，并确认只有本节“源码边界”列出的生成目录变化。Analyzer/SourceGenerator 修改需同时构建 DotNet 和打开 Unity 触发脚本重编译，确认预期 ET 诊断、CodeFix 和生成类型均出现，并核对 Plugins DLL 已刷新。

FileServer 运行验证：先确保五个候选目录至少一个含测试文件，从 `Bin` 启动 `dotnet FileServer.dll`，再对 `http://localhost:8088/<相对文件>` 执行 `Invoke-WebRequest`，比较长度/哈希并从另一台可信网络主机验证是否确实可达；完成后终止进程。Recast 需用已知 OBJ 烘焙、确认生成文件可被实际导航加载器读取，并记录参数和目标路径。破坏性 Shell 不做试运行；通过临时克隆、路径快照和 `git status` 验证。

普通知识库校验命令：

```powershell
powershell -ExecutionPolicy Bypass -File KnowledgeBase/Test-KnowledgeBase.ps1
```
