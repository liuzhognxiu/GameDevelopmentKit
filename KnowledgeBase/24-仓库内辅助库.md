## 模块定位

本页覆盖 `Unity/Assets/Scripts/Library` 下六组随仓库维护的辅助库。它们不是同一套框架：UniTask 和 StateController 目录是第三方包之上的项目适配，LubanLib 是生成代码的运行时契约，SocoTool 是 Shader 变体构建工具，UXTool 同时包含运行时 UI 组件和大型编辑器工具集，FolderTag 与 ReplaceComponent 则只在编辑器中产生主要行为。

| Catalog ID | 库 | 真实职责 | 不负责 |
| --- | --- | --- | --- |
| `LIB-04` | UniTask Extension | 可复用完成源、取消注册桥接、引用计数式 `CancellationTokenSource` | UniTask 调度器本体、Unity PlayerLoop 安装 |
| `LIB-04` | StateController Extension | 为 StateController 增加按钮可交互、锚点和 UXText 本地化值绑定 | 状态机核心和 Inspector；核心来自 UPM 的 `me.xw.statecontroller` |

| `LIB-06` | SocoTool | Shader 变体剔除、收集、筛选、合并、拆分和批处理 | Shader 编译、运行时预热调度、项目资源清单生产 |

## 入口与调用链

### LIB-04：UniTask 与 StateController

1. 调用方通过 `AutoResetUniTaskCompletionSourcePlus.Create()` 取得池化完成源，读取 `Task` 后等待。
2. `AttachCancellation` 给 token 注册回调；完成、取消或异常都会释放 `CancellationTokenRegistration`。
3. 调用方执行 `TrySetResult`、`TrySetCanceled` 或 `TrySetException`；真正归还池发生在等待方 `GetResult` 的 `finally` 中。
4. `CancellationTokenSourcePlus.MallocToken()` 增加引用计数，调用方必须与 `FreeToken()` 配对；宿主销毁时 `Cancel()` 取消仍在占用同一 token 的操作。
5. StateController 核心在状态变化时调用 `StateValueBinding<T>.ApplyValue`；本扩展分别设置 `Button.interactable`、`RectTransform.anchorMin/anchorMax` 或 UXText 的本地化字段。

项目的 `GameCodeBindCustomizer` 已经无条件为绑定到 `StateController` 的节点生成 `StateGroup` 属性及状态名/索引常量。仓库说明中提到的 `STATE_CONTROLLER_CODE_BIND` 宏在当前源码中不存在，不能再作为启用前提。

ET UGF 桥接是 UniTask 扩展的真实消费者：`UGFUIForm.OpenUIFormAsync` 与 `UGFEntity.ShowEntityAsync/ShowUIEntityAsync` 从对象池取 `CancellationTokenSourcePlus`，用 `MallocToken()` 传给 UGF Awaitable API，并在成功 await 后 `FreeToken()`；`Dispose` 分支会 `Cancel()` 并回收 CTS。当前实现的 `FreeToken()` 不在 `finally` 中，异常或取消路径需单独验证，不能只凭目录存在认定资源/引用计数闭环。

### LIB-05：LubanLib

Game 普通流程由 `ProcedurePreload` 调 `GameEntry.Tables.LoadAllAsync()`，`GameEntry.Game.cs` 证明 `TablesComponent` 来自 UGF Component 缓存；GameHot 流程由 `HotEntry.Tables` 和 `Game.Hot.ProcedurePreload` 调用同名 `LoadAllAsync()`。两者最终反射生成的 `TablesComponent.LoadAsync(loader)`，loader 返回 `UniTask<ByteBuf>` 或 `UniTask<JSONNode>` 后并行加载 `DT*`。

```text
Game/GameHot TablesComponent.LoadAllAsync
  -> 生成的 TablesComponent.LoadAsync(loader)
  -> loader(tableName) 返回 UniTask<ByteBuf> 或 UniTask<JSONNode>
  -> 各生成 DT*.LoadAsync 并行反序列化
  -> UniTask.WhenAll
  -> PostInit / ResolveRef / PostResolveRef
```

ET 的生成物不是 `TablesComponent.cs`，而是 `Unity/Assets/Scripts/Game/ET/Code/Model/Generate/**/Luban/Tables.cs` 中的 `ET.Tables`。`ConfigLoader` 在 `ConfigComponent.LoadAll` 处理器中 `World.Instance.AddSingleton<Tables>()`，再用 `ConfigComponent.Instance.ReadBytesAsync/ReadTextAsync` 提供 loader，并调用 `ET.Tables.LoadAsync`；ReloadOne/ReloadAll 通过 `IDataTable.LoadAsync()` 与 `Refresh()` 重建引用。

Editor 生成 Bean 则继承 `EditorBeanBase`，通过 SimpleJSON 实现 `LoadJson`/`SaveJson`；`LoadJsonFile` 和 `SaveJsonFile` 直接读写 UTF-8 文件。

### LIB-06：SocoTool

剔除链为 Unity Shader 编译 -> `ShaderVariantsStripperCode.OnProcessShader` -> 每次扫描 Assets/Packages 下所有 `ShaderVariantsStripperConfig` -> 合并全局和 Shader 局部条件、按条件相等性与优先级决策 -> 从 `IList<ShaderCompilerData>` 删除变体。若一个 Pass 被删空，代码会把最初的第一个变体加回。

收集链从 `Tools/Soco/ShaderVariantCollectionTools/OpenWindow` 打开，选择 `.shadervariants` 与 Tool Config 后，经 `IMaterialCollector` -> `IMaterialFilter` -> 材质转变体 -> `IVariantFilter`，最后写回集合；`IExecutable` 可继续批处理。窗口 `Awake` 会 `CreateIfDefaultConfigIsNull()`，首次打开若脚本目录没有 `ShaderVariantCollectionToolConfig` 会创建默认 Tool Config，`OnDisable` 会保存配置；内置功能还可浏览、手工增删、合并、取交集和拆分集合。

### LIB-07：UXTool

项目在 `ProcedurePreload` 加载表和 UGF 本地化后调用 `UXTool.InitAsync()`；它先通过 `ResourceManager.InitAsync` 加载 `UXToolAssetCollection.asset`，再取得 UGF `LocalizationComponent` 并同步语言。该 asset 内有 Odin 序列化的 `m_AssetDict` 和 `m_CollectionPathGUIDs`，证明 GUI、BeginnerGuide、颜色配置等固定路径资源被收进集合；真正运行时接入仍以 `ProcedurePreload` 调用链为准。`UXImage`、`UXText`、`UXTextMeshPro` 随后通过 `LocalizationHelper` 刷新图片或文字。流程销毁时 `UXTool.Clear()` 卸载集合并清空组件引用。

编辑器主入口是 `ThunderFireUXTool/` 菜单，覆盖组件库、层级管理、颜色配置、本地化、新手引导、Scene 工具栏、背景图、自动拼接、最近文件、资源检查和脚本检查。`UXInitialize` 会在脚本重载时按 `[UXInitialize(order)]` 运行标注类型的静态构造函数。

### LIB-08：FolderTag 与 ReplaceComponent

FolderTag 在域加载时读取 `ProjectSettings/FolderTag_Prefs.json`（或用户配置路径）和所有 `Resources/FolderTag_Prefs`，再注册 `projectWindowItemOnGUI`。用户在文件夹/Scene Inspector 或 `Preferences/Folder Tag` 修改数据后，整份 JSON 被重写。

ReplaceComponent 在域加载时订阅 `ObjectFactory.componentWasAdded`。第一次新增组件后，它通过 `TypeCache` 收集类上的 `[ReplaceComponent]` 和静态字段上的 `[ReplaceComponentTypeConfig]` 映射；延迟一帧销毁刚加入的原组件，再调用 `AddComponent` 创建替代类型。项目侧 `ExButton` 同时标注 `[ReplaceComponent(typeof(Button))]` 与 `[BindingTargetToken("ExButton")]`，所以它既是新增 `Button` 的 Editor 替换目标，也是 CodeBind 识别的按钮类型；这不表示已有 Button 会自动迁移。

## 开发扩展步骤

### 新增 UniTask/StateController 能力

1. UniTask 完成源调用 `Create()`，先挂取消回调，再把 `Task` 暴露给唯一等待方；所有结束分支使用 `TrySet*`。
2. 使用 `CancellationTokenSourcePlus` 时把 `FreeToken()` 放进 `finally`，宿主销毁时调用 `Cancel()`。
3. 新 State Binding 继承 `StateValueBinding<T>`，用 `RequireComponent` 固定目标，在 `InitializeTarget` 缓存组件并在 `ApplyValue` 只写目标属性。
4. 若 Binding 引入 Editor 类型，把 Editor 代码和程序集引用隔离，随后同时验证 Editor 和 Player 编译。

### 新增 Luban 生成契约

1. 优先修改 Luban 模板/扩展和配置源，不手改生成的 `DT*`、`DR*`、`Tables*`。
2. 新二进制类型必须成对实现 `ByteBuf.Write*`/`Read*`，并对空值、长度上限和 ReaderIndex 越界做一致处理。
3. Editor 可编辑 Bean 继承 `EditorBeanBase`，生成 `LoadJson`/`SaveJson` 后通过实际 JSON 往返验证。

### 扩展 SocoTool

1. 新剔除条件实现 `ShaderVariantsStripperCondition` 的判断、相等性和 Editor UI；保持可无参构造，供反射创建。
2. 新收集步骤继承 `IMaterialCollector`、`IMaterialFilter`、`IVariantFilter` 或 `IExecutable`，创建为资产并加入 Tool Config。
3. 先在临时 Config/ShaderVariantCollection 上测试，再执行真实收集或 Player/AssetBundle 构建。

### 扩展 UXTool

1. 运行时组件放 Runtime，菜单、Importer、Inspector、修复和资产生成放对应 Editor 程序集。
2. 需要 UX 资源/本地化的入口必须位于 `UXTool.InitAsync()` 之后，并在流程关闭时对称清理静态注册。
3. 新工具配置统一走 `ThunderFireUIToolConfig` 路径和 `Create` 方法；明确它是个人设置还是应提交的项目资产。
4. 会改 prefab、labels、图片或外部文件的操作应补 Undo/确认框、范围预览和失败恢复。

### 扩展 FolderTag/ReplaceComponent

1. FolderTag 新字段同时更新 `FolderData`、JSON 兼容读取和 Inspector；写入前确保目标目录存在。
2. ReplaceComponent 可在替代组件类上加 `[ReplaceComponent(typeof(SourceType))]`；多映射用带 `[ReplaceComponentTypeConfig]` 的静态 `Dictionary<Type,Type>`。
3. 替代类型必须是可添加的 `Component`，并单独迁移既有 prefab；监听器不会替你做批量升级。

## 约束与常见错误

| 场景 | 真实约束/常见错误 |
| --- | --- |
| 完成源复用 | `AutoResetUniTaskCompletionSourcePlus` 只在 `GetResult` 后回池；创建后不等待、重复等待或缓存跨版本 Task 都会破坏池化假设。完成回调本身抛异常还可能阻止 `core.TrySet*` 正常返回给调用方。 |
| 取消 | `UniTask.AttachCancellation` 收到已经取消的 token 会立刻抛普通 `Exception`；`MallocToken` 与 `FreeToken` 不平衡会泄漏引用或在多释放时抛错。当前 UGF UI/Entity 调用把 `FreeToken` 放在 await 之后而非 `finally`，异常路径需特别检查。 |
| StateController CodeBind | 当前生成器没有 `STATE_CONTROLLER_CODE_BIND` 条件；只加宏不会改变行为。组名/状态名被直接拼成 C# 标识符，包含空格、符号、关键字或重名会生成非法/冲突代码。 |
| StateController 本地化 | `LocalizationValue` 的 Editor 下拉依赖 UXTool Editor key 列表；运行时 UXText Binding 又要求 UXTool/UGF 本地化已经初始化。关闭本地化只设置 `ignoreLocalization`，不会恢复旧文字或图片。 |
| Luban 生成物 | 手改 `Game/**/Generate/Luban` 或 Editor Generate 会在下次导出丢失；loader 名必须与导出的二进制名一致。`EditorBeanBase.SaveJsonFile` 不创建父目录并直接覆盖文件。 |
| Luban 内存统计 | `TablesMemory.EndRecord()` 使用 `Math.Min(0, after-before)`：正常正向增长记为 0，GC 后下降会累计负数。因此 Inspector 的“memory size”当前不能当作表内存实测值。 |
| Soco 剔除 | 每次 `OnProcessShader` 都重新 `FindAssets/LoadConfigs`，大量 Shader 会增加构建时间；所有变体被剔除时仍会强制保留第一个。白名单或高优先级条件也必须用实际变体验证。 |
| Soco 序列化/兼容 | 条件使用 `[SerializeReference]`；改类名、命名空间或程序集会使旧 Config 丢类型。Collection mapper 依赖 Unity 私有 `ShaderUtil` 反射和 `.shadervariants` 的 `m_Shaders` 序列化字段，Unity 升级后必须回归。 |
| Soco 项目扩展 | `ProjectFile/MaterialCollection_ProjectDependRes` 绑定 UGF ResourceCollection；复制 SocoTool 到无 UGF 项目时应改写或删除。`MaterialCollection_TotalMaterial` 默认扫描 Assets/Packages，范围很大且注释明确不建议真实项目直接使用。 |
| UXTool 初始化 | Player 中 `LocalizationHelper.GetString` 依赖已设置的 `LocalizationComponent`；在 `UXTool.InitAsync` 前调用可能空引用。AssetCollection 和固定路径资源缺失时，UXImage 默认材质、替代图、本地化图片等无法加载。 |
| UXTool 编辑器副作用 | `ThunderFireUXTool` 不是只读查看器。创建配置、导入图片、组件库删除、检查修复、自动拼接和 SVN 操作都可能写盘或调用外部程序；执行前检查选择范围和版本控制 diff。部分工具只在 `ODIN_INSPECTOR` 或 `USE_InputSystem` 下存在。 |
| FolderTag | 自定义保存路径的父目录不存在时 `File.WriteAllText` 会失败。递归标签返回的是祖先 `FolderData`，在子目录 Inspector 编辑时可能直接改到祖先标签。启动合并资源标签后按 GUID 建字典，重复或损坏数据也可能令初始化失败。 |
| ReplaceComponent | 只拦截“刚添加”的精确源类型，不处理已有组件，也不复制序列化字段。重复映射使用 `TryAdd`，先被枚举到的映射获胜且顺序不应依赖；替换过程没有显式 Undo/数据迁移。 |

## 验证方法

1. 静态校验：运行 `powershell -ExecutionPolicy Bypass -File KnowledgeBase/Test-KnowledgeBase.ps1`。
2. 程序集校验：在 Unity 6000.3.21f1 等待 `UniTask.Extension`、`StateController.Extension`、`LubanLib`、`SocoTool`、`Leihuo.UXTools.*`、`FolderTag.Editor`、`ReplaceComponent.*` 全部编译；再做一次目标 Player 编译以发现 Editor 反向引用。
3. UniTask：覆盖完成、异常、取消、已取消 token 和宿主销毁，确认回调只运行一次且 CTS 引用计数平衡。
4. StateController：在临时 prefab 上验证四种 Binding；运行 CodeBind，确认状态组属性、状态名/索引生成且 C# 标识符合法。
5. LubanLib：导出一组实际表，运行 `TablesComponent.LoadAsync`，核对并行加载、引用解析和 Editor Bean JSON 往返；不要把 `TablesMemory` 当前值作为通过标准。
6. SocoTool：在临时 Shader/Config/SVC 上做剔除检查、收集和拆分，再用 Development Build 或 AssetBundle 构建核对变体数量和渲染；保留构建前后资产 diff。
7. UXTool：运行 `ProcedurePreload`，切换至少两种语言，检查 UXImage/UXText、红点、安全区和 UIStateAnimator；Editor 侧逐项验证菜单的创建、Undo、覆盖和删除范围。
8. FolderTag/ReplaceComponent：用临时目录、Scene 和 GameObject 验证 JSON 写入、递归显示、清理空 GUID，以及新加 `Button` 被换为 `ExButton`；确认既有 Button 不会自动变化。

本文只把源码、生成文件和资产 YAML 能支撑的内容写为静态结论，不通过 Unity Agent Bridge 修改或运行 Unity；Unity 编译、构建、Shader 变体剔除、SVC 窗口写盘、FolderTag/ReplaceComponent 交互验证仍需有完整项目依赖的 Editor 环境。
