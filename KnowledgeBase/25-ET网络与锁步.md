# 模块 25：ET 网络、Demo 与锁步

> Catalog ID: `ET-07`  
> 状态：`verified`  
> 最后核验：`2026-08-04`  
> 适用模式：ET Client / ET Server / Shared

## 模块定位

本模块说明 ET Hotfix 中三条彼此衔接的业务链：Client/Server/Share 消息分发与 `Session` 生命周期、Realm/Gate/Map Demo 登录进图、以及 Match/Room 的 LockStep 帧同步。客户端外网连接被隔离在独立 `NetClient` Fiber；服务端业务 Scene 通过进程内 Actor 消息或 `NetInner` Fiber 通信；锁步模拟由 Client 和 Server 共用 Share 中的 `RoomSystem`、`LSWorld` 与确定性 System。

本文不把协议生成物当作手写入口，也不把 HotfixView 的 UI/表现同步当作确定性模拟。Router、ActorLocation、AOI 和 DB 只解释它们在主链中的边界，详细实现应分别查协议生成、ET Core 和服务端文档。

## 依赖关系

- `NetComponent` 拥有 `AService` 和子 `Session`；外网构造为 `KService(..., ServiceType.Outer)`，接收后按当前 SceneType 调用 `NetComponentOnRead` Invoker。
- `MessageSessionDispatcher` 处理带 `ISessionMessage`/`ISessionRequest` 语义的直连消息；`MessageDispatcher` 处理投递到 Entity/Scene 的 `IMessage`、`IRequest` 和 Location 消息。二者都按特性中的 SceneType 过滤。
- `Model/Share/Module/Message` 只定义跨端消息语义和状态：`Session` 保存 RpcId、回调表、`LastRecvTime`/`LastSendTime`，`MessageSessionDispatcher` 由 `[MessageSessionHandler]` 扫描生成 opcode 到 Handler 的映射；真正网络读写和超时组件生命周期在 Hotfix/Share System 中执行。
- 同进程跨 Fiber 使用 `ProcessInnerSender`；服务端 `MessageSender` 遇到跨进程 ActorId 时先投递到固定 `NetInner` Fiber，再由 `ProcessOuterSender` 通过进程内网连接发送。
- Gate 依赖 `LocationProxyComponent`/`MessageLocationSenderComponent`：普通 Unit 消息按 `LocationType.Unit` 路由，锁步 `FrameMessage`/`IRoomMessage` 按 Player 保存的 `RoomActorId` 路由。
- 客户端登录前从 RouterManager HTTP `/get_router` 取得 Realm 与 Router 列表，经 Router 建立到 Realm/Gate 的 KCP 会话；Realm/Gate 实际监听地址来自 Luban 启动表。
- LockStep 数据依赖 MemoryPack 快照和 TrueSync 定点数；`LSWorld`、`LSUnit`、`LSInputComponent` 位于 Model/Share，模拟 System 位于 Hotfix/Share，客户端表现位于 View 程序集。
- ET Core 的 `FiberManager.Create` 把 Fiber 注册到指定 Scheduler，再把 `FiberInit` 投递到该 Fiber 的 `ThreadSynchronizationContext`；`UNITY_EDITOR` 下 `Thread`/`ThreadPool` Scheduler 都映射到 `MainThreadScheduler`，因此编辑器静态/播放验证不能证明真实多线程调度。若 `FiberInit` 抛异常，当前实现只记录日志而不完成等待源，这是创建方可能挂起的失败边界。
- 服务端预配置 Fiber 由 `EntryEvent2_InitServer` 按 `DTStartProcessConfig`、`DTStartSceneConfig` 创建；每场锁步房间则由 Map 动态创建 ID 大于 10000000 的 `RoomRoot` Fiber。

## 入口与调用链

### 消息与 Fiber 分发

1. `NetComponent.OnRead` 更新 `Session.LastRecvTime`，反序列化 `(ActorId, message)`，回收网络缓冲区，再以 SceneType 调用 `NetComponentOnRead`。
2. NetClient Fiber 中，`IResponse` 交给 `Session.OnResponse` 完成本 Fiber 的 RPC；`ISessionMessage` 交给 `MessageSessionDispatcher`；其他 `IMessage` 经 `FiberParentComponent.ParentFiberId` 转发回 Main Fiber。
3. Realm 只接受 Session 消息。Gate 除 Session 消息外，把 `FrameMessage` 和 `IRoomMessage` 的 `PlayerId` 覆盖为已认证 PlayerId，再发给该玩家的 RoomActorId；Location 消息转到 Unit Actor。
4. Actor 消息进入目标 Fiber 的邮箱。`OrderedMessage` 用 `CoroutineLockType.Mailbox + ParentInstanceId` 串行并在实体已更换时返回 NotFound；`UnOrderedMessage` 直接异步调用 `MessageDispatcher`。
5. `MessageHandler<E, Request, Response>` 捕获异常、恢复原 RpcId，并由 `ProcessInnerSender.Reply(fromAddress, response)` 返回；Session RPC 则由 `MessageSessionHandler` 检查 Session InstanceId 后直接 `session.Send(response)`。

### Demo 登录与进图

```text
HotfixView Login UI
  -> LoginHelper.Login
  -> ClientSenderComponent.LoginAsync
  -> 创建 SceneType.NetClient Fiber
  -> Main2NetClient_Login（进程内 RPC）
  -> RouterManager /get_router + Router 握手
  -> 临时 Realm Session: C2R_Login
  -> Realm 按 account hash 选 Gate
  -> R2G_GetLoginKey（Actor RPC）
  -> R2C_Login(Address, Key, GateId)，Realm Session 随后关闭
  -> 持久 Gate Session: C2G_LoginGate
  -> Gate 校验 key、移除 5 秒认证超时、创建或复用 Player
  -> G2C_LoginGate(PlayerId) -> Main Fiber 发布 LoginFinish
```

普通 Demo 的 `C2G_EnterMap` 在 Gate 为 Player 创建临时 GateMap 和 Unit，并把真正传送延迟到本帧末尾，确保 RPC 响应先返回。`TransferHelper` 序列化 Unit/`ITransfer` 组件、释放旧 Unit、锁定 Unit Location，再向目标 Map 发送 `M2M_UnitTransferRequest`；目标 Map 恢复实体，依次向客户端发送 `M2C_StartSceneChange`、`M2C_CreateMyUnit`，加入 AOI 后解锁 Location。客户端 `SceneChangeHelper` 等待 MyUnit 后完成 CurrentScene 切换并唤醒 `EnterMapAsync`。

### LockStep 主链

1. 客户端 Lobby 调 `EnterMapHelper.Match`，经 Gate 的 `C2G_MatchHandler` RPC 到 Match Fiber。`MatchComponent` 去重排队；达到 `LSConstValue.MatchCount` 后随机选择启动表中的 Map。
2. Map 收到 `Match2Map_GetRoom`，动态创建 `SceneType.RoomRoot` ThreadPool Fiber，发送 `RoomManager2Room_Init`；房间 Fiber 创建 `Room`、`RoomServerComponent` 和 `LSWorld(SceneType.LockStepServer)`，返回 RoomActorId。
3. Match 按 `LocationType.Player` 通知 Gate。Gate 给 Player 添加 `PlayerRoomComponent` 并向客户端发送 `Match2G_NotifyMatchSuccess`。客户端创建同 Room InstanceId 的 `Room`，等待表现层场景事件后发送 `C2Room_ChangeSceneFinish`。
4. Gate 把该消息补上 PlayerId 并路由到 Room。全部 `RoomPlayer.Progress == 100` 后，服务端等待 1 秒，构造初始 `LockStepUnitInfo`，执行 `room.Init`，添加 `LSServerUpdater`，广播 `Room2C_Start`；客户端收到后创建 `LSWorld(SceneType.LockStepClient)` 和 `LSClientUpdater`。
5. 客户端按 `FixedTimeCounter` 推进预测帧：先快照并执行共享 `room.Update`，再发送当前输入的 `FrameMessage`。Gate 再次覆盖 PlayerId 后转给 Room。
6. 服务端每 50 ms 取下一权威帧；输入缺失时沿用该玩家上一帧输入，否则填零输入。随后先广播 `OneFrameInputs`，再用相同输入执行共享 `room.Update`。
7. 客户端按收到顺序递增 `AuthorityFrame`。若权威输入等于预测则记录回放并发哈希；不等则从该帧的 MemoryPack 快照恢复 LSWorld，执行权威帧，再重放其后的预测帧。
8. 每当客户端提交的 `FrameMessage.Frame` 能被 20 整除，服务端下发时间差；客户端把更新间隔调整到 40～66 ms。客户端只对已成为权威的帧发送 `C2Room_CheckHash`；不一致时服务端回传该帧 LSWorld 快照，当前客户端 Handler 仅输出双方状态用于诊断，不自动修正。
9. 已有 PlayerRoom 的账号重新登录时，Gate 异步向 Room 请求当前 `StartTime`、Unit 状态和 `AuthorityFrame`，发送 `G2C_Reconnect`；客户端重建 Room/LSWorld，并从 `frame + 1` 继续预测。

## 核心类型与 API

| 类型/API | 职责 | 生命周期/线程约束 |
| --- | --- | --- |
| `NetComponent` | 驱动 AService、创建/接收 Session、按 SceneType 上抛消息 | Scene 组件；`Update` 驱动网络，销毁时 Dispose AService |
| `Session` / `Call` / `Send` | 维护 RpcId、回调表、收发时间和远端地址 | NetComponent 子实体；只能在所属 Fiber 使用，销毁会让全部待决 RPC 失败 |
| `ClientSenderComponent` | Main Fiber 到 NetClient Fiber 的代理 | 登录时创建 NetClient Fiber；销毁时异步 `FiberManager.Remove` |
| `MessageSessionDispatcher` | 按 Opcode + SceneType 调直连 Session Handler | `[Code]` Singleton，热代码重建时重新扫描特性 |
| `MessageDispatcher` | 按消息 Type + SceneType 调 Actor/Location Handler | 目标 Entity 必须属于匹配 SceneType，RPC 响应类型必须与 Opcode 映射一致 |
| `ProcessInnerSender` / `MessageSender` | 同进程 Actor RPC；统一封装同/跨进程发送 | 不允许直接取得其他 Fiber 引用；跨进程经 NetInner Fiber |
| `FiberInit_*` | 在目标 Fiber 线程组装 Timer、Mailbox、Sender 和业务组件 | `FiberManager.Create` 完成初始化后才返回；Unity Editor 的 ThreadPool 调度仍映射主线程 |
| `Room` / `RoomSystem.Init` | 保存玩家、权威/预测帧、FrameBuffer、时钟、Replay 和 LSWorld | Server 挂在动态 RoomRoot；Client 挂在 Main Scene，切场景/重连时替换 |
| `FrameBuffer` | 环形保存输入、MemoryPack 快照和哈希 | 默认容量 1200 帧（20 fps × 60 s），初始可访问上限为起始帧 + 600；越界访问抛异常 |
| `LSWorld` / `LSEntitySystemSingleton` | 确定性实体树、稳定 ID、按实体 ID 排序执行 LSUpdate | Fiber、SceneType 不序列化；反序列化后调用方必须恢复 SceneType/归属 |
| `LSServerUpdater` | 以服务端时间生成权威帧并补齐缺失输入 | Room 启动后添加，每个 Room Fiber 独立更新 |
| `LSClientUpdater` / `LSClientHelper.Rollback` | 本地预测、发送输入、快照回滚和重放 | 只修改 Client Room；表现同步通过事件/`ILSRollback`，不写回共享模拟 |

## 数据与生命周期

- 外网 Accept 创建 Session 时，非 Benchmark 服务端同时添加 5 秒 `SessionAcceptTimeoutComponent` 和每 2 秒检查一次的 `SessionIdleCheckerComponent`；只有 Gate key 验证成功后才移除认证超时。接收或发送任一方向超过 10 秒未活动时 Session 被释放。
- `Session.Call` 先登记 RpcInfo 再发送。Cancellation 返回 `ERR_Cancel`；带 timeout 的重载会移除回调并抛超时；Session 销毁则以当前 Session Error 结束所有待决 RPC。
- `NetComponent.OnRead` 不直接知道业务 Handler，只把反序列化出的 `(Session, Message)` 作为 `NetComponentOnRead` 按 SceneType 发布；NetClient、Realm、Gate 等具体分支由各自 Invoker/Handler 决定。
- Realm Session 是一次性的：登录响应后延迟 1 秒 Dispose。Gate Session 保存在 NetClient Fiber 的 `SessionComponent`，附加 `ClientSessionErrorComponent`；断开时通知 Main Fiber，但当前 Main Handler 只记录错误。
- Gate Session 销毁会通过 `SessionPlayerComponent.Destroy` 发送 `G2M_SessionDisconnect`。普通 Map Handler 当前为空；锁步 `RoomPlayer.IsOnline` 默认 true，现有 Hotfix 没有维护其离线状态。
- Server RoomRoot Fiber 由 Map 动态创建，Room 初始化后长期持有 Room、RoomServerComponent、LSWorld、FrameBuffer 和 updater。本轮源码未找到比赛结束后调用 `FiberManager.Remove` 的路径。
- `RoomSystem.Update` 先把本帧输入写入各 `LSInputComponent`，再序列化 LSWorld 并计算哈希，最后执行按实体 ID 排序的 LSUpdate 并递增 `LSWorld.Frame`。因此 frame N 的 Snapshot 已含第 N 帧输入但尚未执行该帧 LSUpdate；回滚时恢复快照后仍会用权威输入覆盖并执行该帧。
- `Record` 只记录 `frame <= AuthorityFrame` 的输入，每 1200 帧保存一个回放快照。客户端回放从 `Replay.FrameInputs` 推进，`JumpReplay` 从最近的 1200 帧快照恢复。
- 重连不是补发历史输入：服务端返回当前 LSUnit 状态和当前权威帧，客户端以此作为新的基线；旧 Client Room 会先被移除。

## 开发扩展步骤

### 新增一个外网 Session RPC

1. 在 `Design/Proto/ET-Client/OuterMessage.proto`（普通业务）或 `LockStepOuter.proto`（锁步）增加请求/响应，写正确的 `ResponseType` 和 `ISessionRequest`/`ISessionResponse` 注释。
2. 切换到 `Design/Proto` 目录运行 `proto2cs.bat`，确认 Client 与 ClientServer 生成目录同步变化；该脚本依赖调用目录，不要从仓库根直接调用，也不要手改 `Model/Generate/**/Message`。
3. 在 Server Hotfix 增加 `[MessageSessionHandler(SceneType.Realm/Gate)]` Handler。鉴权类请求必须在校验成功后才移除 `SessionAcceptTimeoutComponent`。
4. Client Main 通过 `ClientSenderComponent.Call/Send`，不要直接跨 Fiber 访问 Gate Session。确认响应由 NetClient Fiber 的 `Session.OnResponse` 完成。
5. 同时验证 Handler SceneType、协议接口类别和 RpcId；把需要由 Gate 路由到 Entity/Room 的消息定义成对应 Location/Room 接口，而不是 Session 消息。

### 新增一个 Room 命令

1. 在 `LockStepOuter.proto` 定义 `IRoomMessage`；该接口要求 `PlayerId` 字段。
2. 客户端通过 `ClientSenderComponent.Send` 发送。Gate 会基于已认证 Session 覆盖 PlayerId，并使用 `PlayerRoomComponent.RoomActorId` 路由，Room Handler 不应信任客户端自填身份。
3. 在 Server Hotfix 增加 `[MessageHandler(SceneType.RoomRoot)]` Handler，只修改所属 Room Fiber 内的状态。
4. 广播复用 `RoomMessageHelper.BroadCast`；同一消息发给多个玩家时必须保持 `MessageObject.IsFromPool = false`，否则首个发送后可能回池。

### 新增一个锁步状态或 System

1. 可回滚数据放 Model/Share 的 `LSEntity`/MemoryPack 类型；使用 TrueSync 数值，给序列化字段稳定顺序，明确忽略 Fiber、SceneType 和表现引用。
2. 模拟逻辑放 Hotfix/Share，以 `[LSEntitySystemOf]` + `[LSEntitySystem]` 实现 `ILSUpdate`；实体通过 LSWorld 的稳定 ID API 创建，由 `LSUpdater` 按 ID 排序执行。
3. 不在共享 System 中读取 Unity Transform、墙钟、平台浮点随机数或客户端单例；使用随机数前先以相同种子初始化 `LSWorld.Random`，之后只从该状态取值。当前 Room 初始化链没有设置 Random。
4. 表现层只订阅 `LSSceneChangeStart`、`LSSceneInitFinish` 或实现 `ILSRollback` 重建视图；不得反向写 LSWorld。
5. 同时测试权威一致、预测不一致回滚、哈希故障、重连和回放跳转；Model/协议变化需完整重启或重新构建两端，不能只 reload Hotfix。

## 约束与常见错误

- **混用两套 Handler**：`ISessionRequest` 对应 `MessageSessionHandler` 和当前 Session；Actor/Room/Location 消息对应 `MessageHandler` 和目标 Entity。类型或特性用错会进入错误分支或找不到 Handler。
- **SceneType 不匹配**：分发器会按 flags 过滤；例如锁步客户端 Handler 绑定 `SceneType.LockStep`，Room 服务端绑定 `SceneType.RoomRoot`，不是 `SceneType.Room`。
- **跨 Fiber 持有实体**：Main 只能持有 NetClient 的 ActorId，服务端跨 Scene 使用 Actor/Location 路由。`FiberManager.Get` 是 internal，直接共享 `Session`、Room 或 Entity 会引入线程竞争。
- **错误处理池对象**：RPC 响应和收到的帧消息常用 `using` 回池；广播对象必须取消池回收。新增异步分支时要确认对象不会在 await/多播期间被复用。
- **认证超时误删**：Accept Session 5 秒后会被销毁；过早移除会放过未认证连接，忘记移除会让合法 Gate Session 在登录后被断开。
- **把诊断当修复**：`Room2C_CheckHashFailHandler` 只反序列化并打印服务端/客户端世界，没有替换客户端状态；生产级纠偏、踢线或采样策略尚未实现。
- **房间与离线清理未闭环**：匹配成功后的“等待确认/超时”仅有注释；没有 RoomRoot Fiber 回收；`G2M_SessionDisconnectHandler` 为空且 `RoomPlayer.IsOnline` 未更新。扩展人数或长期运行前必须补齐。
- **当前并非多人压力基线**：`LSConstValue.MatchCount == 1`。修改人数会同时影响匹配、输入补齐、全员加载确认、广播和断线策略，不能只改 UI。
- **依赖隐式帧顺序**：`OneFrameInputs` 没有 Frame 字段，客户端按到达顺序 `++AuthorityFrame`。不要把权威帧改走可能乱序的旁路，也不要跳过某帧广播而不扩展协议。
- **预测上限注释与代码有一帧差异**：代码在“当前预测差值 > 5”时才停止，因此差值为 5 时仍会再推进一帧；需要严格最多 5 帧时应补边界测试后修正。
- **环形缓冲不是永久历史**：FrameBuffer 仅按 `frame % 1200` 保存且下界未校验；很旧的校验/跳转可能读到已覆盖槽位，外部请求必须限制可接受帧范围。
- **Editor 不能证明多线程安全**：Unity Editor 中 Thread/ThreadPool Scheduler 都映射 MainThreadScheduler；必须在 Player 或 DotNet 服务端验证真实并发行为。
