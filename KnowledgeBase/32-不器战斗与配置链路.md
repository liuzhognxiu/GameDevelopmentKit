# 模块 32：不器战斗、经营与配置链路

> Catalog ID: `BUQI-01`  
> 状态：`verified`  
> 最后核验：`2026-08-21`  
> 适用模式：GameHot / Editor / .NET Headless

## 模块定位

本模块覆盖《不器》当前已落地的纯 C# 战斗内核、九日经营流程、随机供给、商人、训练、事件、八方链接、坊市交互和 Luban 配置链。当前内容基线为 300 件原创器物、6 个精炼、16 个回响、8 个商人、4 个训练师、12 个训练项目、24 个事件和 72 个事件选项。

本模块只把源码、配置、生成物和本轮实际运行的非 Unity 门禁记为已验证。Unity Editor 编译、EditMode 测试、预制体实机交互和目标 Player 构建仍需在 Unity 环境中单独验收；仓库中的历史 QA 文件不能替代当前工作树复测。

## 依赖关系

- `Battle` 只依赖 C# 标准库和自身类型，不得引用 Unity、UGF、ET、资源、场景或网络。
- `Share/Buqi.Simulation.Headless` 直接编译 `Battle/**/*.cs`，因此可以在不启动 Unity 的情况下阻断编译错误、行为契约漂移和批准哈希漂移。
- `Run`、`DemoUI` 和 `UI` 依赖业务配置模型；生成表由 `BuqiGeneratedConfigAdapter` 转为 `BuqiConfigCatalog`，再由内容校验器和各运行时服务消费。
- Excel 是配置真源；生成 C#、JSON、bytes 和 `LocalizationKey.cs` 只能通过 Luban 导出更新。

## 入口与调用链

```text
BuqiItem.xlsx + 其余 Buqi 工作簿 + Localization.xlsx
  -> Tool.exe ExcelExporter Check / Export
  -> DR/DT/Buqi* generated C# + dtbuqi*.json/bytes + Localization.bytes
  -> TablesComponent.LoadAllAsync
  -> BuqiGeneratedConfigAdapter
  -> BuqiConfigValidator + BuqiContentConfigValidator
  -> Battle / Run / Supply / Event / Training / DemoUI
```

```text
九日经营状态
  -> 当前时段操作（坊市 / 训练 / 事件 / PvE / 异步对战）
  -> BuqiRunOperationFlowAdapter
  -> 原子更新货币、器物、训练、事件与结算状态
  -> 保存、恢复或推进到下一时段/下一日
```

```text
BattleRequest + IItemDefinitionProvider
  -> BuqiBattleSimulator.Simulate
  -> 八格环形目标解析与链接规则
  -> 状态边界 -> 冷却 -> Declare/Resolve/Chain -> Aggregate -> 死亡 -> 沙暴
  -> BattleResult + BattleLogHash
```

## 核心类型与 API

| 类型/API | 职责 | 生命周期/线程约束 |
| --- | --- | --- |
| `BuqiBattleSimulator` | 战斗主循环、稳定事件顺序和哈希 | 纯 C#；非法请求返回 `InvalidBuild` |
| `BuqiLinkEngine` / `BuqiLinkTopology` | 八格环形邻接、链接条件与执行保护 | 战斗内确定性计算，不读取 Unity 状态 |
| `BuqiRunController` | 九日局内状态与阶段推进 | 由运行流程统一持有和持久化 |
| `BuqiRunOperationFlowAdapter` | 将商店、事件、训练等操作接入同一事务边界 | 操作失败不得留下部分状态 |
| `BuqiBazaarSupplyViewSource` | 从商人配置与供给服务生成坊市候选 | 按日、构筑、角色与槽位约束过滤 |
| `BuqiRunEventSelector` / `BuqiRunEventExecutor` | 事件选择、条件、成本和结果执行 | 使用稳定 ID；保存数据不持有 Unity 对象 |
| `BuqiRunTrainingService` | 训练师与训练项目结算 | 先校验条件与成本，再原子提交 |
| `BuqiConfigValidator` | 结构、引用、战斗与内容安全校验 | 300 件正式目录或 42 件兼容目录 |
| `BuqiContentConfigValidator` | 商人、训练、事件、升级、链接与经济效果校验 | 正式 300 件目录使用 120/108/72 解锁带 |

## 数据与生命周期

- 战斗规则为 `RuleVersion = 0.6.0`、`SimulationVersion = battle-core-0.6.0`。当前语义包括 10 tick/秒状态跳字、固定 2 倍急速/0.5 倍减速、立即冷却推进、BattleSeed 暴击、多重、弹药、飞行、怒气与无硬上限沙暴。批准哈希包含规则/模拟/内容版本；改变版本必然刷新全部向量哈希。
- 300 件器物 ID 连续为 `W8-001..W8-300`。每条记录都有中文策划注释 `DesignNote`、正式作用 `EffectDescription`、名称本地化键、升级说明、供应角色、解锁日、位置提示、至少三个器物链接，以及 1 至 3 个当前内核可执行战斗效果。
- 器物按日解锁为 120/108/72，对应第 1/4/7 日；尺寸分布为 132/108/60，对应 S/M/L。基础价格、强化、定型和精炼成本都由尺寸预算约束。
- 28 件 `economy` 器物各定义一个 `MaxPerDay = 1` 的运行层收益；非经济器物不定义运行层收益。
- 商人、训练、事件和链接使用稳定字符串 ID。保存/恢复只能存 DTO 和 ID，不能持有表行或 Unity 对象引用。
- 坊市售卖通过拥有物拖向上方摊位触发：悬停阶段只预览退款，合法放下后才原子移除器物并增加货币。

## 开发扩展步骤

1. 先在测试或 PowerShell 配置门禁中写出失败断言，再修改 Excel 或运行时源码。
2. 修改表格后运行 Luban Check 和正式 Export；同时审查 Excel、generated C#、Editor JSON、Hot bytes 和本地化输出。
3. 新增器物字段时同步修改 `BuqiConfigModels`、`BuqiGeneratedConfigAdapter`、两层 validator 和专属目录测试。
4. 修改战斗语义时先更新独立行为契约；只有契约通过且差异经审查，才显式执行 `update-hashes`。
5. 修改经营操作时以 `BuqiRunOperationFlowAdapter` 为事务边界，补充保存/恢复、重复点击和失败回滚测试。
6. 最后在 Unity 中运行相关 EditMode 测试并实际操作预制体；没有当前工作树的 Unity 证据时不得宣称实机完成。

## 约束与常见错误

- 不要手改 `Generate/Luban`、`.json` 或 `.bytes`；它们会在下次导出时被覆盖。
- 不要把 The Bazaar 的名称、文本、美术或具体数值复制进正式内容；研究资料只用于学习机制。
- 不要把 `update-hashes` 当成消除失败的快捷命令。必须先定位规则差异并运行独立契约。
- 不要让预览操作直接写入货币、背包或棋盘；拖拽取消和非法放下必须保持原状态。
- 不要把历史 QA XML 当成当前分支通过。Unity 证据必须记录本次源版本、测试集、时间和结果。
