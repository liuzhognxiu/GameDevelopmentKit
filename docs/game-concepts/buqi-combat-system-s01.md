# S01 战斗系统策划案（确定性自动战斗 + 关键词）

**优先级：P0** ｜ **依赖：配置表规范（S08）** ｜ **状态：待开发**

## 1. 目标
实现一套**确定性、可回放、可服务器校验**的自动战斗模拟器。玩家战前完成构筑，战斗由触发器网络自行结算，无需实时操作。这是《星墟商栈》的核心乐趣载体。

## 2. 核心规则（已按 The Bazaar 真实机制核对，2026-08-21 修订）
- **时间轴（实时秒驱动）**：战斗以 **1 秒 = 1 tick** 实时推进；每个物品按各自的**秒级冷却**触发，战斗**无硬性 tick 上限**。这是与初版“20–40 tick 硬截断”的根本区别——原作不设固定上限，靠沙暴逼出结果。
- **确定性**：同一输入（双方阵容快照 + 种子）必须产生完全一致结果，跨平台（PC/移动）零漂移，便于异步回放与服务器校验。
- **触发调度**：每 tick 冷却推进 −1（加速 −2 / 迟滞 −0.5 / 冻结 0）；冷却归 0 即触发，按槽位顺序（或优先级）结算。
- **每 tick 结算顺序（固定，保证确定性）**：
  1. 状态跳数：毒蚀（每秒）、灼烧（每秒 2 点并递减）、Tempo 等资源累积
  2. 冷却推进（含加速/迟滞/冻结修正）
  3. 触发结算：冷却归零的物品按序激活
  4. 护盾 / 再生 / 愈合结算
  5. 死亡判定
  6. 沙暴判定（超时进入猝死）
- **沙暴猝死（Sudden Death）**：战斗超过 `STORM_START`（初版建议 30s，可配置）仍无胜负，进入沙暴——每 tick 对**双方**施加递增真实伤害 `STORM_BASE + (tick−STORM_START)×STORM_RAMP`，直至一方 HP 归零。该机制天然终结“无限护盾/再生”循环，对应原作 Storm / Sandstorm。
- **胜负**：任一方 HP 归 0 即负；沙暴逼出唯一结果。**无“剩余血量比”判定**（原作亦如此）。

### C. 结论

- S01 与契约 v0.7.0 在**语义上基本一致**，仅存在单位粒度（秒 ↔ 0.1s tick）与命名（星墟商栈术语 ↔ 不器术语）差异。
- 契约 v0.7.0 是 S01 的**实现细化**：把秒级推进细化为 1/10000 tick 的整数推进，把"有几率"细化为万分比 + 独立随机判定，并补充了反无限循环的事件预算上限（§6）与哈希校验（§10）。
- **不器 v0.7.0 相对 S01 的差异**：删除狂怒/怒气；新增"价值 Value"（S01 无此词条）；灼烧明确"护盾减伤 50%"；棋盘 8→10 格。
- 后续若 S01 语义变更，必须先改契约并走 `update-hashes`，再更新本映射表。
