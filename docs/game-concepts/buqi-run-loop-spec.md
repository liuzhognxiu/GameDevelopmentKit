# 《不器》单局循环规格 v0.5

> 定位：单局（Run）循环的**设计真源**。定义"从选人到渡劫成道"的完整流程、进度数值与状态转移，代码按本文修改。
> 取代：B02 `systems/01-run-loop.md`（5 胜 / 3 败 / 3 套起始方案旧基线）；代码 `BuqiRunRules` 的"九天"结构。
> 术语：本文用**游戏术语**——装备（包装=器物）、胜场（包装=道印）、单局生命（包装=道基）、对手快照（包装=道影）；遵循 `gameplay-terminology.md` v1.2。境界/修为/渡劫/心魔试炼为进度机制名，无更平白替代，直接使用。
> 标记：**[确认]** = 用户已敲定；**[可调]** = 本文建议值，实现后可调，进 B10 调优登记。

## 1. 单局总览

```
选 1 名英雄 → 无限天问道赛程 → 十胜圆满 → 渡劫 → 成天道（胜利）
                                  ↘ 单局生命断绝（失败）
```

- 无固定天数上限（无限天）。
- 每天 6 时段（当前代码已正确实现，保持不变）：
  晨(操作) → 午(操作) → 昏(PvE) → 午后(操作) → 操作 → 夜(PvP)

## 2. 双进度

### 2.1 境界 = 修为（9 境经验制）[确认]

| 序 | 境界 | 突破所需累计修为 [可调] | 叙事节点 |
|---|---|---:|---|
| 0 | 炼气 | 开局 | 首次问道，问道碑亮起 |
| 1 | 筑基 | 8 | 闻辛同台较劲 |
| 2 | 结丹 | 18 | 坊市商人/训练师开启 |
| 3 | 元婴 | 30 | 对手开始针对性构筑 |
| 4 | 化神 | 44 | "必胜丹方"骗局伏笔 |
| 5 | 炼虚 | 60 | 历代对手快照开放 |
| 6 | 合体 | 78 | 取舍压力最强 |
| 7 | 大乘 | 98 | 大乘圆满 |
| 8 | 圆满 | 120 | 九境圆满，引动天劫 |

**修为来源 [可调]**：

| 来源 | 修为 |
|---|---:|
| PvE 胜 | +3 |
| PvE 败 | +1 |
| PvP 胜 | +2 |
| PvP 败 | +1 |
| 事件 | +1~2 |

**境界突破**：修为达阈值 → 晋入下一境，触发**三选一奖励**（成长项 + 内容解锁项，按英雄过滤混入专属项）。

### 2.2 胜场 = PvP 胜利（十胜）[确认]

- 每次 **PvP 胜** +1 胜场，上限 **10**。
- **PvE 胜不给胜场**（只给修为）。
- 胜场 == 9 后，下一次 PvP 即**渡劫之战**（见 §4）。
- 胜场同时是问道碑排名凭证（剧情称"道印"，十印圆满）。

## 3. 单局生命（20）[确认]

- 初始 **20** 点。
- **PvP 败** → 单局生命 -= **当前天数**（Day）。
- 单局生命 > 0：正常继续。
- 单局生命归零：进入**心魔试炼**（最后机会）：
  - 下一次 PvP **胜** → 单局生命 = 当前天数（恢复一线生机），胜场 +1（正常），退出心魔试炼；
  - 下一次 PvP **败** → **道途断绝**，本局结束（Defeat）。

> 恢复值"=当前天数"为 [可调] 建议；与"败扣=当前天数"对称。剧情称"道基"。

## 4. 渡劫 = 第 10 胜 [确认]

- 胜场 == 9 后，下一次 PvP 的对手固定为**万法道影**（历届问道者所有赢法堆成的最强阵容）。
- 渡劫之战 = **三关三问**；战前玩家**三式选一**（对应现有 `BuqiTribulationRoute`）：
  1. **直面天雷**（FaceThunder）：不取巧硬撼；
  2. **碎器证道**（ShatterArtifact）：主动碎掉最高品质装备；
  3. **问心消劫**（QuestionHeart）：燃尽胜场以取舍应答（消耗胜场，≤当前心魔值）。
- 三关全过 → **渡劫成功** → 天道三形态（定衡 / 众修 / 自择）→ **Victory**。
- 任一关不过 → 渡劫失败 → **Defeat**。

## 5. 英雄选人 [确认]

- 开局选 1 名英雄（阿瓷 / 闻辛 / 裴照川 / 荀照），各带专属卡池、本命法宝、道途特质（详见 `buqi-heroes.md` v0.1）。
- 状态新增 `HeroId`；商店 / 事件 / PvE 掉落 / 突破三选一按当前英雄过滤（`DTBuqiItem.Hero` 字段）。

## 6. 每日状态机

沿用现有 `BuqiRunPhase` / `BuqiRunPeriod` 骨架，转移规则调整为：

| 当前 | 触发 | 下一状态 |
|---|---|---|
| Encounter（Hour1/2/4/5） | 完成操作 | 时段 +1；Hour2→PvE，Hour5→PvP |
| PveBattle（Hour3） | 结算（胜负） | 修为结算 → Hour4 Encounter |
| PvpBattle（Hour6） | 结算 | 见下方"PvP 结算分支" |
| DaySettlement | 确认 | Day+1 → Hour1（无限天） |
| TribulationRoute | 三式选一 | TribulationStage |
| TribulationStage | 三关结算 | 全过=Victory / 不过=Defeat |

**PvP 结算分支**（核心改动）：

1. PvP 胜：
   - 修为 +2；
   - 若 `胜场 < 9`：胜场 +1 → DaySettlement → 下一 Day（无限天）；
   - 若 `胜场 == 9`：胜场 → 10，进入 TribulationRoute（渡劫）。
2. PvP 败：
   - 修为 +1；
   - 单局生命 -= Day；
   - 若单局生命 > 0：→ DaySettlement → 下一 Day；
   - 若单局生命归零：进入心魔试炼状态；再败一次 PvP → Defeat，胜则单局生命=Day、胜场+1、继续。

## 7. 实现映射（代码改动清单）

### 7.3 `BuqiRunController` 转移

- `SettleBattle`：PvE 只结算修为（不给胜场）；PvP 按 §6"PvP 结算分支"；单局生命归零走心魔试炼。
- 渡劫触发：`胜场 == 9` 且下一次 PvP，而非 `Day == RunDayCount`。
- `ResolveTribulationStage`：保留三关结构，语义对齐 §4。
- 移除 `RunDayCount` 上限：`Day` 无限递增。

### 7.4 规则版本

- `BuqiRunState.CurrentRuleVersion` 由 `buqi-nine-day-run-rule-v3` 改为 `buqi-infinite-day-run-rule-v1`。

## 9. 保留的工程规范（自 B02，仍有效）

以下自 `01-run-loop.md` 保留，不因进度数字改动而失效：

- **命令模型**：`RunCommandEnvelope { commandId, expectedRevision, commandType, payload }`；同 ID 重放返回原结果，`expectedRevision` 拒绝旧视图新命令。
- **保存与恢复**：起始方案确认后 / 每个准备命令后 / 战前 / 结算后 保存；`settlementId` 与 `commandId` 幂等；版本不兼容显式拒绝恢复。
- **验收**：相同 RunSeed 与操作序列产生相同候选与结果；UI 重开不改变状态与 RNG 游标；非法阶段命令返回明确原因。
