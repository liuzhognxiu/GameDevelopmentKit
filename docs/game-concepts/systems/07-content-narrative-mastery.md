# 07｜内容架构、叙事映射与长期精通系统

## 1. 系统卡

| 字段 | 定义 |
|---|---|
| Purpose | 让玩家把多局经验沉淀为可迁移的构筑知识，并让“不器城学习取舍”的叙事由真实玩法行为支撑 |
| Player experience goal | 玩家不是因为永久数值变大而进步，而是更早看懂题目、更敢承担账单、更会主动舍弃 |
| Owner | 内容设计、叙事设计、`ContentStageGate`、本地进度记录 |
| Inputs | 单局选择、构筑标签、预测/归因记录、战斗事实、阶段门禁、剧情状态 |
| Outputs | 启用内容、角色/对手快照文本、城市反馈、知识型精通指标、章节状态 |
| 核心边界 | 首阶段不提供永久数值成长；叙事不能赋予隐藏战斗倍率 |

## 2. 长期循环

```text
积累装备词汇
-> 识别对手快照结构
-> 形成节奏与反制模型
-> 尝试更高风险组合
-> 主动舍弃不兼容装备
-> 形成个人构筑表达
```

### 长期奖励类型

| 类型 | 首阶段状态 | 玩家获得什么 | 禁止 |
|---|---|---|---|
| 知识精通 | 启用 | 对规则、窗口和账单的理解 | 用教程直接公布最优解 |
| 内容发现 | 分阶段启用 | 新装备、改造、对手快照关系 | P-1 前把完整验证库作为玩家内容启用 |
| 叙事反馈 | 最小切片 | 城市/角色回应玩家真实行为 | 对白给隐藏增伤 |
| 表达记录 | `[TO VALIDATE]` | 常用关系、代表构筑、关键战报 | 伪装为战力排行榜 |
| 永久数值 | 首阶段禁用 | 无 | 天赋、属性、账号加成 |
| 社交/赛季 | 首阶段禁用 | 无 | 排行、赛季压力、每日任务 |

## 3. 内容阶段门禁

| 阶段 | 装备 | 改造 | 商店 | 事件 | 对手快照 | 叙事 |
|---|---:|---:|---:|---:|---:|---|
| 战斗沙盒 | 9 | 3 | 0 | 0 | 测试快照 | 无正式叙事 |
| 最小配置链路 | 9 | 3 | 0 | 0 | 6 | 一句测试说明 |
| 内部效果验证库 | 24 | 6 | 0 | 0 | 16 | 仅配置/模拟验证，不作为玩家内容放行 |
| P-1 认知走查 | 9 | 3 | 主持人选项 | 0 | 3 组题目 | 不评价玩家策略 |
| 三轮迷你局 | 12 | 6 | 3 | 3 | 9 | 序章 + 角色短对白 |
| 完整首阶段 | 18 | 6 | 3 | 6 | 12 | 序章至第一章前半 |

表中数量必须区分历史门槛、内部验证覆盖和玩家可见预算。当前事实：历史 Step 3 完成了 `9/3/6` 最小链路，随后内部效果验证库扩为 `8 构筑方向/24 装备/6 改造/16 对手快照`；P-1 仍使用固定 `9/3` 题目，且三类参与者样本尚未完成，因此不能进入正式 Step 4 UI、完整经济或验证库整体启用。

## 4. 内容设计矩阵

每个新装备必须至少占据一个“主要职责”，并与另一个系统形成可读交互。

| 维度 | 选项 | 设计用途 |
|---|---|---|
| 尺寸 | S / M / L | 空间机会成本 |
| 节奏 | 启动 / 周期 / 终结 | 战前预测窗口 |
| 关系 | 左邻 / 右邻 / 双邻 / 标签 / 敌方目标 | 布局表达 |
| 资源 | 生命值 / 护盾 / 充能 / 过载 / 冷却 | 战斗账本 |
| 风险 | 空转 / 过载伤害 / 启动慢 / 易受延迟 / 占位 | 失败可解释性 |
| 方向 | fast 快攻 / buffer 护盾 / chain 连锁 / heal 续航 / poison 消耗 / burn 压迫 / freeze 控制 / overload 过载 | 内部验证库的 8 个 archetype；题目可归纳展示，但不是职业锁 |

### 内容准入问题

1. 它制造了什么新玩家决策？
2. 它的强度账单在哪个可见窗口发生？
3. 玩家能在战前预测它的主要行为吗？
4. 它与现有装备形成新关系，还是只增加数值档位？
5. 它是否超出 `buqi-effects-cv1` 已批准词汇？若是，停止并单独评审规则扩容。

## 5. 叙事与系统映射

| 叙事命题 | 玩法证据 | 可用表达 | 不可用捷径 |
|---|---|---|---|
| 残法也能成路 | 弱装备通过关系形成有效构筑 | 阿瓷评价组合方式 | 免费送高品质核心 |
| 城在模仿 | 城市复现玩家布局/节奏 | 灯火、街道、钟声变化 | 旁白直接宣布城有意识 |
| 有效不等于正确 | 高收益改造真实触发过载账单 | 回火事故、角色争论 | 剧情说危险但战斗无代价 |
| 大道来自取舍 | 玩家主动留空、卖出或覆盖强力改造 | 世界在两幕内回应 | 只用对白选项代表价值选择 |
| 规则与自由都有代价 | 稳定方案降低上限，开放方案增加风险 | 天衡院提供精确信息 | 把天衡院写成作弊反派 |

叙事状态只能改变已设计的内容呈现、可见候选或明确规则修正。所有机械后果必须在确认前显示，并进入 RunState 与日志。

## 6. 首阶段叙事切片

### 序章

- 漏火丹炉、缺口旧剑、护心铃意外形成可重复构筑。
- 荀照指出事实，不替玩家评价构筑。
- 三套起始方案分别引导频率、护盾转化、相邻连锁。
- 第一次战后，荀照引用真实战报中的一个主因。

### 单局中段

- 阿瓷承载风险与改造的生活化解释。
- 闻辛作为同规则竞争者，不拥有隐藏加成。
- 对手快照附一条前主人习惯，帮助记忆，不泄露完整答案。

### 单局结尾

- 取得 `[PLACEHOLDER]` 五枚胜场后，回环巷轻微复现玩家最后布局。
- 反馈读取实际构筑特征，例如空格、最大尺寸核心或主要标签。
- 不生成复杂分支，不承诺完整五章演出。

## 7. 精通指标

长期精通不以“玩了几天”定义，而以心智模型变化定义。

| 指标 | 观测 | 成功长什么样 |
|---|---|---|
| 预测具体度 | 是否指出装备、窗口、结果 | 从“试试看”变成可证伪判断 |
| 归因准确度 | 主因是否有日志证据 | 从结果描述变成因果描述 |
| 重构针对性 | 改动是否处理主因 | 从追品质变成改节奏/位置/账单 |
| 规则迁移 | 能否不用卡名表达规律 | 能说出“高频小伤会喂护盾转化” |
| 风险承担 | 是否理解收益与代价窗口 | 主动选风险并预留处理手段 |
| 构筑表达 | 是否形成不同于教程的合法组合 | 有理由地混搭，而非随机堆卡 |

`[PLACEHOLDER]` 首阶段完成定义：同一玩家完成 3 局后，能独立描述至少两条非卡名式规则，并在新对手快照上应用其中一条。第一次正式样本后再确定通过率。

## 8. Edge Cases

- 玩家反复选择同一起始方案：允许；观察是否因理解增长产生不同构筑，不强迫轮换。
- 玩家用意外混搭取胜：先验证规则和账单，再判断为 intended/acceptable/bug。
- 剧情状态要求禁用某装备：必须在单局开始前明确，不中途移除玩家持有物。
- 城市模仿玩家空格：只做表现或明确事件，不能修改当前战斗占位。
- 旧构筑记录来自旧版本：只读展示；不能进入当前规则对战。
- 玩家不关心剧情：核心循环仍必须完整，叙事可跳过但关键机械后果不可跳过。

## 9. Failure States

- 玩家靠账号加成掩盖构筑理解不足。
- 新内容只是旧效果换名，认知负担增加而决策不增加。
- 叙事选择与玩法后果脱节，所谓“承担代价”只发生在对白。
- 对手快照人格文案误导实际构筑。
- 长期目标依赖每日奖励或赛季压力，而不是精通欲望。
- 玩家可见内容扩张早于 P-1，导致卡面和反馈问题被组合数量掩盖。

## 11. Acceptance

### 功能

- `ContentStageGate` 阻止未批准内容进入候选池。
- 叙事后果通过版本化状态和显式规则进入 RunState。
- 跳过叙事不跳过机械后果确认。
- 旧版本记录不会进入当前战斗。

### 体验

- 玩家能把至少一个叙事命题映射到真实玩法取舍。
- 多局后预测和重构理由更具体，而非只记住卡名排名。
- 没有永久数值成长时，玩家仍愿意再开一局验证新假设。
