# 《不器》按天循环 Demo 设计

日期：2026-08-07
状态：规则确认稿，待用户审阅

## 1. 目标

把当前线性 UI 演示改造成可以完整游玩的离线单局 Demo。玩家每天连续经历三次随机商店或事件，随后依次进行 PVE 和本地预制玩家 PVP；完成两场战斗后进入下一天，直到获得 9 场胜利或单局生命归零。

本轮保留现有确定性战斗模拟、回放、配置表和拖拽布阵能力。PVP 只从本地预制玩家构筑池中随机选择对手，不连接服务器，不上传玩家构筑，不做实时匹配。

## 2. 已确认规则

### 2.1 单局终局

- 初始胜场为 0，达到 9 胜立即获得单局胜利。
- 初始单局生命沿用当前 Demo 的 3 点；每次战败扣 1 点，归零立即单局失败。
- PVE 与 PVP 都计入胜场和生命结算。
- 战斗底层若返回平局，保留原始平局结果和日志，但单局结算按玩家胜利处理；界面显示“平局，按规则判定本方获胜”。
- 每场战斗结算后立即检查终局。PVE 后若已经终局，不再进入当天 PVP；PVP 后若已经终局，不再进入当天结算。

### 2.2 每日流程

```text
DayStart
-> Encounter 1: Random(Shop, Event)
-> Encounter 2: Random(Shop, Event)
-> Encounter 3: Random(Shop, Event)
-> PVE Battle
-> PVP Battle
-> DaySettlement
-> Next Day / RunTerminal
```

- 三次遭遇分别随机，允许同一天出现三个商店或三个事件。
- 随机由版本化 RunSeed 和 RNG 游标驱动；同一初始状态与命令序列必须产生相同遭遇和对手。
- 默认商店/事件权重均为 1，后续可由配置调整，当前不增加额外调权界面。
- 完成 PVP 后天数加 1、遭遇序号归零，并生成下一天内容。

### 2.3 构筑与空间

- 玩家棋盘继续使用现有 8 格规则。
- 仓库从当前 5 格改为默认 8 格。
- 棋盘整理不再作为独立顶层阶段；在非战斗界面保持可用，进入 PVE 时冻结玩家构筑快照，PVP 沿用同一天当前构筑。
- 装备必须拥有独立实例 ID，才能正确表示重复装备、品质、改造和自动合并；不能继续只用定义 ID 表示玩家持有物。
- 玩家构筑、仓库、金币、装备品质和改造跨天保留。

### 2.4 删除的流程

- 删除 `OpponentIntel` 公开情报阶段。
- 删除 `Prediction` 战前预测阶段。
- 商店、事件、改造和棋盘编辑不再固定依次通过；改造、升级和整理作为商店/事件及常驻构筑操作的一部分。
- 战斗总结和回放仍保留，但不作为需要玩家提交预测或败因才能继续的门禁。

## 3. 状态机

顶层运行阶段收敛为：

```text
Encounter
PveBattle
PvpBattle
DaySettlement
RunTerminal
```

`EncounterIndex` 取 `0..2`。成功结算遭遇后递增；到 3 时进入 PVE。PVE 结算且未终局时进入 PVP；PVP 结算且未终局时进入 `DaySettlement`；日结算完成后 `Day++` 并返回 `EncounterIndex=0`。

所有阶段只接受白名单命令。界面关闭、重开、重复回调和回放控制不得自行推进状态。

## 4. 核心状态

`BuqiRunState` 至少包含：

- `ContentVersion`、`RuleVersion`、`Revision`。
- `RunSeed`、`RngCursor`。
- `Day`、`Phase`、`EncounterIndex`。
- `Coins`、`Wins`、`Lives`。
- 8 格棋盘、8 格仓库和装备实例集合。
- 当前固化遭遇、当前商店货架或事件候选。
- 当前 PVE 对手 ID、当前 PVP 预制玩家 ID。
- 待结算战斗请求 hash、原始战斗结果、归一化单局结果。
- 已应用命令 ID 和结算 ID。
- 最终单局结果与统计摘要。

初始金币沿用当前 Demo 的 12；后续数值调整通过配置完成，不在状态机里散落常量。

## 5. 模块边界

### 5.1 单局核心

`BuqiRunController` 只负责命令验证、阶段转换、天数和终局；不直接生成商店、不实现战斗规则，也不操作 Unity UI。

`BuqiRunRules` 集中定义 9 胜、3 点生命、每日 3 次遭遇、8 格棋盘、8 格仓库和平局判胜等规则常量。

### 5.2 遭遇

`BuqiEncounterService` 根据 RunSeed、游标和配置固化下一次 `Shop` 或 `Event`。候选一旦生成，查看详情、返回界面和恢复存档都不能重抽。

事件必须通过显式命令结算金币、生命、装备或改造结果；非法选择保持状态不变。

### 5.3 装备与经济

`BuqiInventoryService` 管理装备实例、棋盘、仓库、移动和容量校验。

`BuqiEconomyService` 管理购买、出售、刷新、锁定、同名同品质合并、升级和改造成本。所有操作先校验再一次性提交，不能先扣款后发现无空间。

### 5.4 对手与战斗

`IBuqiOpponentProvider` 提供统一选择接口：

- PVE provider 从本地 PVE 题目池随机选择合法快照。
- PVP provider 从本地预制玩家构筑池随机选择合法快照。
- 未来联网实现只替换 PVP provider，不改变单局控制器和战斗模拟器。

`BuqiRunBattleFactory` 把玩家当前构筑和选中的对手快照组装成真实 `BattleRequest`，调用现有 `BuqiBattleSimulator`，并产出回放数据。它不得再使用两个固定对手互战代替玩家战斗。

### 5.5 结算、战报与保存

`BuqiBattleSettlementService` 将原始结果映射为单局胜负，应用胜场或生命变化，并进行 9 胜/生命归零检查。重复提交同一 `settlementId` 返回原结果，不重复发奖。

战报从真实 `BattleEvent` 生成摘要，不再使用固定三条事实。至少保留结果、主要伤害来源、关键触发和过载/状态损失。

保存点包括：每次遭遇固化后、每个经济命令成功后、布阵确认后、战斗结果生成后、战斗结算后和日结算后。战斗结果必须先保存再结算，崩溃恢复不得重选对手或重复发放结果。

## 6. UI 行为

- 顶部资源显示：天数、遭遇进度、金币、胜场 `x/9`、单局生命。
- 商店或事件页同时保留进入构筑整理的入口。
- PVE/PVP 页显示战斗类型和回放；PVP 可以显示预制玩家名称，但没有独立公开情报流程。
- 战斗结束展示真实结果与战报，确认后进入下一场或终局。
- 日结算只总结当天 PVE/PVP 结果和资源变化，不额外发起随机遭遇。
- 终局页明确显示胜利或失败、总天数、最终构筑和战斗统计，并允许重新开始。

## 7. 错误与恢复

- 配置池为空、快照非法或无法生成合法对手时停止推进并显示错误，不静默使用错误构筑。
- 商店和事件命令失败时不改变金币、装备、随机游标或阶段。
- 仓库与棋盘都无空间时，只有能够立即合并的购买允许成功。
- 内容版本不兼容时显式拒绝恢复，并保留旧存档用于诊断。
- 回放暂停、倍速、跳过和重播只影响播放，不改变已保存战斗结果。

## 8. 独立工作包

### 第一批：可并行实现

1. **单局契约与状态机**：新建纯 C# 状态、规则、命令、转换和测试；独占 `Buqi/Run/Core/`。
2. **装备与经济**：装备实例、8 格仓库、购买/出售/合并/升级/改造和测试；独占 `Buqi/Run/Economy/`。
3. **随机遭遇**：确定性商店/事件选择、候选固化、事件结算和测试；独占 `Buqi/Run/Encounter/`。
4. **PVE/PVP 战斗接入**：两个本地 provider、真实玩家快照工厂、平局映射输入和测试；独占 `Buqi/Run/Battle/`。
5. **保存、战报与结算**：版本化 DTO、幂等结算、真实战报摘要和恢复测试；独占 `Buqi/Run/Settlement/`。

第一批工作包只依赖书面接口契约，不修改现有 `BuqiUIDemoController.cs`、`BuqiRunShellForm.cs` 或阶段 Widget，避免并行冲突。

### 第二批：顺序集成

6. **主流程集成**：在第一批合并后替换旧的线性 Demo 状态机，接入现有拖拽布阵和回放。
7. **UI 收敛**：移除情报与预测入口，更新阶段轨道、8 格仓库、日结算和终局显示。
8. **完整验收**：覆盖连续多天、三次随机遭遇、PVE、PVP、9 胜、生命归零、平局判胜、保存恢复和 Unity 实际交互。

## 9. 验收标准

- 相同种子与命令序列产生相同三次遭遇、PVE 对手和 PVP 预制玩家。
- 每天严格完成三次随机商店/事件后进入 PVE，再进入 PVP，再进入下一天。
- 任意战斗达到 9 胜立即胜利，任意战斗后生命归零立即失败。
- 平局保留原始日志，并在单局结算中计为玩家胜利。
- 玩家真实 8 格棋盘参与 PVE/PVP；改变装备或摆位可以改变请求 hash 和战斗结果。
- 仓库默认 8 格，重复装备、品质和改造可区分并正确保存。
- 不存在公开情报和战前预测顶层阶段。
- 退出恢复后遭遇、对手、战斗结果与奖励不重抽、不重复结算。
- 从开始到胜利或失败可在 Unity 中完整游玩，无需编辑器调试窗口推进状态。
