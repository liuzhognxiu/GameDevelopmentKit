# 《不器》战斗实验室测试界面设计

- 日期：2026-08-24
- 状态：需求确认稿，待用户审阅
- 适用范围：Unity Demo 主菜单、独立战斗实验室、全量道具配装、敌人选择与现有战斗回放
- 设计选择：C 双棋盘工作台

## 1. 已确认结论

1. 主菜单新增独立的“战斗实验室”入口，不复用正式单局入口。
2. 玩家先选择英雄，再进入全卡库配装界面。
3. 第一版提供 3 个固定测试英雄；英雄只改变战前生命、护盾和初始过载，不增加主动技能、被动技能或专属卡池。
4. 全量道具均可无限次拖出；每次成功落位生成一个独立实例。
5. 玩家与自定义敌人都能使用同一组英雄预设。
6. 敌人同时支持配置预设和自定义配装两种模式。
7. 工作台采用一个卡库配两个始终可见的配置驱动棋盘；当前配置为 8 格，并预留后续 10 格迁移。道具直接拖到目标棋盘，不增加“放到我方/敌方”切换步骤。
8. 点击“开始模拟”后复用现有完整战斗回放；从回放返回时保留实验室当前配置。
9. 战斗实验室不读写正式单局经济、阶段、存档、奖励或结算状态。
10. 第一版只接鼠标。

## 2. 体验目标

测试者应能在不进入正式单局流程的情况下完成以下闭环：

```text
主菜单
-> 选择我方英雄
-> 查看全部正式道具
-> 反复拖出任意道具并配置我方棋盘
-> 选择配置敌人，或创建自定义敌人
-> 直接模拟战斗
-> 查看完整回放与日志
-> 返回工作台
-> 调整任一方构筑并再次模拟
```

成功体验应满足：

- 所有可用道具都能在一个卡库中找到，不受商店、解锁日或金币限制。
- 同名道具可以在同一棋盘中出现多次，只要空间合法。
- 测试者始终能同时看见双方棋盘，便于做镜像、克制和摆位比较。
- 预设敌人和自定义敌人的所有权、可编辑状态明确，不会误改配置快照。
- 非法拖拽不产生半成品实例，也不改变任一棋盘。
- 每次模拟都使用现有正式战斗规则和正式道具定义。

## 3. 范围与非目标

### 3.1 本轮范围

- 主菜单“战斗实验室”入口。
- 独立英雄选择页。
- 3 个固定测试英雄及其基础属性投影。
- 从 `BuqiConfigCatalog.Items` 读取的全量道具卡库。
- 我方配置驱动棋盘的拖入、移动、删除和清空。
- 配置预设敌人列表、属性和只读棋盘预览。
- 自定义敌方英雄选择与配置驱动棋盘编辑。
- 双方构筑校验、战斗请求生成和模拟提交。
- 复用现有 `BattleForm` 的完整回放。
- 回放返回后的实验室状态恢复。
- 1280x720 与 1920x1080 布局。
- 纯 C# 控制器测试、UI Prefab 契约测试和入口接线测试。

### 3.2 本轮不做

- 英雄主动技能、被动技能、天赋、成长或专属卡池。
- 新增英雄 Luban 配置表。
- 英雄或实验室构筑的持久化。
- 金币、购买、出售、刷新、解锁或正式单局奖励。
- 品质编辑、改造编辑、临时修正编辑或批量生成。
- 卡库搜索、筛选、收藏或卡组模板。
- 自动摆位、自动整理、自动交换或自动挤位。
- 我方与敌方棋盘之间直接转移实例。
- 战斗规则、效果结算、目标选择或日志算法修改。
- 在线匹配、服务器上传、排行榜或共享构筑。
- 键盘、手柄和触屏输入。

## 4. 英雄契约

### 4.1 固定预设

| HeroId | 显示名称 | 定位 | InitialExecution | InitialBuffer | InitialNoiseDebt |
|---|---|---|---:|---:|---:|
| `balanced` | 归衡者 | 均衡 | 100 | 0 | 0 |
| `guarded` | 铁衣客 | 护盾 | 85 | 20 | 0 |
| `survivor` | 长生客 | 生存 | 115 | 0 | 4 |

字段含义沿用现有 `BuildSnapshot`：

- `InitialExecution`：战斗开始时的生命与最大生命基准。
- `InitialBuffer`：战斗开始时的护盾。
- `InitialNoiseDebt`：战斗开始时的过载债务，必须低于正式失衡阈值。

### 4.2 规则

- 英雄预设属于战斗实验室模块内的只读定义，不进入正式运行配置。
- 我方必须选择英雄后才能进入工作台。
- 工作台提供“更换英雄”，更换只替换战前属性，不清空棋盘。
- 自定义敌人必须选择一名英雄才能模拟。
- 配置预设敌人不套用实验室英雄；其基础属性完整读取 `BuqiEchoConfigRow.Snapshot`。
- 英雄名称只用于实验室和回放双方名称，不参与战斗哈希之外的规则判断。

## 5. 数据来源与投影

### 5.1 全量道具

卡库来源为当前 `BuqiConfigCatalog.Items`：

- 每个合法 `BuqiItemConfigRow` 投影成一张卡库定义卡。
- 卡库按 `DefinitionId` 使用序号比较稳定排序，保证测试可重复。
- 卡库卡片不是道具实例，不会因拖出而消失或减少数量。
- 道具的尺寸、基础冷却、效果、标签、流派、角色和正式说明均读取配置。
- 卡库投影不得复制战斗效果计算逻辑。

卡片至少展示：

| UI 内容 | 数据来源 |
|---|---|
| 名称 | `DisplayName` / 本地化回退 |
| 尺寸 | `Size`，并以实际 1/2/3 格宽度表达 |
| 品质 | 新建实验室实例固定为普通品质 |
| 冷却 | `BaseCooldownTicks` 经正式时间显示规则转换 |
| 正式作用 | `EffectDescription`，缺失时使用正式效果投影回退 |
| 标签 | `Tags`、`ArchetypeId`、`Role` |
| 位置提示 | `PositionHint` |

### 5.2 预设敌人

预设敌人来源为当前 `BuqiConfigCatalog.Echoes`：

- 列表包含所有具有非空 `Snapshot` 的配置行。
- 显示名称优先使用 `DisplayName`，回退为 `EchoId`。
- 敌人属性、流派和棋盘从 `Snapshot` 完整复制。
- 预设快照进入实验室后使用防御性深拷贝，UI 不持有配置对象的可变引用。
- 预设快照先通过 `BuqiBoardValidator`；非法项保留在列表中但标明原因并禁止模拟，便于发现配置问题。
- 预设棋盘只读；不能接收卡库拖拽、移动实例或回收实例。

### 5.3 实验室实例

从卡库向可编辑棋盘拖拽时：

1. 开始拖拽只创建视觉预览，不创建 `ItemInstance`。
2. 指针进入棋盘锚点格后，根据配置尺寸计算完整占位范围。
3. 只有在合法目标释放并被控制器接受后，才创建实例。
4. 新实例的 `DefinitionId` 来自卡库定义，`Quality` 固定为普通，`AnnotationId` 为空，临时修正为空。
5. 我方与自定义敌方分别维护单调递增实例序号，生成稳定且全场唯一的实例 ID。
6. 取消拖拽或非法释放不消费序号，不产生实例。

推荐实例 ID 形式：

```text
lab-player-0001
lab-player-0002
lab-enemy-0001
```

## 6. 控制器与状态模型

新增纯 C# `BuqiBattleLabController`，作为 UI 与正式战斗模型之间的唯一状态边界。

### 6.1 顶层状态

```text
Phase
  HeroSelection
  Workbench

Player
  SelectedHeroId
  EditableBoard

OpponentMode
  Preset
  Custom

PresetOpponent
  SelectedEchoId
  ReadOnlySnapshot
  ValidationError

CustomOpponent
  SelectedHeroId
  EditableBoard
```

### 6.2 状态保留

- 从英雄选择进入工作台后，控制器在表单关闭前持续存在。
- 从工作台打开 `BattleForm` 时不销毁控制器。
- 回放确认关闭后重新显示同一实验室状态。
- 在预设与自定义敌人模式之间切换时，分别保留最后选中的预设敌人和自定义敌方构筑。
- 更换任一方英雄不清空对应棋盘。
- 返回主菜单或关闭实验室后释放所有实验室实例；本轮不跨会话保存。

### 6.3 命令边界

控制器至少提供以下意图级命令：

- 选择我方英雄。
- 进入工作台或返回英雄选择。
- 更换我方英雄。
- 切换敌人模式。
- 选择预设敌人。
- 选择自定义敌方英雄。
- 预览卡库道具到目标棋盘锚点。
- 从卡库创建实例并放置。
- 在同一棋盘内移动实例。
- 从可编辑棋盘删除实例。
- 清空指定可编辑棋盘。
- 创建战斗回放数据。

所有修改命令返回：

```text
Accepted
Reason
CurrentView
```

失败命令必须保持视图与实例序号不变。

## 7. 棋盘规则

- 我方和自定义敌方棋盘格数均读取 `BuqiGlobal.BoardSlotCount`，逻辑编号为 `0..BoardSlotCount-1`。
- 实验室控制器、ViewModel、Prefab Builder 和布局代码不得引用固定长度 8；棋盘格按配置数量生成。
- 本设计的布局验收范围为 8 至 10 格，确保后续从 8 格迁移到 10 格时不需要重做实验室 UI 或控制器。
- 当前代码中的 `BuqiBoardValidator.BoardSlotCount`、`BuqiRunRules.BoardSlotCount`、`BuqiDragDeployController.BoardSlotCount` 和 `BattleReplayController` 仍按 8 格实现。
- 在上述权威规则与回放投影完成 10 格迁移前，配置校验仍应拒绝 `BoardSlotCount = 10`，实验室不得绕过校验或独自提交 10 格战斗。
- 10 格迁移完成后，实验室通过同一配置字段自动生成 10 格双方棋盘，不新增实验室专用开关。
- 道具按 `AnchorSlot` 和配置尺寸占用连续格。
- 放置不得越界或与已有实例重叠。
- 同一 `DefinitionId` 可以对应多个实例；同一 `InstanceId` 不得重复。
- 卡库道具可直接拖到我方或自定义敌方棋盘，目标棋盘由实际释放区域决定。
- 棋盘实例只能在所属棋盘内移动；跨双方棋盘释放视为非法，不改变状态。
- 向已占用范围释放不自动交换或整理，返回具体重叠原因。
- 拖到固定回收区删除可编辑实例；预设敌人实例不可删除。
- 棋盘外释放视为取消，不显示阻塞弹窗。

拖拽预览同时提供：

- 完整连续占位格高亮。
- 合法或非法状态图形，不只依赖颜色。
- 一行具体原因，例如“需要连续 3 格”“超出棋盘范围”“与玄甲符重叠”“预设敌人不可编辑”。

## 8. 战斗请求与回放

### 8.1 我方快照

我方 `BuildSnapshot`：

- `SnapshotId` 使用实验室会话内稳定标识。
- `ContentVersion` 使用 `BuqiDefinitionProvider.ContentVersion`。
- `ArchetypeId` 固定为空；实验室不新增“主要流派”推导规则。
- 三个初始属性读取所选英雄。
- `Items` 从我方棋盘实例深拷贝并按正式规范排序。

### 8.2 敌方快照

- 预设模式使用所选 `Echo` 快照的深拷贝，保留其基础属性、品质、改造和摆位。
- 自定义模式按敌方英雄和敌方可编辑棋盘构建新快照。
- 双方实例 ID 在进入模拟前再次验证全场唯一。

### 8.3 模拟

点击“开始模拟”时：

1. 确认我方英雄已选择。
2. 确认敌人模式所需数据完整。
3. 使用 `BuqiBoardValidator` 分别验证双方快照。
4. 构建使用当前 `BuqiBattleSimulator.RuleVersion` 的 `BattleRequest`。
5. 使用由双方规范化快照与实验室模拟序号导出的稳定种子；不消费正式单局 RNG。
6. 调用 `BuqiBattleSimulator.Simulate`。
7. 将结果、日志、双方名称、快照和定义提供器投影为 `BattleReplayData`。
8. 使用 `BattleReplayOpenData` 打开现有 `BattleForm`。

模拟失败时停留在工作台，保留双方配置并显示具体错误。不得修改正式单局状态或自动重置棋盘。

## 9. UI 设计

### 9.1 英雄选择页

- 页面标题为“选择测试英雄”。
- 3 张英雄卡并排显示名称、定位、生命、护盾和初始过载。
- 选中状态同时使用边框、标记和文字，不只使用颜色。
- 双击或单击不直接跳转；使用明确的“进入实验室”主命令。
- 未选择英雄时主命令禁用并显示原因。
- 返回命令关闭实验室并回到主菜单。

### 9.2 双棋盘工作台

```text
+--------------------------------------------------------------------------+
| 返回 | 战斗实验室 | 我方英雄 | 敌人模式 | 敌方英雄/预设 | 开始模拟      |
+-------------------------------+------------------------------------------+
| 全部道具                      | 我方 N 格棋盘                             |
| 卡片网格，可滚动              | [0][1][2]...[N-1]                        |
| 每次拖出复制实例              |                                          |
|                               | 敌方 N 格棋盘                             |
| 固定道具详情                  | [0][1][2]...[N-1]                        |
| 名称/尺寸/品质/冷却/效果/标签 | 预设只读；自定义可编辑                    |
+-------------------------------+------------------------------------------+
| 回收区 | 当前拖拽占位与具体合法性反馈 | 最近一次模拟状态                    |
+--------------------------------------------------------------------------+
```

布局规则：

- 全卡库占左侧，双方棋盘上下排列在右侧。
- 右侧两个棋盘使用相同格宽、相同卡片比例和相同占位反馈。
- 我方和敌方使用明确标题与不同所有权标记，颜色不是唯一差异。
- 卡库顶部显示“全部道具”和数量，不增加“放到我方/敌方”切换。
- 卡库卡拖到哪个棋盘，就在该棋盘创建实例。
- 预设敌人模式下敌方棋盘显示锁定标记和“配置快照，只读”。
- 自定义敌人模式下敌方英雄选择器可见，敌方棋盘切换为可编辑。
- 固定详情区不会因悬停内容长度挤压棋盘。
- 回收区在拖拽可编辑实例时增强显示，拖拽卡库定义时不接受删除。

### 9.3 分辨率

1280x720：

- 卡库保持至少 2 列可读卡片。
- 双方棋盘在 8 格和 10 格配置下都保持单行，不折行、不横向滚动。
- 道具详情允许垂直滚动，不能挤占棋盘命中区。
- 顶部状态和命令允许分组收紧，但“开始模拟”和敌人模式不能隐藏。

1920x1080：

- 卡库增加到 3 至 4 列。
- 棋盘格和卡片保持稳定比例，不随内容改变宽度。
- 增加详情与敌人列表可视高度，不放大标题或制造空洞区域。

## 10. 鼠标交互

- 单击英雄卡：选择英雄。
- 单击配置敌人：固定选择并更新只读快照。
- 悬停卡库卡或棋盘实例：临时显示完整详情。
- 单击卡库卡或棋盘实例：固定详情。
- 滚轮：浏览卡库、预设敌人列表或详情滚动区域。
- 从卡库拖到可编辑棋盘：复制并放置新实例。
- 从棋盘实例拖到同一棋盘：移动实例。
- 从可编辑棋盘拖到回收区：删除实例。
- 点击“清空”：清空指定可编辑棋盘；不影响另一侧。
- 点击“开始模拟”：只在双方当前快照合法时提交。

点击卡库卡只固定预览，不自动生成实例。双击不绑定快捷放置。

## 11. 错误与空态

| 场景 | 行为 |
|---|---|
| 配置表尚未初始化 | 阻止进入工作台，显示配置不可用原因 |
| 没有合法道具 | 显示卡库空态，禁止模拟 |
| 没有预设敌人 | 预设模式显示空态，仍可切换自定义模式 |
| 英雄未选择 | 禁止进入工作台或禁止自定义敌人模拟 |
| 道具尺寸非法 | 卡库卡标记配置错误，禁止拖出 |
| 放置越界 | 高亮越界范围，保持棋盘不变 |
| 放置重叠 | 高亮冲突格和冲突道具，保持棋盘不变 |
| 拖到预设敌人棋盘 | 显示“预设敌人不可编辑”，不创建实例 |
| 跨双方棋盘移动实例 | 显示“不能转移双方已有实例”，保持两侧不变 |
| 战斗校验失败 | 保留工作台，显示左右侧和具体校验原因 |
| 模拟器返回无效构筑 | 不打开回放，显示模拟失败原因 |
| 回放打开失败 | 保留实验室状态，允许再次提交 |

错误使用非阻塞行内反馈；只有无法初始化整个实验室时才使用阻塞状态面板。

## 12. 代码边界

### 12.1 新增或修改区域

- 战斗实验室纯 C# 状态、控制器和 ViewModel。
- `BuqiBattleLabForm` 及实验室专属交互组件。
- 实验室 UI Prefab 与必要的 Prefab Builder。
- 主菜单入口接线。
- UI 配置源及其正常生成产物。
- 战斗实验室专属 EditMode、Prefab 和接线测试。

### 12.2 复用区域

- `BuqiGeneratedConfigAdapter`：读取当前正式配置目录。
- `BuqiDefinitionProvider`：提供正式战斗定义。
- `BuqiBoardValidator`：最终棋盘合法性权威。
- `BuqiBattleSimulator`：权威战斗模拟。
- `BattleReplayData`、`BattleReplayOpenData`、`BattleForm`：完整回放。
- 现有道具卡、悬停详情和拖拽控件的视觉与输入约定；只有契约匹配时复用实现。

### 12.3 禁止修改

- 供给生成、商店经济和价格算法。
- 正式单局状态机、遭遇结算和存档格式。
- 战斗效果解析、模拟顺序、终止条件和日志哈希。
