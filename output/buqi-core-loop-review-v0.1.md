# 《不器》Fun Hypothesis、Design Pillars 与核心循环评审 v0.1

> 评审日期：2026-08-04  
> 评审范围：`week-eight-core.md`、玩法规格 v0.4、战斗契约 v0.4、原型计划 v0.4  
> 已确认边界：PC/移动双端；目标用户偏《The Bazaar（大巴扎）》玩家；异步对战自动构筑肉鸽；单局目标 8–12 分钟。

## 1. 结论

《不器》的规则契约、确定性要求和战报设计已经足够进入工程，但核心乐趣尚未通过验证。现有流程最大的问题不是少系统，而是 **P0 先证明“战斗能正确运行”，P2 才证明“玩家愿意根据结果重构”**；真正的 Fun Hypothesis 被推迟到了成本更高的位置。

建议在 Step 1 / P0 代码实现前新增 **P-1 Fun Gate（纸面原型）**。用固定的 9 个装备、3 组对手快照和有限的购买/摆位选择，先验证玩家能否形成预测、看懂偏差，并主动做出有代价的修正；未通过则改循环，不扩内容。

## 2. Fun Hypothesis

> **《不器》好玩的核心是：玩家用有限格位与带代价的装备组装一套自己能预测的自动构筑，看它对抗公开但不完整的对手快照；当结果证明或推翻自己的判断时，玩家能通过一次有代价的重构，让下一战明显更接近自己的预期。**

这句话包含四个不可删除的变量：

| 变量 | 玩家此刻在做什么决策 | 删除后的风险 |
|---|---|---|
| 有限格位 | 核心、辅助、稳定性谁占空间 | 构筑退化为“见强就拿” |
| 带代价改造 | 速度、强度、稳定性如何交换 | 改造退化为无脑强化 |
| 可预测运转 | 预判启动、连锁与中断 | 战斗退化为不可读动画 |
| 结果后重构 | 针对败因改购买、改造或摆位 | 单局退化为随机抽取后看结算 |

**可证伪条件**：玩家即使能复述战报，也无法在下一轮提出一个具体改动及其预期影响，则 Fun Hypothesis 不成立。理解结果不等于拥有决策，考试会做阅读理解也不等于会造机器。

## 3. Design Pillars

| 支柱 | 不可妥协的体验标准 | 机制过审问题 | 否决条件 |
|---|---|---|---|
| **先预测，再验证** | 开战前玩家能说出一个主要预测，战后能核对预测偏差 | 这个信息是否帮助玩家判断“谁先启动、链在哪里断、风险何时兑现”？ | 只能战后解释，战前无法形成预测 |
| **每格都代表取舍** | S/M/L、位置和空格共同制造机会成本 | 加入这张装备后，玩家放弃了什么合法方案？ | 大型卡只是更高数值；摆位存在显然唯一答案 |
| **强度必须带账单** | 改造和高收益装备改变风险、节奏或适配面 | 强度的 source 对应哪个 sink，代价在哪场战斗真实发生？ | 代价常被绕过，或改造对所有构筑都是正收益 |
| **败因能转成行动** | 战报指向下一轮可执行的购买、改造或摆位调整 | 玩家看到败因后，至少有两种成本不同的应对吗？ | 战报只解释死亡，不能支持重构 |
| **异步对手是题目，不是倍率墙** | 对手快照提供可读威胁，同时保留足够未知让玩家押注 | 玩家是在针对结构，还是在追显示战力？ | 同规则下仍靠隐藏倍率或无法预期的内容制造难度 |

第五条中的“公开但不完整”需要谨慎：当前只展示方向、三张关键装备、主要威胁、占用和已知改造，结构合理；但公开量尚未 playtest，属于 **[PLACEHOLDER · 假设：足够形成预测，又不会把摆位变成标准答案；验证：比较全公开、当前摘要、仅方向三组]**。

## 4. 三层核心循环

### 4.1 Moment-to-moment：0–30 秒认知循环

> **形成预测 → 观察关键触发 → 定位偏差 → 更新下一轮假设**

| 项目 | 定义 |
|---|---|
| Purpose | 让无操作战斗仍产生持续判断，而不是等待结算 |
| Player experience goal | “我知道这条链想怎么转，也看见它为什么没转起来” |
| Inputs | 双方棋盘、连续冷却、相邻关系、关键状态、威胁提示 |
| Outputs | 一条被验证/推翻的预测；一个明确败因；一个待验证改动 |
| Edge cases | 同 tick 多链触发、屏幕较小、战斗过快、多个原因贡献接近 |
| Failure states | 玩家只盯总血量；只能在 0.5x 看懂；战报结论与玩家观察割裂 |

当前 30–45 秒战斗目标为 **[PLACEHOLDER · 假设：能展示至少两轮核心链条且不拖沓；验证：记录首次关键触发、胜负已明显、正式结束三个时间点]**。60 秒硬上限有防死局 rationale，但不是“好玩时长”的证据。

### 4.2 Session loop：8–12 分钟单局循环

> **读取对手快照摘要 → 选择两次准备机会 → 购买/改造/取舍 → 排列 8 格构筑 → 写下战前预测 → 自动战斗 → 复盘 → 支付代价重构 → 胜场/单局生命结算**

| 项目 | 定义 |
|---|---|
| Purpose | 连续制造“押注—验证—修正”，让每轮改变玩家的构筑模型 |
| Player experience goal | “不是抽到答案，而是把不完整材料拼成了自己的答案” |
| Inputs | 金币、持有装备、两次准备入口、对手快照摘要、上一战战报 |
| Outputs | 更新后的构筑、资源余量、胜场/单局生命、下一轮策略意图 |
| Edge cases | 商店没有针对牌；失败后资源补偿反而奖励故意输；仓位满；连续遇到同类对手快照 |
| Failure states | 准备选择只有数值高低；玩家每轮改很多但不知道哪项有效；失败补偿抹平前期决策 |

8–12 分钟、5 胜场、3 单局生命、每轮两次准备目前均为 **[PLACEHOLDER · 假设：一局可完成约 4–7 次预测闭环；验证：记录每局有效战斗数、每轮准备时长和产生实质构筑变化的轮次比例]**。如果双端测试中移动端中位局长显著高于 PC，不能只加“跳过战斗”；要检查信息阅读和拖放操作是否在移动端收了隐形税。

### 4.3 Long-term：数小时至数周精通循环

> **积累装备词汇 → 识别对手快照结构 → 建立克制与节奏模型 → 尝试更高风险组合 → 形成个人构筑表达**

首阶段不做永久数值成长是正确的。长期钩子先验证 **玩家知识增长**，而不是用成长条掩盖单局不足；可记录同一玩家跨 3 局后，战前预测准确度、重构理由具体度和混搭尝试是否提高。

当前长期循环缺少明确完成定义。建议首阶段定义为：玩家完成 3 局后，能够独立描述两条非卡名式规则，例如“高频小伤害会喂给护盾转化”“大型核心挤掉降噪位，因此高速不是免费速度”。具体通过率待首测确定，不能先让百分比替我们表演科学。

## 5. 现有流程评审

| 现阶段 | 裁决 | 理由 | 调整 |
|---|---|---|---|
| 核心概念与边界 | **通过** | 品类、双端、目标用户、单局时长和不做项已明确 | 补写本评审的 Fun Hypothesis |
| 玩法规格 v0.4 | **有条件通过** | 决策面完整，边界和日志扎实；大量数值尚未 playtest | 所有体验数值统一标为待验证，不视为基线真理 |
| P0 确定性战斗 | **技术必要，顺序需调整** | 能证明算得对，不能单独证明值得玩 | 在其前增加 P-1 Fun Gate |
| P1 可读战斗 | **通过，且应提前做低保真版本** | 可解释性是核心机制，不只是 UI 工程 | P-1 用纸卡/表格战报先测归因 |
| P2 三轮迷你局 | **方向正确** | 首次真正验证“败因→重构” | 将该验证提前到 P-1，P2 再验证数字界面与节奏 |
| P3 完整首阶段 | **暂缓** | 18 装备和完整事件不应早于核心闭环 | 保留现有停止线 |

### 关键缺口

1. **缺少战前预测记录**：现有埋点记录玩家做了什么，但没有记录玩家认为会发生什么。没有预测，就无法区分“玩家理解系统”与“玩家看到战报后合理化”。
2. **70% 战败后发生调整不够严格**：换一张更高品质卡也算调整，但未必针对败因。应记录“改动对象、理由、预期结果”，再由日志判断是否针对主因。
3. **双端输入成本未进入设计门槛**：8 格排布适合双端，但卡面信息、长按详情、拖放误触和战报密度必须分别测试。共享规则，不等于共享同一套信息密度。
4. **经济 Sources/Sinks 尚未闭合验证**：金币 source 有每轮收入、胜负补偿、事件和出售；sink 有购买、刷新、升级、改造。纸面测试需记录轮末存量、未花原因和选择价值，防止 20 上限只是给通胀加了盖子。

## 6. 建议新增 P-1 Fun Gate

### 纸面原型范围

- 使用现有 9 个验证装备，不新增内容。
- 3 组固定玩家起始盘，3 组暴露关键威胁的对手快照。
- 每轮只给 3 个可选改动：购买、改造、摆位各一个，成本明确。
- 用表格或主持人按固定日志结算，不做正式 UI，不追求完整 30–45 秒演出。
- 每场前让玩家写一句预测；每场后写一个主因和一个下一轮改动。

### 必须定义的失败信号

| 失败信号 | 坏掉长什么样 | 处理 |
|---|---|---|
| A：无预测 | 玩家只能说“试试看”，无法指出关键链或先后手 | 减少同时生效的信息，重写卡面与威胁摘要 |
| B：无归因 | 结果出来后，玩家主因与日志不一致 | 先修反馈通道和日志层级，不先改平衡 |
| C：无重构 | 玩家知道原因，但三个选项都不能针对它或代价无差异 | 重画准备选择池与成本，不扩内容 |
| D：唯一解 | 多名玩家面对同一题稳定选择同一项，且理由只是净数值更高 | 增加机会成本或降低信息公开度 |
| E：伪变化 | 玩家改了卡，但预期与改动没有因果关系 | 收紧“针对性调整”的统计定义 |

### Gate 判定

先做小样本认知走查，不用百分比装精确：至少覆盖 3 类目标玩家，每人完成 3 轮连续闭环。只有当多数玩家能连续完成“预测—归因—针对性重构”，且不存在稳定唯一解，才进入 Step 1；否则回到卡面、威胁摘要和准备选项。

正式阈值在第一次走查后根据观测分布设定，当前标记为 **[PLACEHOLDER · 验证后确定]**。

## 7. 对《大巴扎》的机制活检

官方商店页将《The Bazaar》描述为“每一局都是一道新谜题”：玩家选择英雄、收集并在棋盘上组装物品，随后观看构筑对抗怪物和真实玩家；强调按自己的节奏规划、组合发现、风险承担与临场适应。

《不器》应借用的不是百余物品和内容量，而是这个内核：

> **构筑是一道动态题目；自动战斗是答案检查器；下一轮选择是订正。**

《不器》的差异化抓手应落在 8 格 S/M/L 空间压缩、可追溯的充能连锁、以及带真实账单的改造。若这三者不能让玩家做出《大巴扎》中不存在的新判断，修仙包装再好看也只是换了校服。

## 8. 下一步决策

**建议暂停直接进入 Step 1，先执行 P-1 Fun Gate。** P-1 不要求改正式代码；其产出应是纸面测试题、固定结算表、预测/归因/重构记录表，以及是否进入 Step 1 的裁决。
